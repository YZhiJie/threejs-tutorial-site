15.2 进阶应用：DRACO/KTX2 压缩与骨骼动画 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑤⑥⑨ 再学习本篇。

核心概念讲解 ​

上一篇能把模型加载进来了，但两个现实问题立刻出现：美术给的模型动不动几十上百 MB，网页打开要等半分钟；模型里带的骨骼动画躺在 gltf.animations 里不会自己动。本篇解决这两件事。

DRACO：几何压缩 ​

DRACO 是 Google 的几何压缩算法，把顶点坐标/法线/UV 等网格数据量化+熵编码，典型能砍掉 40%~90% 的几何体积。压缩后的模型带 KHR_draco_mesh_compression 扩展，GLTFLoader 遇到它会交给 DRACOLoader 解码：

js
import { DRACOLoader } from 'three/addons/loaders/DRACOLoader.js'

const dracoLoader = new DRACOLoader()
// decoder 文件（js/wasm）放在哪，就指到哪；可以直接用 three 官方 CDN
dracoLoader.setDecoderPath('https://cdn.jsdelivr.net/npm/three@0.186.0/examples/jsm/libs/draco/')
loader.setDRACOLoader(dracoLoader)

解码器是首次遇到压缩模型时才按需下载的（约 300 KB wasm），不压缩的模型不会白付这个成本。

KTX2/Basis：纹理压缩 ​

贴图往往比几何更占体积，而且 PNG/JPG 进了显存还要完全解压（一张 1024×1024 贴图约占 5.6 MB 显存）。KTX2 把贴图转成 GPU 原生块压缩格式：文件更小，显存里也不解压，显存占用直降 4~8 倍。

js
import { KTX2Loader } from 'three/addons/loaders/KTX2Loader.js'

const ktx2Loader = new KTX2Loader()
  .setTranscoderPath('https://cdn.jsdelivr.net/npm/three@0.186.0/examples/jsm/libs/basis/')
  .detectSupport(renderer)   // 必须！探测 GPU 支持哪种块压缩格式，选对转码目标
loader.setKTX2Loader(ktx2Loader)

detectSupport(renderer) 漏掉是最常见的 KTX2 翻车原因——没有它，转码器不知道该把 Basis 中间格式转成 BC7 还是 ETC2，贴图直接不显示。

实测压缩收益（Soldier.glb，本仓库实测） ​

处理体积累计降幅
原始 .glb2.06 MB—
+ DRACO 几何压缩1.19 MB−42%
+ WebP 贴图转码1.40 MB−32%
WebP + DRACO0.80 MB−62%
贴图再换 KTX2(ETC1S)（典型值）≈0.5 MB−75%

命令行工具两条路线任选：

bash
npm i -g @gltf-transform/cli
gltf-transform draco in.glb out.glb      # 几何压缩
gltf-transform webp  in.glb out.glb      # 贴图转 WebP（浏览器原生支持）
gltf-transform etc1s in.glb out.glb      # 贴图转 KTX2（需安装 KTX-Software）
# 或 meshopt 路线（解码更快、压缩率略低）：
gltfpack -i in.glb -o out.glb -cc -tc

资产交付流水线：从美术导出到上线 ​

单条命令能压缩一个模型，但企业项目里模型会持续迭代、由不同美术产出，必须有可重复的流水线，否则"上次那个压缩参数"永远找不回来。一条完整的资产流水线分五段：

阶段做什么工具 / 命令产出与验收
① 导出GLB 单文件、Y-up、应用变换、单位米制Blender（见 15.3 清单）raw/<name>.glb
② 清理删无用节点/动画、合并重复材质、焊接顶点gltf-transform prune/weld/dedup节点数与材质数下降
③ 压缩几何 DRACO 或 meshopt；贴图 KTX2/WebPgltf-transform optimize体积 ≤ 预算
④ 分级按距离生成 LOD（100% / 50% / 25% 面数）gltf-transform simplifylod0/1/2.glb
⑤ 验收体积、贴图尺寸、命名、可加载性CI 脚本 + 真机抽测门禁通过才发布

把整条链写进 package.json，任何一次资产更新都跑同一条命令，产物可复现：

json
{
  "scripts": {
    "assets": "node scripts/build-assets.mjs",
    "assets:one": "gltf-transform optimize raw/soldier.glb ship/soldier.glb --compress draco --texture-compress ktx2",
    "assets:lod": "gltf-transform simplify ship/soldier.glb ship/soldier-lod1.glb --ratio 0.5 --error 0.001"
  }
}

build-assets.mjs 只做三件事：遍历 raw/、按规则跑命令、把结果写到 ship/ 并打印体积对比。不要手工在本地拖文件——手工步骤一旦成为唯一路径，下一个人就复现不出来。

贴图与命名规范：省下的是显存和排查时间 ​

资产管线里最容易失控的不是几何，而是贴图。三条硬规则：

规则具体要求违反的代价
尺寸上限移动端单张 ≤ 2048，桌面 ≤ 4096；必须是 2 的幂4K 贴图显存翻 4 倍，低端机直接闪退
通道打包把 AO / Roughness / Metalness 打进一张 ORM 贴图三张变一张，纹理单元与带宽都省
颜色空间基础色/自发光用 sRGB；法线/粗糙度/AO 用线性颜色发灰发亮，调半天材质也调不对

命名同样要统一：<资产名>_<贴图类型>_<尺寸>.ktx2（如 building_basecolor_1024.ktx2），全小写、无空格、无中文。文件名里的尺寸不是装饰——它让 review 时一眼看出"这张图该不该出现在移动端"。

缓存与 CDN：别让用户下载第二遍 ​

压缩后的资产通常带内容哈希发布（如 soldier.8f3a2c.glb），配合长缓存：

nginx
# 静态资产：内容哈希 + 一年 immutable
location ~* \.(glb|gltf|ktx2|bin)$ {
  add_header Cache-Control "public, max-age=31536000, immutable";
  add_header Content-Type "model/gltf-binary";   # .glb 必须给对 MIME
}

为什么必须用内容哈希而不是 ?v=2：CDN 和浏览器可能忽略查询串，或者旧文件已被边缘节点缓存。文件名变了，缓存才一定会失效。同时把 DRACO / Basis 解码器自托管到自己的域名下，别依赖第三方 CDN——解码器是首屏关键路径，第三方抽风时整个 3D 页面都起不来。

首帧：编译、预加载与渐进呈现 ​

模型下载完不等于"立刻能看"：着色器还要编译、纹理还要上传，这一段常被忽略。三个低成本动作：

js
// ① 预编译：在显示加载层时把材质编译完，避免入场第一帧卡 200ms
const gltf = await loader.loadAsync('/assets/soldier.8f3a2c.glb')
scene.add(gltf.scene)
await renderer.compileAsync(gltf.scene, camera)   // r186 支持异步编译
revealScene()                                      // 编译完再揭示，首帧就顺

// ② 只预加载关键资产：把首屏模型的 URL 交给资源提示
// <link rel="preload" as="fetch" href="/assets/soldier.8f3a2c.glb" crossorigin>
// 不要给所有 LOD / 所有场景都加 preload，会抢首屏带宽

// ③ 渐进呈现：先挂低模占位，高模就绪后替换
scene.add(lod2Model)                 // 立刻有东西看
loader.load('/assets/soldier.8f3a2c.glb', gltf => {
  scene.remove(lod2Model)
  scene.add(gltf.scene)              // 高模到位，无缝替换
})

对应的验收指标：renderer.info.memory.textures 不超预算（19.1）、首帧耗时单独记录、renderer.info.render.calls 在资产替换后没有暴涨。

AnimationMixer：让骨骼动画动起来 ​

gltf.animations 是 AnimationClip 数组（Soldier 自带 Idle / Walk / Run / TPose 四段）。播放它们需要 AnimationMixer：

js
mixer = new THREE.AnimationMixer(model)
const action = mixer.clipAction(clip)  // clip → 可控制的 action
action.play()

切换动作时不要直接停旧开新（会生硬跳变），用交叉淡入淡出：

js
next.reset().fadeIn(0.3).play()
current.fadeOut(0.3)

mixer 是"时钟"不是"永动机"：必须在每帧渲染循环里 mixer.update(delta)，忘了这句动画永远定格在第一帧。

morph targets：另一种动画思路 ​

骨骼动画驱动"关节"，morph targets（形变目标）则直接存"每个顶点从 A 形状挪到 B 形状"，适合面部表情、肌肉挤压这类骨骼掰不出来的变形。RobotExpressive 同时带 14 段骨骼动画和 3 组 morph 目标，下一篇实战会用到它。morph 通过 mesh.morphTargetInfluences[i]（0~1 的权重）控制，也能做成 AnimationClip 交给 mixer 统一调度。

代码示例 ​

加载带骨骼动画的士兵模型，装配 DRACO/KTX2 解码器，并用 lil-gui 下拉框平滑切换 Idle / Walk / Run：

js
import * as THREE from 'three'
import { OrbitControls } from 'three/addons/controls/OrbitControls.js'
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js'
import { DRACOLoader } from 'three/addons/loaders/DRACOLoader.js'
import { KTX2Loader } from 'three/addons/loaders/KTX2Loader.js'
import { RoomEnvironment } from 'three/addons/environments/RoomEnvironment.js'
import GUI from 'three/addons/libs/lil-gui.module.min.js'

// ---- 基础设施 ----
const scene = new THREE.Scene()
scene.background = new THREE.Color(0x0b0e14)
const camera = new THREE.PerspectiveCamera(45, innerWidth / innerHeight, 0.1, 100)
camera.position.set(0, 1.6, 4.5)
const renderer = new THREE.WebGLRenderer({ antialias: true })
renderer.setSize(innerWidth, innerHeight)
renderer.setPixelRatio(Math.min(devicePixelRatio, 2))
renderer.toneMapping = THREE.ACESFilmicToneMapping
document.getElementById('app').appendChild(renderer.domElement)
const controls = new OrbitControls(camera, renderer.domElement)
controls.enableDamping = true
controls.target.set(0, 1, 0)

const pmrem = new THREE.PMREMGenerator(renderer)
scene.environment = pmrem.fromScene(new RoomEnvironment(), 0.04).texture

// ---- 装配压缩管线：解码器按需下载，未压缩模型零成本 ----
const dracoLoader = new DRACOLoader()
  .setDecoderPath('https://cdn.jsdelivr.net/npm/three@0.186.0/examples/jsm/libs/draco/')
const ktx2Loader = new KTX2Loader()
  .setTranscoderPath('https://cdn.jsdelivr.net/npm/three@0.186.0/examples/jsm/libs/basis/')
  .detectSupport(renderer)            // 必须：探测 GPU 支持的压缩纹理格式

const loader = new GLTFLoader()
loader.setDRACOLoader(dracoLoader)
loader.setKTX2Loader(ktx2Loader)

// ---- 加载骨骼动画模型 ----
let mixer = null
const actions = {}
let activeAction = null
const params = { 动画: 'Idle' }

loader.load(
  'https://cdn.jsdelivr.net/gh/mrdoob/three.js@r186/examples/models/gltf/Soldier.glb',
  (gltf) => {
    const model = gltf.scene
    scene.add(model)

    mixer = new THREE.AnimationMixer(model)
    // 为每段动画建 action：Idle / Walk / Run / TPose
    gltf.animations.forEach(clip => { actions[clip.name] = mixer.clipAction(clip) })

    // 下拉框切换动画
    const gui = new GUI({ title: '骨骼动画' })
    gui.add(params, '动画', Object.keys(actions)).onChange(name => {
      const next = actions[name]
      next.reset().fadeIn(0.3).play()  // 新动作淡入
      if (activeAction) activeAction.fadeOut(0.3)  // 旧动作淡出
      activeAction = next
    })
    actions.Idle.play()
    activeAction = actions.Idle
  },
  undefined,
  (err) => console.error('加载失败：', err)
)

const clock = new THREE.Timer()
clock.connect(document)
renderer.setAnimationLoop(() => {
  clock.update()
  const delta = clock.getDelta()
  if (mixer) mixer.update(delta)      // 骨骼动画的发动机：每帧推进
  controls.update()
  renderer.render(scene, camera)
})

addEventListener('resize', () => {
  camera.aspect = innerWidth / innerHeight
  camera.updateProjectionMatrix()
  renderer.setSize(innerWidth, innerHeight)
})

常见问题解答 ​

Q1：动画不播放，模型杵在那一动不动？

按顺序排查三个高频原因：

  1. gltf.animations 是不是空数组——模型导出时没勾"导出动画"，打印一下就知道；
  2. 每帧有没有调 mixer.update(delta)——这是最常见的遗漏，mixer 不会自己走；
  3. mixer.clipAction(clip) 的根对象传对没有：new THREE.AnimationMixer(model) 里的 model 必须是动画实际作用的节点（通常就是 gltf.scene），传错对象动画会"播了但没作用于模型"。
Q2：遇到 DRACO 模型报 decoder 404 / "draco_wasm_wrapper.js 加载失败"？

setDecoderPath() 指错了。三个要点：路径是目录不是文件，结尾要有 /；目录下必须同时有 draco_wasm_wrapper.js、draco_decoder.js、draco_decoder.wasm 三件套；用 CDN 就写 https://cdn.jsdelivr.net/npm/three@0.186.0/examples/jsm/libs/draco/。自建项目推荐把这三个文件拷进自己的 public/draco/，避免 CDN 抽风。

Q3：KTX2 模型的贴图死活不显示？

九成是漏了 ktx2Loader.detectSupport(renderer)——没有它转码器不知道目标 GPU 格式。另外两个检查点：setTranscoderPath 目录下要有 basis_transcoder.js + basis_transcoder.wasm；KTX2Loader 必须在 renderer 创建之后再 detectSupport（它要读 WebGL 上下文的能力）。

Q4：DRACO 和 meshopt（gltfpack）选哪个？

DRACO 压缩率更高但解码慢、需 wasm；meshopt 解码飞快且是纯 JS，压缩率略低。经验法则：大静态模型用 DRACO，海量小模型/低端设备用 meshopt。两者加载方式不同（meshopt 用 loader.setMeshoptDecoder(MeshoptDecoder)），别混用命令和加载器。

Q5：模型更新了，用户看到的还是旧版本？

九成是缓存问题。先确认文件名是否变了：用 ?v=20261031 这类查询串，CDN 或代理可能仍按路径缓存，改了版本号也不一定失效；内容哈希文件名（soldier.8f3a2c.glb）才是可靠方案，内容一变文件名就变。其次检查 Cache-Control：资产目录配 public, max-age=31536000, immutable，入口 HTML 配 no-cache，让 HTML 每次回源拿到新的资产清单。最后确认 app 层没有把资产 URL 写死在配置里——应该从构建生成的 manifest 读取，否则哈希变了、引用还是旧的。

动手小练习 ​

  1. 把演示里 mixer.update(delta) 一行注释掉，刷新确认动画定格，体会"mixer 是时钟不是永动机"。
  2. 用 gltf-transform draco 把一个本地模型压缩后丢进演示加载，观察 Network 面板里 wasm 解码器是首次遇到压缩模型时才下载的。
  3. 给动画切换加上 mixer.timeScale = 0.5，观察慢动作；再想想它和 action.timeScale 的区别（全局 vs 单条）。
  4. 按本篇流水线给一个模型生成 lod0 / lod1 / lod2 三档，在 16.2 的 LOD 示例里换上，对比远处楼栋的三角形数与显存占用变化。
