18.1 基础入门：声明式 3D 与第一个 R3F 场景 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑪ 再学习本篇。

核心概念讲解 ​

前面 17 个模块我们都是"命令式"地写 Three.js：亲手 new 出每个对象、亲手 add 进场景、亲手写渲染循环。React Three Fiber（下称 R3F）把这一切变成声明式：你用 JSX 描述"场景里应该有什么"，React 负责比对差异、调用底层 three API。three 本身的渲染能力一行没少——变的是组织代码的方式。

接桥：把 11.2 的科幻基地改写成 R3F ​

还记得 11.2 科幻基地综合场景吗？雾、阴影、26 栋实例化建筑、可拾取信标、旋转雷达、尘埃粒子，全部在一个文件里命令式搭建。同一座基地，用 R3F 写出来长这样（精简版，保留核心结构）：

jsx
import { Canvas, useFrame } from '@react-three/fiber'
import { OrbitControls } from '@react-three/drei'
import { useLayoutEffect, useMemo, useRef } from 'react'
import * as THREE from 'three'

function Buildings({ count = 26 }) {
  const ref = useRef()
  const dummy = useMemo(() => new THREE.Object3D(), [])
  useLayoutEffect(() => {
    const col = new THREE.Color()
    for (let i = 0; i < count; i++) {
      let x, z
      do { x = (Math.random() - 0.5) * 44; z = (Math.random() - 0.5) * 44 }
      while (Math.hypot(x, z) < 6)
      const h = 2 + Math.random() * 8
      dummy.position.set(x, h / 2, z)
      dummy.scale.set(2, h, 2)
      dummy.updateMatrix()
      ref.current.setMatrixAt(i, dummy.matrix)
      ref.current.setColorAt(i, col.setHSL(0.58, 0.3, 0.3))
    }
    ref.current.instanceMatrix.needsUpdate = true
  }, [count, dummy])
  return (
    <instancedMesh ref={ref} args={[undefined, undefined, count]} castShadow receiveShadow>
      <boxGeometry args={[1, 1, 1]} />
      <meshStandardMaterial roughness={0.55} metalness={0.35} />
    </instancedMesh>
  )
}

function RadarDish() {
  const pivot = useRef()
  useFrame((state, dt) => {
    pivot.current.rotation.y += dt * 2
    pivot.current.rotation.x = Math.sin(state.clock.elapsedTime * 0.6) * 0.35 - 0.3
  })
  return (
    <group ref={pivot} position={[0, 6.4, -5.2]}>
      <mesh rotation-x={Math.PI / 2}>
        <coneGeometry args={[1.4, 0.5, 32, 1, true]} />
        <meshStandardMaterial color="#94a3b8" roughness={0.4} side={THREE.DoubleSide} />
      </mesh>
    </group>
  )
}

function Beacon({ position, name, onPick }) {
  return (
    <mesh position={position} onClick={(e) => { e.stopPropagation(); onPick(name) }}>
      <cylinderGeometry args={[0.12, 0.18, 2.2, 16]} />
      <meshStandardMaterial color="#22d3ee" emissive="#0891b2" emissiveIntensity={1.2} />
    </mesh>
  )
}

export default function App() {
  return (
    <Canvas shadows camera={{ position: [24, 18, 28], fov: 50, far: 300 }} style={{ height: '100vh' }}>
      <color attach="background" args={['#05070c']} />
      <fogExp2 attach="fog" args={['#05070c', 0.022]} />
      <hemisphereLight args={['#334466', '#05070c', 0.55]} />
      <directionalLight position={[20, 30, 12]} intensity={2} castShadow shadow-mapSize={[2048, 2048]} />
      <mesh rotation-x={-Math.PI / 2} receiveShadow>
        <planeGeometry args={[160, 160]} />
        <meshStandardMaterial color="#0c1320" roughness={0.95} />
      </mesh>
      <gridHelper args={[160, 80, 0x1d3a5f, 0x122036]} position-y={0.02} />
      <Buildings />
      <Beacon position={[0, 1.2, 0]} name="能量核心" onPick={(n) => alert(n)} />
      <RadarDish />
      <OrbitControls enableDamping maxPolarAngle={Math.PI / 2 - 0.04} />
    </Canvas>
  )
}

逐段对照，命令式与声明式的映射一目了然：

原生 three（命令式）R3F（声明式）
new THREE.Scene() + 手动建 renderer/相机并接线<Canvas> 一个组件包办，场景内容由子节点组成
scene.add(mesh)JSX 嵌套：<mesh> 写进 <Canvas> 即自动挂载
new THREE.BoxGeometry(1, 1, 1) 构造函数传参<boxGeometry args={[1, 1, 1]} />
mesh.position.set(0, 1, 0)<mesh position={[0, 1, 0]}>
scene.fog = new THREE.FogExp2(...)<fogExp2 attach="fog" args={['#05070c', 0.022]} />
renderer.setAnimationLoop(loop) / requestAnimationFrameuseFrame((state, dt) => ...)，组件卸载自动取消
new OrbitControls(camera, dom) + 每帧 controls.update()<OrbitControls enableDamping />（drei 提供）
手动 Raycaster + DOM 事件监听<mesh onClick={...}>，事件直达网格

为什么需要 R3F ​

  • React 状态驱动 3D：颜色、转速、模型 URL 都变成 props/state，数据一变场景自动更新，不再手动同步 DOM 与 three 对象。
  • 组件复用：<Lights />、<RadarDish />、<Beacon /> 像乐高积木一样跨项目搬来搬去，这是 18.3 实战篇的主题。
  • 生态：官方辅助库 drei 提供几百个现成组件/钩子（控制器、环境、阴影、文字、加载器），大量"要抄半天"的原生写法变成一行 JSX。

术语解释：

  • 声明式（Declarative）：描述"要什么结果"，执行细节交给框架。SQL、React 都是声明式。
  • Reconciler（协调器）：React 比对前后 JSX 差异、决定增删改哪些底层对象的引擎。R3F 就是一个把 JSX 翻译给 three 的 reconciler。

Canvas：一个组件包办基础设施 ​

<Canvas> 在挂载时自动创建 renderer（默认开 antialias）、scene、默认透视相机，并处理窗口 resize 与像素比。常用 props：

jsx
<Canvas
  shadows                                  // 开启阴影（renderer.shadowMap.enabled）
  dpr={[1, 2]}                             // 像素比区间，等价于 clamp(devicePixelRatio, 1, 2)
  camera={{ position: [0, 2, 5], fov: 45 }}// 默认相机初始配置
  gl={{ antialias: true }}                 // 透传给 WebGLRenderer 构造参数
>

写进 <Canvas> 的所有子节点都会被 add 到它内部维护的 scene 上。

JSX 与 three 对象的映射规则 ​

记住四条就能读懂任何 R3F 代码：

  1. 小写驼峰标签 = THREE 命名空间里的类：<meshStandardMaterial> → new THREE.MeshStandardMaterial()；<torusKnotGeometry> → new THREE.TorusKnotGeometry()。
  2. JSX 属性 = 实例属性赋值：position={[0,1,0]} 等价于 mesh.position.set(0,1,0)；带连字符表示深入嵌套，shadow-mapSize={[2048,2048]} 等价于 light.shadow.mapSize.set(...)。
  3. args = 构造函数参数数组：<boxGeometry args={[1,1,1]} /> 等价于 new THREE.BoxGeometry(1,1,1)。
  4. attach = 挂到父对象的哪个属性：geometry/material 会自动 attach 到父 mesh 的对应槽位；而 fog、background 这类"scene 的命名属性"必须显式写 attach="fog"、attach="background"。

自定义类（如后处理 pass）可用 extend({ MyClass }) 注册后同样以标签使用，进阶篇会见到。

代码示例 ​

第一个完整 R3F 场景：旋转立方体 + 灯光 + 地面阴影 + drei 的 OrbitControls，单文件可直接运行：

jsx
// src/App.jsx —— 第一个 R3F 场景
import { Canvas, useFrame } from '@react-three/fiber'
import { OrbitControls } from '@react-three/drei'
import { useRef } from 'react'

function SpinningCube() {
  const ref = useRef()
  // useFrame 每帧执行；delta 是距上一帧的秒数，动画天然帧率无关（复习 4.2）
  useFrame((state, delta) => {
    ref.current.rotation.y += delta * 0.8
    ref.current.rotation.x += delta * 0.3
  })
  return (
    <mesh ref={ref} castShadow>
      <boxGeometry args={[1.6, 1.6, 1.6]} />
      <meshStandardMaterial color="#4f9cf9" roughness={0.35} metalness={0.1} />
    </mesh>
  )
}

export default function App() {
  return (
    <Canvas shadows dpr={[1, 2]} camera={{ position: [0, 2, 5], fov: 45 }} style={{ height: '100vh' }}>
      <color attach="background" args={['#0b0e14']} />
      <ambientLight intensity={0.2} />
      <directionalLight position={[3, 5, 4]} intensity={2} castShadow />
      <SpinningCube />
      <mesh rotation-x={-Math.PI / 2} position-y={-1.2} receiveShadow>
        <planeGeometry args={[12, 12]} />
        <meshStandardMaterial color="#1c2330" roughness={1} />
      </mesh>
      <OrbitControls enableDamping />
    </Canvas>
  )
}

常见问题解答 ​

Q1：R3F 和原生 three 能混用吗？

可以，而且很常见。R3F 创建的每一个对象都是货真价实的 three 实例：组件内 useThree() 能拿到 scene、camera、gl（即 renderer）、size 等底层对象；任何 JSX 标签挂上 ref 就是对应的 THREE.Mesh/THREE.Light 实例，可以直接调原生 API（如上文 Buildings 里的 setMatrixAt）。已有的原生 three 代码可以包一层 <primitive object={...} /> 直接塞进场景。

Q2：R3F 性能会不会比原生 three 差？

不会明显变差。reconciler 只在 JSX 变化时做一次差异比对；每帧动画走 useFrame 直接改 three 对象，完全不经过 React。真正渲染画面的仍是同一个 WebGLRenderer。常见的性能事故其实是误用——在渲染循环里 setState 导致 React 每秒重渲染 60 次，下一篇专门讲这条铁律。

Q3：我是 Vue 用户，怎么办？

看 TresJS——Vue 生态的声明式 three 渲染器，理念与 R3F 完全一致，只是 JSX 换成 Vue 模板语法（<TresMesh>、<TresBoxGeometry>）。Svelte 用户则有 Threlte。本篇学的映射规则（args/attach/驼峰属性）在那边几乎原样适用。

Q4：args 和 attach 到底什么时候必须写？

args：只要类的构造函数需要参数就必须写（几何体的尺寸、颜色的色值、雾的参数）；无参构造（如多数材质）可省略。attach：子节点要占据父对象的命名属性而非作为子级追加时必须写——典型是 attach="fog"、attach="background"；mesh 内的 geometry/material 有默认 attach 规则，不用写。

动手小练习 ​

  1. 把立方体换成 <torusKnotGeometry args={[0.7, 0.25, 160, 24]} />，调 roughness/metalness 观察高光变化（复习 6.1）。
  2. 给 <mesh> 加 onPointerOver/onPointerOut，悬停时把材质 emissive 改成青色——体会"事件就是 props"，全程没碰 Raycaster。
  3. 删掉 <color attach="background" /> 改用 CSS 给页面铺渐变背景，并给 <Canvas> 的 gl 属性传入 { alpha: true }，理解"背景透明"这条链路。
