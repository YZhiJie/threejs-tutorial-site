21.1 基础入门：大屏 3D 架构与相机漫游 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑫⑬⑮⑯ 再学习本篇。

核心概念讲解 ​

接桥：零件已齐，开装整机 ​

走到这里，你的工具箱其实已经集齐了"数据大屏"需要的全部零件：

零件来自在大屏里干什么
万级实例城市⑯ 大场景组织与优化底图层：一次 draw call 的城区底图
扫描线 / 全息特效⑫ 自定义着色器特效层：扫描环、发光轮廓
泛光 / 暗角合成链⑬ 后处理管线特效层：让画面"很贵"的氛围
glTF 真实资产⑮ glTF 资产管线底图层：精细模型按需上屏

所以这一篇没有新 API，讲的是"装配图"：这些零件按什么分层、谁和谁通信、相机怎么听指挥。把架构想对，大屏就是拼装而不是发明。

大屏 3D 的典型分层架构 ​

一个标准的 3D 数据大屏由四层组成，从下到上各司其职：

层职责技术选型性能要点
底图层城市/园区/厂区三维场景InstancedMesh + 合并静态几何draw call 控制在两位数
标注层楼名、设备牌、数值牌CSS2D / Sprite / 实例化标牌下一篇专门讲取舍
特效层扫描线、泛光、告警闪烁ShaderMaterial + EffectComposerPass 数量别贪多
UI 层标题栏、数据面板、列表纯 HTML + CSS，盖在 canvas 上pointer-events 管事件

最大的认知转变是 UI 层：大屏四周的标题栏、数据卡片、排行榜，不要试图用 3D 做——HTML 的排版能力、文字清晰度、开发效率都碾压三维文字。3D canvas 只负责中间那块"会动的地图"。

html
<!-- 典型结构：一层画布 + 一层 UI 罩子 -->
<div id="app"></div>            <!-- WebGL canvas，底图+标注+特效 -->
<div class="screen-ui">         <!-- UI 层：absolute 定位盖在上面 -->
  <div class="title-bar">智慧城市运营中心</div>
  <div class="side-panel left">…数据面板…</div>
  <div class="side-panel right">…视角书签按钮…</div>
</div>

关键 CSS 只有一条规则：罩子整体 pointer-events: none（事件穿透给 3D），需要点击的按钮单独开 pointer-events: auto。

相机漫游：从 A 点飞到 B 点 ​

大屏开场常有一段"从高空俯冲到园区"的运镜，点击建筑也会飞过去——这本质是相机关键帧插值：

  1. 记录起点（当前相机 position 与 controls.target）；
  2. 记录终点（目标位置与注视点）；
  3. 每帧推进进度 t: 0 → 1，用 lerpVectors 插值两组向量；
  4. 给 t 套一个缓动函数（smoothstep 就够），起飞和到站才柔和。

手写 lerp 还是 gsap？ gsap 一行 gsap.to(camera.position, {x, y, z}) 很香，但相机动画要同时驱动 position 和 controls.target 两组向量、还要处理"用户拖拽打断"，自己写三十行 lerp 反而更可控、零依赖。本文用手写版讲原理，项目里换 gsap 思路不变。

视角书签：一键飞行的"存档点" ​

书签是最实用的漫游组织方式——一个书签 = 一组 position + target：

js
const bookmarks = [
  { name: '全景俯瞰', pos: new THREE.Vector3(0, 95, 135), target: new THREE.Vector3(0, 0, 0) },
  { name: '中央广场', pos: new THREE.Vector3(16, 9, 26),  target: new THREE.Vector3(0, 3, 0) }
]

UI 层渲染成按钮，点击就调 flyTo(bookmark)。运维场景里"总览 → 分区 → 重点设备"的三级视角，就是三组书签。书签数据交给运营同学配置都没问题——它只是 JSON。

代码示例 ​

以下是与演示 camera-tour.html 对应的核心代码，按分层逐段拆解：

① 底图层：16.3 的成品件原样搬来——合并地面 1 次 draw call，4000 栋楼 1 次 draw call，中央留出广场：

js
// 地面：25 块地板合并成一个 Mesh
const groundGeoms = []
for (let i = 0; i < 25; i++) {
  const g = new THREE.BoxGeometry(24, 0.2, 24)
  g.translate((i % 5 - 2) * 25, -0.1, (Math.floor(i / 5) - 2) * 25)
  groundGeoms.push(g)
}
scene.add(new THREE.Mesh(
  mergeGeometries(groundGeoms),
  new THREE.MeshStandardMaterial({ color: 0x1a2333, roughness: 0.95 })
))

// 楼群：一个 InstancedMesh，中央留广场
const city = new THREE.InstancedMesh(boxGeometry, buildingMaterial, 4000)
for (let i = 0; i < 4000; i++) {
  const x = (i % side - side / 2) * 3.4
  const z = (Math.floor(i / side) - side / 2) * 3.4
  const inPlaza = Math.abs(x) < 10 && Math.abs(z) < 10   // 广场不摆楼
  const h = inPlaza ? 0.01 : 1.5 + Math.random() * 12
  dummy.position.set(x, h / 2, z)
  dummy.scale.set(1.8, h, 1.8)
  dummy.updateMatrix()
  city.setMatrixAt(i, dummy.matrix)
  city.setColorAt(i, color.setHSL(0.58, 0.25, 0.3 + Math.random() * 0.35))
}
scene.add(city)

② 飞行状态与 flyTo：一次飞行就是"两组向量的插值任务"：

js
const flight = {
  active: false, t: 0, duration: 2.2,
  fromPos: new THREE.Vector3(), toPos: new THREE.Vector3(),
  fromTarget: new THREE.Vector3(), toTarget: new THREE.Vector3()
}

function flyTo(bm) {
  flight.fromPos.copy(camera.position)      // 起点 = 相机当前在哪
  flight.fromTarget.copy(controls.target)
  flight.toPos.copy(bm.pos)                 // 终点 = 书签存的位置
  flight.toTarget.copy(bm.target)
  flight.t = 0
  flight.active = true
}

const ease = t => t * t * (3 - 2 * t)       // smoothstep 缓动

// 飞行途中用户拖拽 → 立即打断，控制权还给用户
controls.addEventListener('start', () => { flight.active = false })

③ 渲染循环里推进插值：

js
renderer.setAnimationLoop(() => {
  timer.update()
  const dt = timer.getDelta()
  if (flight.active) {
    flight.t += dt / flight.duration        // 进度 0 → 1
    const k = ease(Math.min(flight.t, 1))
    camera.position.lerpVectors(flight.fromPos, flight.toPos, k)
    controls.target.lerpVectors(flight.fromTarget, flight.toTarget, k)
    if (flight.t >= 1) flight.active = false // 到站，交还控制权
  }
  controls.update()
  renderer.render(scene, camera)
})

④ UI 层接线：按钮是普通 DOM，点击调 flyTo 即可——HTML 与 3D 的通信就是直接的函数调用，不需要任何桥接框架：

js
document.querySelectorAll('.bookmark-btn').forEach(btn =>
  btn.addEventListener('click', () => flyTo(bookmarks[+btn.dataset.bm]))
)

常见问题解答 ​

Q1：大屏要投到各种分辨率的屏幕上，设计稿 1920×1080 怎么适配？

业界标准做法是固定设计稿尺寸 + 整体缩放：UI 层容器写死 width: 1920px; height: 1080px，JS 监听窗口变化计算 scale = Math.min(w / 1920, h / 1080)，然后 transform: scale(scale) 加居中定位。3D canvas 不参与缩放，照常 renderer.setSize(真实宽高) 铺满——缩放只作用在 HTML UI 上。这样无论 4K 拼接屏还是 1366 的笔记本，版面比例永远和设计稿一致。

Q2：HTML 面板盖住 3D 区域后，拖拽 OrbitControls 没反应了？

事件被 HTML 元素截胡了。规则：大屏 UI 罩子容器设 pointer-events: none（鼠标事件穿透到下面的 canvas），只有真正可交互的元素（按钮、列表、输入框）单独设 pointer-events: auto。本演示里 .screen-ui 整体 none、右侧书签面板 auto，所以点按钮好使、拖地图也好使。

Q3：飞行途中用户拖拽会怎样？要不要锁交互？

不要锁——用户打断运镜是合理诉求，锁了只会让人觉得"卡死"。正确做法是监听 controls 的 start 事件（用户按下拖拽时触发），在回调里把 flight.active = false，插值立即停止，OrbitControls 无缝接管。想更顺滑，可以把打断时的当前位置作为新起点，避免"跳一下"的感觉。

Q4：飞行路径会穿过楼群中间，穿模很难看怎么办？

三个思路按成本排：① 书签点本身抬高，让飞行基本在高空完成，到站再降下来——大多数大屏这样就够了；② 给 flight 加一个"途经点"字段，先飞到高空中转点再俯冲，两段 lerp 串行；③ 上真正的曲线轨迹（CatmullRomCurve3 取样插值），适合开场秀那种固定运镜。日常交互飞行用①②即可。

动手小练习 ​

  1. 给书签加第 ④ 个"夜景模式"：飞行到位的同时把场景雾密度调高、楼群 instanceColor 整体调暗，体会"书签 = 相机 + 场景状态"的扩展思路。
  2. 把缓动函数从 smoothstep 换成 1 - Math.pow(1 - t, 3)（easeOutCubic），对比起飞瞬间的顿挫感差异。
  3. 实现"巡回播放"：用 setInterval 每 6 秒自动 flyTo 下一个书签，并在用户拖拽打断时暂停巡回（提示：打断时 clearInterval）。
