21.2 进阶应用：大规模标注、GIS 与 3DTiles ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑫⑬⑮⑯ 再学习本篇。

核心概念讲解 ​

上一篇搭好了大屏骨架，这一篇解决三个进阶问题：标注上了千级怎么不卡、真实经纬度怎么变成世界坐标、城市级倾斜摄影数据怎么流式加载。

千级标注：三种方案取舍 ​

标注（楼名、设备牌、数值牌）是大屏最密集的元素，三种主流方案的取舍完全不同：

方案原理优点致命伤适用量级
CSS2DRenderer每个标注一个 DOM 节点，每帧投影到屏幕坐标文字最清晰、CSS 随便排版、天然可点DOM 数量瓶颈：近千个节点每帧算矩阵+排版，帧率直线掉< 100
Sprite文字画进 canvas 纹理，贴在永远面向相机的面片上脱离 DOM，3D 空间定位准确一张标签一次 draw call，千级又是 ⑯ 的通话费灾难；文字会糊< 300
实例化标牌InstancedMesh 一次提交全部标牌1 次 draw call 画全部；instanceId 拾取、setColorAt 高亮都现成文字要额外做（图集/HUD 补位）1000+ 首选

经验法则：标注 < 100 用 CSS2D 最省事；过千必须实例化；Sprite 是"几十到几百、且想要 3D 空间感"的过渡选项。

CSS2DRenderer：易用但有数量天花板 ​

js
import { CSS2DRenderer, CSS2DObject } from 'three/addons/renderers/CSS2DRenderer.js'

const cssRenderer = new CSS2DRenderer()
cssRenderer.setSize(innerWidth, innerHeight)
cssRenderer.domElement.style.pointerEvents = 'none' // 事件穿透给 3D

const div = document.createElement('div')
div.className = 'tag'; div.textContent = 'A-001'
const label = new CSS2DObject(div)
label.position.set(x, h + 2, z)
scene.add(label)
// 每帧：cssRenderer.render(scene, camera)

每个 CSS2DObject 每帧都要做一次"世界坐标 → 屏幕坐标"投影并写 DOM style，近千个节点时 CPU 全耗在排版上。

实例化标牌：千级标注的最优解 ​

把标牌当"几何体"实例化，交互走 ⑯ 的老路：raycast 拿 instanceId、setColorAt 高亮。文字怎么办？三种补位策略：悬停 HUD 显示（演示用的方案）、文字图集（所有字符合在一张纹理，shader 按实例偏移取样）、近距才加载 CSS2D（远处图钉、近处文字，本质是标注版 LOD）。

GIS 坐标与经纬度映射 ​

真实业务数据给的是经纬度，Three.js 要的是世界坐标（米）。行业标准投影是墨卡托投影（Web Mercator），基础公式：

js
// 墨卡托投影：经纬度(度) → 平面坐标(米)，R 为地球半径
const R = 6378137
function lonLatToMercator(lon, lat) {
  const λ = lon * Math.PI / 180                     // 经度转弧度
  const φ = lat * Math.PI / 180                     // 纬度转弧度
  return {
    x: R * λ,
    y: R * Math.log(Math.tan(Math.PI / 4 + φ / 2))  // 纬度非线性拉伸
  }
}

但园区级项目用不上它——几平方公里内地球曲率可以忽略，直接用"每度多少米"做线性映射：

js
// 园区原点（比如西南角）的经纬度，业务方提供
const ORIGIN = { lon: 116.397, lat: 39.908 }
const METER_PER_LON = 111320 * Math.cos(ORIGIN.lat * Math.PI / 180) // 经度方向随纬度打折
const METER_PER_LAT = 110540                                          // 纬度方向近似常数

function lonLatToWorld(lon, lat) {
  return new THREE.Vector3(
    (lon - ORIGIN.lon) * METER_PER_LON, 0,
    -(lat - ORIGIN.lat) * METER_PER_LAT   // 北纬越大 → -Z 方向（北对齐 -Z）
  )
}

精度红线：别拿 (lon * 111320) 这种上万米的绝对值直接当世界坐标——float32 只有约 7 位有效数字，大数会抖动。先减原点、再换算，让场景坐标保持在原点附近的千米级小数值。

3DTiles 概念与接入思路 ​

城市级倾斜摄影/白模数据动辄几十 GB，不可能一次加载。3DTiles 是 Cesium 提出的流式标准：把城市切成多层级瓦片，相机远看只加载粗瓦片，飞近再逐级换精细瓦片——思路与 ⑯ 的 LOD 完全一致，只是换成了行业标准数据格式。

Three.js 侧接入思路（本篇只给地图，不深入）：

  • 3d-tiles-renderer-js：NASA AMMOS 社区维护的 Three.js 加载器，TilesRenderer 挂进场景就能流式加载；
  • CesiumJS：如果项目以 GIS 为核心（全球地形、椭球坐标系），直接用 Cesium 比 Three.js 硬接更省命；
  • 自建园区通常不需要 3DTiles——glTF + ⑮ 的压缩管线足够，3DTiles 是"整个城市"量级才出场的方案。

③ 高亮与还原：setColorAt + needsUpdate，老配方：

js
function highlight(i) {
  if (selected >= 0 && pinMesh) {          // 先还原上一个的颜色
    pinMesh.setColorAt(selected, pinColor.setHSL(0.52, 0.75, 0.55))

常见问题解答 ​

Q1：CSS2DRenderer 标注一多就卡，但又想要它的清晰文字怎么办？

混合策略：① 距离剔除——每帧（或每 0.5s）只显示相机 200 米内的标注，其余 object.visible = false；② 聚合——远处把一片楼合并成一个"XX 片区 · 32 栋"的汇总标注；③ 分层——远景实例化图钉、拉近到阈值再切换成 CSS2D 文字。纯靠 CSS2D 硬扛千级标注没有出路。

Q2：Sprite 上的文字放大就糊，怎么救？

糊是因为 canvas 纹理分辨率跟不上显示尺寸。三招：① canvas 按显示尺寸的 2~3 倍画（如显示 128px 宽就画 384px），再靠 sprite.scale 缩回去；② texture.anisotropy = renderer.capabilities.getMaxAnisotropy() 缓解斜视模糊；③ 字号别太小，canvas 里至少 24px 起步。但记住 Sprite 的本质问题是 draw call，救清晰度救不了数量。

Q3：经纬度转世界坐标后物体疯狂抖动/位置漂移？

典型的 float32 精度问题。墨卡托投影结果是以地心为基准的数百万米大数，GPU 的 32 位浮点只有约 7 位有效数字，米级以下全在抖。解法只有一个：重定原点——以园区中心为 (0,0,0)，所有数据先减原点经纬度再换算，场景内坐标控制在几千米以内。shader 里做计算的同理，大数减法要在 CPU 侧用 float64 算完再传。

Q4：自建园区场景要不要上 3DTiles？

看数据量级：建模师手工精修的园区模型（几十 MB 级），glTF + ⑮ 的 Draco/Meshopt 压缩管线体验更好、可控性更强；只有接第三方城市级倾斜摄影数据（GB 级、天然按瓦片生产）时才需要 3DTiles。别把 3DTiles 当"更高级"的格式，它是"更大规模"的格式。

动手小练习 ​

  1. 给演示的 CSS2D 模式加"200 米距离剔除"，对比剔除前后的 FPS，验证混合策略的有效性。
  2. 在实例化标牌模式下实现悬停 HUD：raycast 命中后把楼名显示在鼠标旁的 div 里，体会"实例化 + HTML 补文字"的搭档方式。
  3. 用 lonLatToWorld 把你家附近 10 个 POI 的经纬度撒进场景（数据可从地图网站拾取），检查相对位置是否与真实地图一致。
