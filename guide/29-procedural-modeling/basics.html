29.1 基础入门：程序化几何与噪声 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑤ 再学习本篇。

核心概念讲解 ​

接桥：5.2 的顶点形变只能"改形状"，不能"造物体" ​

在 ⑤ 几何体 · 自定义顶点 里，我们手写过一座金字塔：准备 12 个顶点、每面独立三顶点、填 position、再调 computeVertexNormals()。那段代码解决的是"内置几何体不够用时怎么自己填数组"。

但它有一个天花板：数组是写死的。想要第二座金字塔、第三座金字塔，只能复制粘贴再改数字；想要一片有 200 棵树的林子、一块带山谷的地形、一座上千栋楼的城市，复制粘贴就彻底失效了。

这一篇把"手写数组"升级成"写函数"：给一组参数，函数自动算出顶点、索引、法线、UV 与颜色。这个函数就叫几何生成器（geometry generator）。有了它，形状不再是一份静态数据，而是一条可以反复求值的配方。

程序化建模到底值在哪 ​

游戏和三维项目里，程序化建模不是"美术偷懒"，而是一种资产策略。它的价值可以拆成四条：

维度传统模型资产程序化生成
制作成本建模、展 UV、烘焙，人力密集写一次生成器，批量产出
变体数量每改一版都要重新导出改一个参数就是新变体
包体体积顶点数据随模型增长，动辄数 MB只有生成器代码，KB 级
可控性改形状要回美术软件seed + 参数完全可复现、可版本化
适用边界主角、道具、精确造型地形、植被、城市、岩石、重复结构

一句话概括：需要"设计感"的物体交给美术，需要"数量与变化"的物体交给生成器。程序化建模的产出通常不是单个精品，而是"同一套规则下的无穷家族"。

生成器的骨架：参数进，缓冲区出 ​

任何程序化几何，最终都要落到 BufferGeometry 的四类数据上：

  1. position：每顶点 3 个数，描述空间位置。
  2. index：每三角形 3 个整数，指向顶点数组。索引让顶点能被多个三角形复用。
  3. normal：每顶点 3 个数，决定受光方向。可以手算，也可以 computeVertexNormals()。
  4. uv / color：贴图坐标或顶点色，用于材质表现。

因此生成器天然是一个纯函数：

js
function makeSomething(params) {
  const positions = []
  const indices = []
  // 1. 按参数铺顶点
  // 2. 按拓扑填索引
  const geo = new THREE.BufferGeometry()
  geo.setAttribute('position', new THREE.Float32BufferAttribute(positions, 3))
  geo.setIndex(indices)
  geo.computeVertexNormals()
  return geo
}

参数是输入，BufferGeometry 是输出，中间不碰 DOM、不碰 GPU、不依赖时间。这条纯函数约定有三个好处：可单测、可缓存、可在 Web Worker 里算。后面所有配方——波浪平面、噪声地形、环形坡道、岩石球——都只是这个骨架的不同填法。

值噪声：从"随机数"到"连续起伏" ​

直接用 Math.random() 铺高度会得到一堆尖刺：相邻采样点毫无关系。地形需要的是连续：这一处的值应该和旁边那处相近。

值噪声（value noise） 的做法是：

  1. 在整数格点上放随机值（用哈希函数，而不是数组，省内存）；
  2. 采样时找到所在格子的四个角；
  3. 按距离做平滑插值（t*t*(3-2t) 这种 S 形曲线，保证一阶导连续）。
js
function hash2(ix, iy, seed) {
  let h = Math.imul(ix, 374761393) + Math.imul(iy, 668265263) + Math.imul(seed, 1442695041)
  h = Math.imul(h ^ (h >>> 13), 1274126177)
  h ^= h >>> 16
  return (h >>> 0) / 4294967296
}

function vnoise2(x, y, seed) {
  const xi = Math.floor(x)
  const yi = Math.floor(y)
  const u = smooth(x - xi)
  const v = smooth(y - yi)
  const a = hash2(xi, yi, seed)
  const b = hash2(xi + 1, yi, seed)
  const c = hash2(xi, yi + 1, seed)
  const d = hash2(xi + 1, yi + 1, seed)
  return (a * (1 - u) + b * u) * (1 - v) + (c * (1 - u) + d * u) * v
}

术语解释：值噪声 value noise 在格点存随机标量并插值；梯度噪声 gradient noise 在格点存随机梯度，插值后更平滑；Simplex 噪声 是梯度噪声的改进版，用单纯形网格、方向性伪影更少、高维计算量更低。Three.js 仓库里没有内置噪声，项目常用 simplex-noise 这类小库，但原理都是"格点 + 插值"。

种子与可复现性：同一 seed 必须同一座山 ​

程序化项目最容易被忽略的一条纪律：随机必须可复现。

  • 用 Math.random()，每次刷新页面都是新的地形，美术没法验收，bug 无法复现，截图对不上。
  • 用带种子的伪随机（seeded PRNG，如 mulberry32、xorshift），同一个 seed 永远得到同一串数。
  • 哈希噪声本身就以 seed 作为输入，所以换 seed 等于换整块地形。
js
function mulberry32(seed) {
  let a = seed >>> 0
  return function () {
    a = (a + 0x6D2B79F5) >>> 0
    let t = Math.imul(a ^ (a >>> 15), 1 | a)
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296
  }
}

注意 Math.imul 的用法：JavaScript 的乘法会溢出到浮点，按位运算又会被截断成 32 位，imul 让整数乘法保持在 32 位内，哈希才稳定。这套写法在 29.2、29.3 里会继续复用。

fBm：把一层噪声叠成"山" ​

单层噪声只有一种尺度，看起来像均匀的起伏。真实地形有大山、有丘陵、有碎石。fBm（分形布朗运动） 的做法是把多层噪声按"频率翻倍、振幅减半"叠加：

js
function fbm2(x, y, seed, octaves = 4) {
  let sum = 0, amp = 0.5, freq = 1, norm = 0
  for (let i = 0; i < octaves; i++) {
    sum += amp * vnoise2(x * freq, y * freq, seed + i * 131)
    norm += amp
    amp *= 0.5
    freq *= 2
  }
  return sum / norm
}
参数含义调大的效果
octaves叠加层数细节更多，也更容易出高频噪点
lacunarity频率倍率（默认 2）越大层次拉得越开，山更"尖"
gain振幅倍率（默认 0.5）越大越粗糙，接近 1 会变成白噪声
seed基准种子换一块完全不同的地形

域扭曲：让规则形状"活"起来 ​

如果直接拿坐标去采样噪声，山谷会沿网格方向排列，看起来有"格子味"。域扭曲（domain warping） 先用一层噪声去偏移采样坐标，再采第二层：

js
const wx = fbm2(x * 0.7, z * 0.7, seed + 5) * warp
const wz = fbm2(x * 0.7 + 3.1, z * 0.7 - 1.7, seed + 9) * warp
const h = fbm2(x * 1.2 + wx, z * 1.2 + wz, seed)

这样山谷会弯曲、河流会拐弯，规则感被打破。代价是采样次数翻倍——第 7 条性能纪律里会再算这笔账。

HeightField：用一张"高度图"造地形 ​

高度场（HeightField） 是最常见的程序化地形表示：在 XZ 平面上铺一张规则网格，每个格点的 Y 由噪声函数决定。

js
const geo = new THREE.PlaneGeometry(4.6, 4.6, seg, seg)
geo.rotateX(-Math.PI / 2)          // 从 XY 平面翻到 XZ 平面
const pos = geo.attributes.position

for (let i = 0; i < pos.count; i++) {
  const x = pos.getX(i)
  const z = pos.getZ(i)
  const n = fbm2(x * 1.15, z * 1.15, seed)
  pos.setY(i, (n - 0.5) * strength * 3.4)
}
geo.computeVertexNormals()

三个要点：

  1. 网格密度决定细节上限。细分不够，再好的噪声也只是"糊的山"；细分过高，顶点数按平方增长。
  2. 位移后必须重算法线，否则光照仍按平面法线计算，山看起来像贴纸。
  3. 采样频率与网格密度要匹配。网格每格 0.1 个单位、噪声却每 80 个单位才变一次，就浪费顶点；反过来噪声比网格还密，会出现高频锯齿。

法线：重算只是第一步 ​

computeVertexNormals() 对索引几何体会把共享顶点的面法线取平均，得到平滑着色；对非索引几何体则每个三角形独立，得到硬棱。所以同一个生成器换一种输出方式，观感完全不同：

需求做法结果
地形、球体、曲面索引 + computeVertexNormals()平滑、连续
岩石、碎块、晶体geometry.toNonIndexed() 或材质 flatShading: true块面感、硬棱
手工精确法线自己写 normal 属性可做假高光、假斜面

还有一个常见错误：绕序反了。三角形默认逆时针为正面，索引顺序写反，computeVertexNormals() 算出的法线会朝内，光照变黑、背面透光。遇到"明明有光却一片漆黑"，先查索引绕序，再查材质 side。

性能：顶点数、生成时机与内存回收 ​

程序化几何的开销分三块，要分开算：

开销何时发生控制手段
JS 计算（采样噪声、填数组）生成时降细分、降 octaves、避免每帧重建
顶点/索引内存上传 GPU 时索引复用顶点、按需 LOD
GPU 绘制每帧合并、实例化（29.2、29.3 展开）

三条硬纪律：

  1. 生成发生在初始化或参数变化时，绝不写在 setAnimationLoop 里。每帧重建几何会同时制造 GC 压力和 GPU 重传。
  2. 替换几何前先 geometry.dispose()。mesh.geometry = newGeo 不会自动释放旧缓冲，反复拖滑块会稳步泄漏显存。
  3. GUI 连续触发要节流。滑块 onChange 在拖动时会连续触发，128 细分的地形每次重建要几十毫秒，看起来就是"拖不动"。可以在 onFinishChange 重建，或加一个 requestAnimationFrame 合并。

估算内存有个简单公式：一个顶点若带 position、normal、uv 三个属性，就是 3+3+2 = 8 个 float，即 32 字节；一万顶点约 320 KB。索引另算，每个三角形 3 个整数约 12 字节。做移动端预算时，这个数字比"看起来不卡"可靠得多。

四种配方，四种拓扑 ​

本篇演示把四类最常见的生成器放在同一个台子上：

配方数学本质拓扑典型用途
波浪平面解析式 sin/cos规则网格水面、旗帜、布料示意
噪声地形高度场 + fBm规则网格地形、沙丘、月球表面
环形坡道参数曲面（角度→半径/高度）手写带状索引螺旋楼梯、赛道、管道
程序化岩石球球面沿法向位移球面网格岩石、陨石、低模星球

前两种是"平面网格 + 改 Y"，第三种是"自己写索引"，第四种是"改已有几何体的顶点"。把这四种吃透，绝大多数程序化造型都能拆解成其中之一或它们的组合。

代码示例 ​

对应演示 geometry-recipes-lab.html：左侧只放一个 Mesh，切换配方或拖动 seed / 强度 / 细分时重建几何，面板实时显示顶点数、三角数与缓冲大小。

① 配方分发：一个入口管住四种生成器：

js
function rebuild() {
  const seg = Math.round(params.resolution)
  const seed = Math.round(params.seed)
  let geo

  if (params.recipe === '波浪平面') geo = makeWavePlane(seg, seed, params.strength)
  else if (params.recipe === '噪声地形') geo = makeTerrain(seg, seed, params.strength)
  else if (params.recipe === '环形坡道') geo = makeRingRamp(seg, seed, params.strength)
  else geo = makeRock(seg, seed, params.strength)

  mesh.geometry.dispose()      // 先释放旧缓冲，再换新几何
  mesh.geometry = geo
  material.flatShading = params.recipe === '程序化岩石球'
  material.needsUpdate = true

  const verts = geo.attributes.position.count
  const tris = geo.index ? geo.index.count / 3 : verts / 3
  statsEl.textContent = `顶点 ${verts} · 三角 ${Math.round(tris)} · seed ${seed}`
}

② 噪声地形：高度场 + 高度映射颜色：

js
const geo = new THREE.PlaneGeometry(4.6, 4.6, seg, seg)
geo.rotateX(-Math.PI / 2)
const pos = geo.attributes.position
const colors = []

for (let i = 0; i < pos.count; i++) {
  const x = pos.getX(i)
  const z = pos.getZ(i)
  const n = fbm2(x * 1.15 + 8.2, z * 1.15 - 3.7, seed)
  const y = (n - 0.5) * strength * 3.4
  pos.setY(i, y)
  pushColor(colors, 0x0f2a4a, 0xe5d5b0, (y + 1.4) / 2.8)
}
geo.setAttribute('color', new THREE.Float32BufferAttribute(colors, 3))
geo.computeVertexNormals()

顶点色不是装饰，而是把"高度"这一标量编码进几何的廉价手段：不用贴图、不用着色器，MeshStandardMaterial({ vertexColors: true }) 直接就能读出海拔层次。

③ 环形坡道：自己拼索引，注意绕序：

js
for (let i = 0; i < around; i++) {
  for (let j = 0; j < width - 1; j++) {
    const a = i * width + j
    const b = (i + 1) * width + j
    const c = (i + 1) * width + j + 1
    const d = i * width + j + 1
    indices.push(a, b, c, a, c, d)
  }
}

a-b-c 这两个三角形让法线朝上：先沿角度方向、再跨到外圈，叉乘结果指向 +Y。写反了就会得到一条"从下面被照亮"的坡道，而且因为开了 DoubleSide 不容易发现，只是明暗关系全错。

④ 岩石球：沿法向位移，别沿坐标轴位移：

js
dir.fromBufferAttribute(pos, i).normalize()
const n = fbm3(dir.x * 2.2 + 4.1, dir.y * 2.2, dir.z * 2.2, seed)
const radius = 1.42 * (1 + strength * ((n - 0.5) * 0.9))
pos.setXYZ(i, dir.x * radius, dir.y * radius, dir.z * radius)

沿法向（球面上就是归一化位置）位移，半径变化是均匀的；如果直接改 y，球会被拉成橄榄，而且极点附近会挤成一团。

⑤ 线框与统计：让几何结构可见：

js
wire.geometry.dispose()
wire.geometry = new THREE.WireframeGeometry(geo)
wire.visible = params.wireframe

线框不是调试专属。程序化几何最容易出问题的地方就是拓扑（缺面、绕序、接缝），线框能一眼看出来。把线框挂在同一个 Mesh 下，旋转、缩放都会跟随。

常见问题解答 ​

Q1：地形接缝处出现一条裂缝或一道硬边，是什么原因？

先分清是"几何裂缝"还是"法线接缝"。几何裂缝通常来自两次生成时采样坐标不一致：例如左右两块地形分别用 x 与 x + offset 采样，边界格点的噪声值不同，顶点就被拉开。修法是把世界坐标作为采样输入，而不是局部坐标。法线接缝则是因为两块地形各自 computeVertexNormals()，边界顶点的平均法线只考虑了本块三角形，两侧亮度突变。可以合并成一个几何体再统一算法线，或为边界顶点手工复制对侧法线。

Q2：位移后光照还是平的，山看起来像贴纸？

三个检查点：① 是否调用了 computeVertexNormals()；② 是否在位移之后调用（顺序错了等于按原始平面算法线）；③ 材质是否用了 MeshBasicMaterial——基础材质不参与光照，法线再准也没用。还有一个隐蔽情况：把几何体交给 InstancedMesh 时共享同一份几何体，法线是共享的，实例缩放如果非等比会扭曲法线，需要自行修正或接受近似。

Q3：拖动滑块时页面明显卡顿，甚至越拖越卡？

前者是重建频率问题：lil-gui 的 onChange 在拖动中连续触发，128 细分的地形每次要采样上万次噪声。改用 onFinishChange，或用 requestAnimationFrame 把一帧内的多次变更合并成一次重建。后者多半是显存泄漏：每次 mesh.geometry = newGeo 前忘记 geometry.dispose()，旧缓冲一直留在 GPU。判断方法是在 DevTools 里看 renderer.info.memory.geometries 是否单调上涨。

Q4：同一个 seed 在我电脑上是这座山，同事电脑上是另一座？

先查是否用了 Math.random()；再查哈希里是否用了普通 * 而不是 Math.imul——JavaScript 的数字会在大整数上溢出成浮点，不同引擎的精度处理可能让哈希结果分叉；最后查是否把浮点坐标直接喂给 Math.floor 做格点索引，跨平台浮点误差会让边界格点偶尔落到相邻格子。稳妥做法是：种子固定、哈希全用 Math.imul、格点索引由整数网格生成而不是从浮点反推。

术语解释：

  • 几何生成器 geometry generator：把参数映射为 BufferGeometry 的纯函数。
  • 值噪声 value noise：整数格点随机标量 + 平滑插值的连续噪声。
  • fBm：多层噪声按频率翻倍、振幅减半叠加，形成分形细节。
  • 域扭曲 domain warping：用噪声偏移采样坐标，打破网格方向感。
  • 高度场 heightfield：用二维网格 + 高度函数表示地形。
  • 索引几何体 indexed geometry：用 index 复用顶点；非索引则每三角形独立顶点。

动手小练习 ​

  1. 打开 geometry-recipes-lab.html，把配方切到"噪声地形"，固定 seed，把细分从 24 拉到 128。记录顶点数与三角数的增长倍率，并解释为什么是"接近平方"而不是"线性"。
  2. 给波浪平面加一层域扭曲：用 fbm2 的返回值偏移采样坐标，对比开启前后地形的"格子感"，记录你用的 warp 强度。
  3. 把岩石球的位移改成只改 y 坐标（不沿法向），观察球体如何被拉成橄榄形，并用法线方向解释为什么极点附近会出现挤压。
