29.2 进阶应用：参数化建模与生长规则 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ②⑤ 再学习本篇。

核心概念讲解 ​

接桥：2.2 的层级变换可以描述一棵树，但描述不了"一林子树" ​

在 ② 场景 · 层级变换 里，我们用 Group 套 Group 的方式摆过一棵树：树干是一个 Mesh，树枝作为子节点挂在树干上，叶子再挂在树枝上。层级变换解决的是"一个物体的部件如何相对运动"——转树干，整棵树跟着转；转树枝，只有那一枝动。

问题在于，这套层级是手工搭出来的。一棵树要点几十次 add，一林子树就是几百上千次，而且每一棵都得手摆。层级变换能表达"这棵树长什么样"，却表达不了"按什么规则长出更多树"。

这一篇补上后半句：用规则生成结构，再用合并或实例化把大量结构压成可渲染的数据。从 L-System 的字符串生长，到挤出与放样，再到建筑模块拼装与三种输出策略，一条线串起来。

L-System：用字符串描述生长 ​

L-System（Lindenmayer System） 最早用来描述植物细胞分裂，后来成了图形学里最经典的植物生成方法。它只有两件事：

  1. 公理（axiom）：初始字符串，比如 F。
  2. 产生式（rules）：把字符替换成更长的字符串，比如 F → F[+F]F[-F]F。

迭代若干次后，字符串会指数级变长：

js
function expand(axiom, rules, depth) {
  let s = axiom
  for (let d = 0; d < depth; d++) {
    let next = ''
    for (const ch of s) next += rules[ch] || ch
    s = next
  }
  return s
}

再用"海龟解释"把字符串变成几何：

字符含义
F前进一段并留下一段枝
+ / -绕局部轴左转 / 右转一个角度
[压栈，记录当前位置与朝向
]出栈，回到上一个分叉点
L在当前位置放一片叶子
js
const stack = []
const cursor = { pos: new THREE.Vector3(), dir: new THREE.Vector3(0, 1, 0) }
for (const ch of expanded) {
  if (ch === 'F') {
    const end = cursor.pos.clone().addScaledVector(cursor.dir, step)
    branches.push({ a: cursor.pos.clone(), b: end, radius })
    cursor.pos.copy(end)
  } else if (ch === '[') stack.push(cursor.pos.clone(), cursor.dir.clone())
  else if (ch === ']') {
    cursor.dir.copy(stack.pop())
    cursor.pos.copy(stack.pop())
  }
}

L-System 的优点是可读、可复现、字符串本身就是"物种基因"；缺点是指数膨胀：深度加一，字符数可能翻三倍。工程上必须给字符数设上限，否则浏览器会先卡死在字符串拼接上。

实际项目里更常见的是"递归分支 + 参数抖动"：不写字符串，直接递归生长，每一代的长度按比例衰减、角度加随机扰动。它比 L-System 少一层解释器，参数也更容易和 GUI 绑定——本篇演示用的就是这条路。

递归分支：一棵树的四个参数 ​

把一棵树拆成"枝段列表"，只需要四个参数：

参数作用调大的效果
递归深度 depth分几级枝更密，三角数与 draw call 增长
分枝角度 angle子枝偏离母枝的角度树冠更张开，过大则像灌木
长度衰减 decay每级长度比例越大越修长，过小变矮胖
随机种子 seed抖动序列换一棵同物种的树

每次分叉时，用四元数把母枝方向绕一根水平轴旋转，再叠加一点向上偏置，避免子枝往下长：

js
const axis = new THREE.Vector3(Math.cos(az), 0, Math.sin(az))
const q = new THREE.Quaternion().setFromAxisAngle(axis, angle)
const dir = parentDir.clone().applyQuaternion(q)
dir.y += 0.14
dir.normalize()

生成完得到两样东西：枝段数组（起点、终点、半径）与叶片数组（位置、缩放、朝向）。注意它们都还是"数据"，不是 Mesh——输出方式可以晚一步再决定，这正是本篇的核心分层。

从枝段到几何：矩阵、合并与实例化 ​

一段树枝本质上是一根"被拉伸、旋转、平移过的单位圆柱"。所以只要给每段算一个矩阵：

js
function branchMatrix(a, b, radius) {
  const dir = b.clone().sub(a)
  const len = dir.length()
  dir.normalize()
  dummy.position.copy(a).addScaledVector(dir, len * 0.5)
  dummy.quaternion.setFromUnitVectors(new THREE.Vector3(0, 1, 0), dir)
  dummy.scale.set(radius, len, radius)
  dummy.updateMatrix()
  return dummy.matrix
}

矩阵一旦有了，三种输出方式都只是"怎么用它"的差别：

  • 每枝一 Mesh：mesh.applyMatrix4(matrix)，直观、可单独控制，但 draw call 等于枝数。
  • 合并几何：unitGeo.clone().applyMatrix4(matrix) 后 mergeGeometries，一次提交画完，但无法再单独动某一枝。
  • InstancedMesh：几何体只留一份，矩阵写进 instanceMatrix，内存最省，还能逐实例改颜色。

三种方式的取舍必须背下来：

输出方式draw call内存可编辑性适合场景
每枝一 Mesh等于枝数（几十到几百）共享 1 份几何，对象开销大每枝可独立动画、换材质近景主角、需要交互的树
合并几何1（按材质分组）顶点数据被复制 N 份改一枝要重建整块缓冲静态森林、远景装饰
InstancedMesh11 份几何 + 每实例 64 B 矩阵可逐实例换矩阵/颜色，但不能换材质同构物体批量、可风吹的树

一句话选型：要动 → 实例化；不动 → 合并；数量少或要独立逻辑 → 独立 Mesh。 49 棵静态树用合并，49 棵会摆动的树用实例化，3 棵近景主角用独立 Mesh。

挤出与放样：把二维轮廓变成三维 ​

除了"从数据生成几何"，Three.js 还提供两条"从轮廓生成体积"的路线：

① ExtrudeGeometry：拉伸二维形状

js
const shape = new THREE.Shape()
shape.moveTo(-0.5, 0)
shape.lineTo(0.5, 0)
shape.lineTo(0.35, 1.4)
shape.lineTo(-0.35, 1.4)
shape.closePath()

const geo = new THREE.ExtrudeGeometry(shape, {
  depth: 0.4,
  bevelEnabled: true,
  bevelSize: 0.04,
  bevelThickness: 0.06,
  bevelSegments: 2,
  curveSegments: 8
})

适合：楼层平面、路牌、切面 logo、带倒角的家具板件。参数化的点在于轮廓点由函数算出来——比如把楼层的窗洞做成 shape.holes，就能生成带洞的墙板。

② LatheGeometry：绕轴旋转一条剖面

js
const profile = []
for (let i = 0; i <= 12; i++) {
  const t = i / 12
  profile.push(new THREE.Vector2(
    0.35 + Math.sin(t * Math.PI) * 0.5,  // 半径随高度变化
    t * 2.6                              // 高度
  ))
}
const geo = new THREE.LatheGeometry(profile, 32)

适合：花瓶、柱子、灯罩、塔身。剖面点可以是噪声扰动过的，这样每个实例的轮廓都不同——但注意 LatheGeometry 生成后几何体是固定的，要做"每个都不同"得生成多份，或者退化为实例化 + 顶点着色器位移。

挤出的两个坑：倒角参数过大会自交（尤其是细长轮廓），以及 UV 会被拉伸。ExtrudeGeometry 默认用世界坐标生成 UV，斜面和侧壁的贴图密度会不一致；需要精确贴图时，建议自己写 UV 或用三平面映射。

程序化建筑：模块化拼装 ​

一栋楼不是"一个盒子"，而是若干模块叠出来的：

模块几何建议输出
体块 massing缩放的 BoxInstancedMesh
楼层线/腰线细长 Box合并进体块材质
窗格小 Box 或平面统一 InstancedMesh，控制总实例数
屋顶平顶（体块自身）、坡顶（四棱锥）、尖顶按类型各一个 InstancedMesh
附属物（招牌、雨棚、天线）少量独立 Mesh保持独立以便交互

拼装的关键不是"模块多"，而是每个模块只负责一件事，且都能用一个矩阵描述。只要满足这两点，模块就能被批量写入实例缓冲；反之，任何需要"逐对象自定义着色器"的模块都会打断批处理。

随机分布：别让树长成一堆 ​

随手 rand() 撒点，结果一定是"有的地方挤成团，有的地方空一片"——这是聚类（clumping），人眼一眼就看出不自然。三种改进：

  1. 网格抖动（jittered grid）：把区域切成格子，每格放一个点，位置在格内随机偏移。实现最简单，密度均匀，缺点是仍有网格痕迹。
  2. 泊松盘采样（Poisson disk）：任意两点距离不小于 r，同时尽量填满。Bridson 算法用"网格加速 + 活跃点队列"，复杂度 O(n)，是植被、路灯、建筑布点的标准做法。
  3. 分层随机：先按地块分区，再在区内抖动。适合城市这种有街区结构的场景。
js
// 网格抖动：城市地块布点的最小实现
const cell = lotSize
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    const x = (i - (n - 1) / 2) * cell + (rand() - 0.5) * cell * 0.22
    const z = (j - (n - 1) / 2) * cell + (rand() - 0.5) * cell * 0.22
    // 在这里决定放楼、放树还是留空
  }
}

抖动幅度要小于格子尺寸的一半，否则相邻点会越界重叠。城市里这个"重叠"反而是好事——楼距太整齐会像 Excel 表格。

UV 与材质适配：程序化几何最容易被忽略的一环 ​

程序化生成的几何往往没有"美术展好的 UV"，直接贴图会拉伸。三条常见对策：

方案做法适用
按拓扑手写 UV平面网格用 u=i/seg, v=j/seg；圆柱按角度展开地形、坡道、管道
三平面映射 triplanar着色器里按法线权重混合 X/Y/Z 三个方向的投影岩石、建筑、任意硬表面
顶点色 / 程序化 Canvas 贴图用高度、坡度、随机值着色，不依赖 UV地形分层、楼体配色

三平面映射的思路值得记住：对每个片元，取世界坐标分别沿三个轴投影采样三次，再用 abs(normal) 做权重混合。它彻底绕开 UV 接缝，代价是三次采样和权重计算。适合"石块、墙体、悬崖"这类没有明确展开方向的物体。

确定性：同一套参数必须长同一棵树 ​

递归生成里只要有一处用了 Math.random()，整棵树就不可复现。正确做法是把 mulberry32 的实例沿着递归传递，并保证随机调用的顺序固定。顺序为什么重要？因为同一个随机序列，先取角度再取长度，和先取长度再取角度，得到的是两棵不同的树。改动代码时如果不小心调整了取值顺序，旧 seed 就会"变异"。

工程上建议把"生成参数 + 种子"存成一份配置（29.3 会给出 JSON 结构），并给生成器版本号。这样美术报"第 37 号树不对"时，你能精确复现，而不是靠截图猜。

代码示例 ​

对应演示 parametric-tree-lab.html：一棵实时重生成的树，GUI 控制深度、角度、衰减、种子与叶密度，输出方式可在逐枝 Mesh / 合并几何 / InstancedMesh 之间切换，HUD 显示枝数、叶数、三角数与 draw call。

① 显式栈生长：避免递归爆栈，也方便随时中断：

js
const stack = [{
  origin: new THREE.Vector3(0, 0.02, 0),
  dir: new THREE.Vector3(0, 1, 0),
  length: 1.7,
  radius: 0.24,
  depth: 0
}]

while (stack.length) {
  const seg = stack.pop()
  const end = seg.origin.clone().addScaledVector(seg.dir, seg.length)
  branches.push({ a: seg.origin.clone(), b: end, radius: seg.radius })
  if (seg.depth >= maxDepth) continue
  // 每个分叉点压入 2~3 个子枝
}

用显式栈而不是函数递归，好处是深度只受内存限制，且可以在循环里插入"字符数/枝数上限"的熔断。

② 方向抖动：绕水平轴旋转：

js
const az = (i / childCount) * Math.PI * 2 + rand() * 0.9
axis.set(Math.cos(az), 0, Math.sin(az))
quat.setFromAxisAngle(axis, angle * (0.72 + rand() * 0.6))
const dir = seg.dir.clone().applyQuaternion(quat)
dir.y += 0.14
dir.normalize()

azimuth 决定"往哪个方位分叉"，极角决定"分多开"。两者都带随机，树冠才不会像伞骨一样规整。

③ 合并输出：克隆 + 变换 + 一次合并：

js
const branchParts = branches.map((seg) =>
  branchGeo.clone().applyMatrix4(branchMatrix(seg.a, seg.b, seg.radius)))
const mergedBark = mergeGeometries(branchParts, false)
branchParts.forEach((g) => g.dispose())
mesh = new THREE.Mesh(mergedBark, barkMat)

合并前必须保证所有几何体的属性集合一致（都有 position / normal / uv）。mergeGeometries 返回 null 通常就是这个原因，而不是"函数坏了"。

④ 实例输出：矩阵 + 颜色两块缓冲：

js
const bark = new THREE.InstancedMesh(branchGeo, barkMat, branches.length)
branches.forEach((seg, i) => {
  bark.setMatrixAt(i, branchMatrix(seg.a, seg.b, seg.radius))
  bark.setColorAt(i, tint.setHSL(0.07, 0.32, 0.28 + (i % 7) * 0.012))
})
bark.instanceMatrix.needsUpdate = true
if (bark.instanceColor) bark.instanceColor.needsUpdate = true

instanceColor 在第一次 setColorAt 之后才存在，所以 needsUpdate 要判空；这一步漏掉，颜色会一直停在默认白。

⑤ 输出方式切换：只换"怎么用矩阵"，不重算树：

js
generate()                    // 先算出 branches / leaves 数据
if (params.mode === '每枝一 Mesh') buildPerMesh()
else if (params.mode === '合并几何') buildMerged()
else buildInstanced()

这是本篇最重要的结构：数据层与渲染层分离。同一棵树的数据可以换三种画法，参数面板只需要改 mode，不需要重新生长。

常见问题解答 ​

Q1：mergeGeometries 返回 null，控制台没有明显报错？

九成是属性结构不一致。参与合并的几何体必须拥有同一组属性名与相同分量数：有的带 uv、有的不带，有的 position 是 3 分量而另一个是 4 分量，都会失败。修法是合并前统一补齐属性，例如给没有 uv 的几何体补一份全零 uv。另一个原因是索引状态不一致：部分几何体有 index、部分没有，先统一 toNonIndexed() 或都建索引再合并。

Q2：切到 InstancedMesh 后树变"瘦"或法线全错？

非等比缩放（半径、长度、半径）会被写进实例矩阵，GPU 用法线矩阵近似变换法线时，非等比缩放会扭曲方向，枝干的光照就会发暗、发脏。两种修法：① 让圆柱几何体本身按长度归一化，实例矩阵只保留旋转与统一缩放；② 接受近似（枝干很细时肉眼不明显）。合并模式没有这个问题，因为 applyMatrix4 会在 CPU 侧正确变换法线。

Q3：叶片一多就掉帧，是三角形太多吗？

先看 draw call 而不是三角形。逐叶一 Mesh 时，几百片叶子就是几百次提交，CPU 先撑不住；切到合并或实例化通常立刻恢复。如果已经实例化仍掉帧，再查三角形总量与过度绘制：叶片用了 DoubleSide 且互相堆叠，片元会被反复着色。可以减叶片多边形（四棱锥代替球体）、缩小叶片、或用一张程序化叶簇贴图代替几何。

Q4：L-System 深度一调高浏览器就卡死？

字符串是指数增长的：F → F[+F]F[-F]F 每层约 3 倍，深度 8 就是数万字符，深度 12 上百万。三个限制必须同时加：最大深度、最大字符数、最大枝段数。达到任一上限就停止扩展并在 HUD 提示。真正上线的植物系统通常不用纯字符串 L-System，而是"规则 + 预算"：先算枝段预算，再按预算分配每一级的分叉数。

术语解释：

  • L-System：用公理与产生式重写字符串，再由海龟解释成几何的生长语法。
  • 挤出 extrude：把二维轮廓沿第三轴拉伸成体积，可带倒角。
  • 放样 lathe：把一条二维剖面绕轴旋转成回转体。
  • 泊松盘采样 Poisson disk：任意两点间距不小于阈值的均匀随机分布。
  • 三平面映射 triplanar mapping：按法线权重混合三个轴向投影，绕开 UV 接缝。
  • draw call：CPU 向 GPU 提交一次绘制命令，固定开销高，是批量物体的主要瓶颈。

动手小练习 ​

  1. 在 parametric-tree-lab.html 里固定 seed，只把"输出方式"从合并切到逐枝 Mesh，记录 draw call 与三角数的变化，并解释为什么三角形数几乎不变。
  2. 把递归深度从 3 调到 6，记录枝数与叶数的增长倍率，判断它接近线性还是指数；再给生成器加一个"最大枝数 300"的熔断，观察树形是否被截断。
  3. 用 ExtrudeGeometry 做一块带两个窗洞的墙板（shape.holes），再把它与树一起放进场景，对比挤出几何与实例化楼块的 UV 表现。
