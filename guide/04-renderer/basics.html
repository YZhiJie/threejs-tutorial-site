4.1 基础入门：WebGLRenderer 与渲染循环 ​

核心概念讲解 ​

渲染器做了什么 ​

WebGLRenderer 是 Three.js 与浏览器 WebGL 之间的桥梁：编译着色器、上传顶点数据、设置渲染状态、逐帧把场景绘制到 <canvas>。日常你只需要 new 一个并设置好尺寸/像素比，但理解它"每帧做什么"对后续性能优化至关重要。

渲染循环与帧率 ​

浏览器用 requestAnimationFrame（rAF）在每次屏幕刷新前回调，通常 60Hz（每帧约 16.7ms）。Three.js 推荐用封装好的：

js
renderer.setAnimationLoop(() => { /* 每帧执行 */ })

为什么动画必须用 deltaTime ​

  • 错误写法：rotation += 0.02（每帧固定增量）。60fps 时每秒转 1.2 弧度，30fps 时只有 0.6——帧率低动画就慢
  • 正确写法：rotation += speed * delta，其中 delta 是距上一帧的真实秒数。任何帧率下，每秒转动量都是 speed

r186 用 THREE.Timer 取得 delta（旧的 THREE.Clock 自 r183 起弃用）。用法固定为三步：

js
const timer = new THREE.Timer()
timer.connect(document)              // 可选：利用页面可见性 API，切后台时自动避免超大 delta
renderer.setAnimationLoop(() => {
  timer.update()                     // ① 每帧先更新内部计时
  const delta = timer.getDelta()     // ② 再取距上一帧的秒数
  // ③ 所有运动都写成：速度 × delta
})

术语解释：delta time（Δt） 相邻两帧的时间间隔。用它驱动运动叫"帧率无关（frame-rate independent）"，是动画系统的基本纪律。

代码示例 ​

下面并排演示"按帧"与"按时间"两种旋转，并用帧率节流让你直观看到差别：

js
import * as THREE from 'three'
import { OrbitControls } from 'three/addons/controls/OrbitControls.js'
import GUI from 'three/addons/libs/lil-gui.module.min.js'

const scene = new THREE.Scene()
scene.background = new THREE.Color(0x0b0e14)
const camera = new THREE.PerspectiveCamera(50, innerWidth / innerHeight, 0.1, 100)
camera.position.set(0, 1.6, 5)
const renderer = new THREE.WebGLRenderer({ antialias: true })
renderer.setSize(innerWidth, innerHeight)
renderer.setPixelRatio(Math.min(devicePixelRatio, 2))
document.getElementById('app').appendChild(renderer.domElement)
const controls = new OrbitControls(camera, renderer.domElement)
controls.enableDamping = true

scene.add(new THREE.AmbientLight(0xffffff, 0.6))
const d = new THREE.DirectionalLight(0xffffff, 1.5)
d.position.set(3, 5, 4)
scene.add(d)
scene.add(new THREE.GridHelper(10, 10, 0x334155, 0x1e293b))

const frameCube = new THREE.Mesh(
  new THREE.BoxGeometry(1.2, 1.2, 1.2),
  new THREE.MeshStandardMaterial({ color: 0x60a5fa })
)
frameCube.position.set(-1.6, 0.8, 0)
const timeCube = new THREE.Mesh(
  new THREE.BoxGeometry(1.2, 1.2, 1.2),
  new THREE.MeshStandardMaterial({ color: 0xfbbf24 })
)
timeCube.position.set(1.6, 0.8, 0)
scene.add(frameCube, timeCube)

const params = { targetFPS: 60 }
new GUI({ title: '模拟帧率' }).add(params, 'targetFPS', [60, 30, 20, 15, 8]).name('限制帧率 (fps)')

// 帧率节流：累加真实时间，不到 1/targetFPS 就跳过本次更新渲染
const timer = new THREE.Timer()
timer.connect(document) // r183 起 Clock 已弃用，改用 Timer；connect 可自动处理切后台
let acc = 0

renderer.setAnimationLoop(() => {
  timer.update()                       // 无论是否提前 return，每帧都要 update
  const realDelta = timer.getDelta()
  acc += realDelta
  const frameInterval = 1 / params.targetFPS
  if (acc < frameInterval) return      // 没到逻辑帧时间点，跳过
  const step = acc
  acc = 0

  // ❌ 与帧率绑定：每帧固定 0.02
  frameCube.rotation.x += 0.02
  frameCube.rotation.y += 0.02
  // ✅ 与时间绑定：角速度(rad/s) × 经过秒数
  timeCube.rotation.x += 1.2 * step
  timeCube.rotation.y += 1.2 * step

  controls.update()
  renderer.render(scene, camera)
})

常见问题解答 ​

Q1：setAnimationLoop 和 requestAnimationFrame 选哪个？

优先 setAnimationLoop：它封装了 rAF、页面隐藏暂停、WebGL 上下文丢失恢复。需要在非浏览器环境或精细控制调度时再手写 rAF。

Q2：timer.getDelta() 和 timer.getElapsed() 区别？

两者都在 timer.update() 之后读取：getDelta() 返回距上一帧的间隔（做运动），getElapsed() 返回计时器启动以来的累计秒数（做"时间曲线"，如 sin(t) 起伏）。注意 r186 的 Timer 已没有 elapsedTime 属性/getElapsedTime() 方法，统一用 getElapsed()。

Q3：标签页切走再回来，物体为什么"瞬移"了？

rAF 在后台标签页被暂停，回来的第一帧 delta 可能很大（几秒），物体一下前进一大截。timer.connect(document) 会借助页面可见性 API 自动规避；再保险一点可用 const dt = Math.min(timer.getDelta(), 0.05) 把单帧步长钳制在 50ms 以内。

动手小练习 ​

  1. 给两个立方体加"上下弹跳"，分别用错误/正确两种写法，在 15fps 下对比。
  2. 实现空格键暂停：暂停时不再累加运动，但仍渲染一帧静态画面。
  3. 加上单帧步长钳制（clamp 到 0.05s），切后台 10 秒再回来验证不再瞬移。
