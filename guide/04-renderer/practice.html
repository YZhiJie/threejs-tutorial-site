4.3 实战案例：帧率自适应渲染 ​

核心概念讲解 ​

真实用户设备千差万别：独显桌面轻松 144fps，低端手机可能只有 20fps。固定画质要么高配浪费、要么低配卡死。自适应渲染的思路是运行时持续监测 FPS，自动在"画质"和"流畅度"之间换挡。

换挡策略（带迟滞，避免抖动） ​

  • 连续 2 个采样窗口 FPS < 45：降低一档 pixelRatio（2 → 1.5 → 1 → 0.75）
  • 连续 6 个采样窗口（约 3 秒）FPS ≥ 57：升回一档
  • 45~57：保持不动

关键设计：升档要比降档"谨慎"得多（需要连续高帧更久），否则画质会在临界点来回横跳，体验比稳定低画质更差。这叫迟滞（hysteresis）。

为什么用 InstancedMesh 压测 ​

要测试自适应逻辑，得能快速加大 GPU 负载。用 InstancedMesh 一次提交成千上万个立方体却只有 1 个 draw call，负载集中在顶点/像素处理上，正好压测画质调整的收益。

术语解释：InstancedMesh（实例化网格） 用同一个几何体绘制大量实例，每个实例有自己的矩阵（位置/旋转/缩放）和颜色，draw call 不随实例数增长。

代码示例 ​

js
import * as THREE from 'three'
import { OrbitControls } from 'three/addons/controls/OrbitControls.js'
import GUI from 'three/addons/libs/lil-gui.module.min.js'

const scene = new THREE.Scene()
scene.background = new THREE.Color(0x0b0e14)
const camera = new THREE.PerspectiveCamera(50, innerWidth / innerHeight, 0.1, 100)
camera.position.set(0, 6, 14)
const renderer = new THREE.WebGLRenderer({ antialias: true })
renderer.setSize(innerWidth, innerHeight)
renderer.setPixelRatio(Math.min(devicePixelRatio, 2))
document.getElementById('app').appendChild(renderer.domElement)
const controls = new OrbitControls(camera, renderer.domElement)
controls.enableDamping = true

scene.add(new THREE.HemisphereLight(0xbfd9ff, 0x202020, 0.9))
const dir = new THREE.DirectionalLight(0xffffff, 2)
dir.position.set(5, 10, 6)
scene.add(dir)

const geometry = new THREE.BoxGeometry(0.5, 0.5, 0.5)
// 实例颜色通过 setColorAt 写入 instanceColor，不需要材质开 vertexColors
const material = new THREE.MeshStandardMaterial({ roughness: 0.5, metalness: 0.1 })

let mesh = null
const dummy = new THREE.Object3D()   // InstancedMesh 设矩阵的"临时容器"
const color = new THREE.Color()

function buildCubes(count) {
  if (mesh) { scene.remove(mesh); mesh.dispose() }
  mesh = new THREE.InstancedMesh(geometry, material, count)
  const side = Math.ceil(Math.cbrt(count))   // 立方根，尽量排成接近立方体的方阵
  let i = 0
  for (let x = 0; x < side && i < count; x++)
    for (let y = 0; y < side && i < count; y++)
      for (let z = 0; z < side && i < count; z++) {
        dummy.position.set(x - side / 2, y + 0.4, z - side / 2)
        dummy.rotation.set(Math.random(), Math.random(), 0)
        dummy.updateMatrix()                          // Object3D 参数 → 矩阵
        mesh.setMatrixAt(i, dummy.matrix)
        mesh.setColorAt(i, color.setHSL(i / count, 0.7, 0.55))
        i++
      }
  scene.add(mesh)
}
buildCubes(800)

const params = { count: 800, autoAdapt: true }
const gui = new GUI({ title: '性能调节' })
gui.add(params, 'count', [200, 800, 2000, 5000, 10000]).name('实例数量').onChange(buildCubes)
gui.add(params, 'autoAdapt').name('自动调节画质')
gui.add({ reset() {
  levelIndex = initialLevel
  renderer.setPixelRatio(levels[levelIndex])
  lowStreak = highStreak = 0
}}, 'reset').name('恢复最高画质')

/* ---------- 自适应状态机 ---------- */
const levels = [2, 1.5, 1, 0.75]         // 从高到低的像素比档位
let levelIndex = levels.indexOf(Math.min(devicePixelRatio, 2))
if (levelIndex < 0) levelIndex = 2
const initialLevel = levelIndex
let lowStreak = 0
let highStreak = 0

let frames = 0
let statTime = performance.now()
const clock = new THREE.Timer()
clock.connect(document) // r183 起 Clock 已弃用，改用 Timer
renderer.setAnimationLoop(() => {
  clock.update() // 每帧先 update，再读取
  const dt = clock.getDelta()
  if (mesh) mesh.rotation.y += dt * 0.15
  controls.update()
  renderer.render(scene, camera)

  frames++
  const now = performance.now()
  if (now - statTime >= 500) {                 // 0.5s 采样窗口
    const fps = Math.round((frames * 1000) / (now - statTime))
    frames = 0
    statTime = now

    if (params.autoAdapt) {
      if (fps < 45) {                          // 降档：连续 2 次低帧
        lowStreak++; highStreak = 0
        if (lowStreak >= 2 && levelIndex < levels.length - 1) {
          levelIndex++
          renderer.setPixelRatio(levels[levelIndex])
          lowStreak = 0
        }
      } else if (fps >= 57) {                  // 升档：连续 6 次高帧（迟滞）
        highStreak++; lowStreak = 0
        if (highStreak >= 6 && levelIndex > 0) {
          levelIndex--
          renderer.setPixelRatio(levels[levelIndex])
          highStreak = 0
        }
      } else {
        lowStreak = highStreak = 0
      }
    }
    console.log('FPS', fps, 'PR', levels[levelIndex],
      'calls', renderer.info.render.calls)
  }
})

常见问题解答 ​

Q1：为什么不用 requestIdleCallback 或直接读平均帧率？

平均帧率对"瞬时掉帧"不敏感，等平均值掉下来时用户已经卡了几秒。用固定窗口计数 + 连续触发的状态机，反应快且可控；迟滞阈值则防止在边界抖动。

Q2：降 pixelRatio 具体省了什么？

渲染缓冲区像素数 = CSS 尺寸 × pixelRatio²。pixelRatio 从 2 降到 1，片元着色器执行量降到约 1/4，这对"像素填充受限"（大面积材质、后处理、高分辨率）的场景收益最大。

Q3：还有哪些可以自动降的画质项？

按性价比排序：pixelRatio → 关闭阴影/降 shadow.mapSize → 降低像素密度（DPR 1）→ 几何体细分（detailed level）→ 关闭后处理抗锯齿 → 减少 draw call。可把这些都做成档位统一调度。

动手小练习 ​

  1. 把调节目标从 pixelRatio 换成 shadow.mapSize（4096/1024/512 三档），注意切换时要 dispose 旧 shadow.map。
  2. 在 HUD 上同时显示当前档位和"升/降档事件"，观察迟滞是否有效阻止抖动。
  3. 加入"启动性能探测"：加载后先渲染 2 秒高负载测试，直接选定初始档位。
