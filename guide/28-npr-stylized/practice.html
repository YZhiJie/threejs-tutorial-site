28.3 实战案例：水墨与漫画风格渲染管线 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑫⑬ 再学习本篇。

核心概念讲解 ​

接桥：⑬ 的 Bloom 是"越亮越糊"，水墨恰恰相反 ​

在 ⑬ 后处理 里，我们用 Bloom 给产品渲染做辉光：越亮的区域越会向外晕开，画面因此显得"发光、通透"。那套逻辑建立在"光是加法"的前提上——亮部向外扩散，暗部保持安静。

水墨的逻辑几乎完全相反：墨是减法。水在纸上扩散时，浓墨会向四周晕开但越远越淡，形成的是"边缘渗化"而不是"辉光叠加"；纸的纤维会把墨吸住，留下颗粒和飞白。所以水墨风格的后处理不能用 Bloom 那套"亮度阈值 + 高斯模糊叠加"，而要用去色 + 墨色分层 + 噪声阈值 + 纸张纹理的组合：先把画面压成有限的几档墨色，再用噪声把档位边界"啃"出毛边，最后叠一层纸纹。

这一篇把 28.1 的描边、28.2 的色阶，和 ⑬ 的 Pass 链组装成一条完整的 NPR 管线，并做成可切换的"写实 / 卡通 / 水墨"三种渲染模式。

一条 NPR 管线的标准顺序 ​

顺序不是随便排的，每一步的输出都是下一步的输入。推荐顺序与理由如下：

顺序步骤做什么为什么在这里成本
1几何渲染正常渲染场景，输出颜色后面所有处理都以它为底1 次场景绘制
2辅助缓冲（可选）法线 + 深度预渲染给描边与深度分层提供几何信息+1 次场景绘制
3描边外壳或屏幕空间边缘检测线要压在色块之上，不能被后续量化抹掉视方案而定
4去色与色阶亮度分层、限制色相墨色只关心明度，先砍掉颜色噪声1 次全屏采样
5噪声阈值用噪声扰动档位边界让硬边变成"手绘毛边"已在同一次 Pass 内
6纸张 / 笔触叠纸纹、飞白、颗粒最后上材质感，避免被前面的阈值吃掉已在同一次 Pass 内
7输出色调映射 + sRGB 编码统一出口，只做一次1 次全屏绘制

两个容易排错的地方：

  • 不要把描边放在量化之后。如果先做色阶，画面里会出现大量"色块边界"，边缘检测会把它们全部误判成线，结果满屏都是墨。正确做法是在颜色还连续时找边，再把线压上去。
  • 不要在每个 Pass 里各做一次色调映射。整条链只允许 OutputPass 负责压缩与编码，其余 Pass 都在线性空间工作。

水墨的三个关键配方 ​

配方一：墨色分层。把画面亮度量化成 3 档，但不用 floor 那种整齐的切法，而是用带噪声的 smoothstep 逐档过渡：

glsl
float grain = (noise(vUv * 7.0 + uTime * 0.12) - 0.5) * 0.16;
float q = l0 + grain;
float lv1 = smoothstep(0.30, 0.36, q);
float lv2 = smoothstep(0.58, 0.64, q);
float tone = 0.20 + 0.34 * lv1 + 0.36 * lv2;

这里 smoothstep 的区间很窄（0.06），所以视觉上仍是硬边；噪声让这条硬边在空间上抖动，看起来像毛笔在纸上留下的不规则边界。tone 只有三档：0.20 / 0.54 / 0.90，对应的就是"浓墨、淡墨、留白"。

配方二：噪声阈值而非模糊。水墨的边缘渗化不能靠高斯模糊，因为模糊会把所有细节一起糊掉。正确的做法是只在阈值附近做文章：用噪声扰动采样位置或阈值，让边界像素随机地归到相邻档，从而产生"毛边"。这也是"阈值噪声"这个词的来源——噪声不是在画面上叠加，而是在决定"这个像素算哪一档"。

配方三：纸张纹理。纸纹有两个作用：一是提供低频的明度起伏，让大面积留白不显得死板；二是提供高频的纤维颗粒，让墨色有"附着感"。一张 256×256 的程序化贴图就够用：

js
ctx.fillStyle = '#f3ecdb'
ctx.fillRect(0, 0, 256, 256)
for (let i = 0; i < 1100; i++) {
  ctx.strokeStyle = `rgba(92, 82, 62, ${0.02 + Math.random() * 0.06})`
  ctx.beginPath()
  ctx.moveTo(x, y)
  ctx.lineTo(x + (Math.random() - 0.5) * 46, y + (Math.random() - 0.5) * 7)
  ctx.stroke()
}

用 CanvasTexture 生成，不依赖任何外部图片，wrapS/wrapT 设为 RepeatWrapping，采样时配合 uPaperAmp 控制强度。注意它是数据纹理，不要设成 sRGB。

笔触噪声与 boiling line ​

"Boiling line" 是手绘动画里的一个经典现象：线条每帧都会轻微抖动，因为原画是一张张手画的。数字渲染想复刻这种"呼吸感"，会让线条的采样位置或阈值随时间缓慢变化。

关键在于抖动必须是连续、缓慢、有界的：

glsl
float boil = (noise(vUv * 26.0 + vec2(uTime * 1.7, uTime * 2.1)) - 0.5) * uBoil;
vec2 uv = vUv + vec2(boil, -boil) * texel * 3.0;

用 uTime 连续演进噪声坐标，而不是每帧 Math.random()。后者会让整幅画高频闪烁，看起来像信号干扰；前者才是"手在抖"的感觉。抖动幅度以 1~3 个像素为宜，超过 3 像素会让文字和细节全部失去稳定感。

纸张的三种尺度 ​

纸纹不是"一张贴图拍上去"就完事，它在画面里其实同时扮演三种尺度，必须分开调：

  • 低频（几十像素）：纸面的起伏与阴影，决定留白是否"透气"。这一层用低频噪声或大尺度的明度变化，幅度控制在 ±5% 以内；太大就像脏了的墙。
  • 中频（三到八像素）：纤维与纸浆的纹理，是"纸感"的主要来源。演示里的横向短线就是这一层，靠 CanvasTexture 里一条条细线实现。
  • 高频（一像素）：颗粒与飞白，决定墨色是否"附着"。用高频噪声配很低的幅度（0.03~0.06），只在暗部看得见，亮部几乎不可见。

三层如果混在同一张 256×256 贴图里，缩放时会出现明显的重复图案；更好的做法是低频用一张大贴图、中高频用可平铺的小贴图，各自设置不同的 repeat。另外，纸纹应该跟随 UV 而不是屏幕像素，否则窗口一拉伸，纸的纤维就被拉长，质感立刻失真。

上线前的检查清单 ​

把 NPR 管线接进项目之前，建议按下面几条逐项过一遍，能省掉大部分返工：

  1. 模式切换是否改齐了五件事：材质、色调映射、背景、雾、后处理开关。少一个就会出现"水墨模式里天空还是黑的"。
  2. 线宽是否乘了设备像素比：桌面调好的 3 px，到手机上可能变成 1.5 px。
  3. 噪声是否连续：搜索代码里有没有 Math.random() 直接参与每帧渲染。
  4. 色调映射是否只做了一次：确认画面上没有"越调越灰"的双重压缩。
  5. 远处是否做了淡出：雾、mip、距离阈值任选其一，避免远景线变成噪点。
  6. 移动端 fill rate 是否够用：水墨 Pass 是全屏多采样，先在中端机上量一次，再决定要不要把纸纹采样降到每两像素一次。

这六条里最容易被忽略的是第 3 条和第 4 条，因为它们不会在静止截图里暴露，只有在播放动画或切换模式时才现形。做 NPR 的验收，一定要看动图，不能只看单帧。

风格化下的抗锯齿与稳定性 ​

NPR 对锯齿的敏感度比写实渲染更高，因为画面里全是硬边和纯色块，任何锯齿都会非常显眼：

  • 几何边缘：主画面尽量开 MSAA；如果走了后处理链，则用 SMAAPass 或 FXAA 兜底。
  • 屏幕空间描边：边缘检测基于单采样的法线/深度缓冲，MSAA 救不了它。解决办法是搜索半径至少 2 像素、阈值留一点余量，并在远处做淡出。
  • 阈值噪声：噪声频率过高会在缩放时产生摩尔纹，建议把噪声坐标乘上分辨率相关的尺度，或按 mip 级别降低幅度。
  • boiling line：幅度过大、频率过快都会造成"闪烁"。固定噪声种子、限制帧间变化量，是工程上最有效的两条纪律。

把风格做成可切换的"渲染模式" ​

比起"做一个水墨项目"，更常见的需求是同一套资产支持多种风格：写实用于展示，卡通用于营销，水墨用于活动页。工程上的做法是把差异收敛成三份材质与三个开关：

js
const MODES = {
  realistic: { toneMapping: THREE.ACESFilmicToneMapping, outline: false, inkPass: false },
  toon:      { toneMapping: THREE.NoToneMapping,        outline: true,  inkPass: false },
  ink:       { toneMapping: THREE.NoToneMapping,        outline: false, inkPass: true  }
}

切换时同步改五件事：mesh.material、renderer.toneMapping、scene.background、scene.fog、inkPass.enabled。少改任何一项，都会出现"水墨模式里还挂着写实的暖色雾"这类违和。材质本身可以在初始化时一次性建好三份，切换只是换引用，不会触发编译卡顿。

成本预算：每个模式多花多少 ​

模式额外 Pass额外 draw call主要开销
写实00PBR 光照、阴影、环境贴图
卡通0每个描边物体 +1外壳绘制、色阶采样
水墨1（InkPass）0全屏去色 + 噪声 + 纸纹采样

演示里会实时显示 Pass 数与 draw call，切换模式时能直接看到"水墨多一次全屏绘制"这件事。注意，后处理是全屏开销，与场景复杂度无关；而描边外壳的成本与物体数量成正比。所以大场景优先考虑后处理描边，小场景优先考虑外壳。

代码示例 ​

对应演示 ink-wash-lab.html：山石、树、雾，三种模式一键切换，水墨模式挂载 InkPass，面板可调墨线浓度、阈值、抖动与纸纹强度。

① 每个物体准备三份材质，切换只换引用：

js
const record = {
  mesh,
  real: new THREE.MeshStandardMaterial({ color: realColor, roughness: 0.92 }),
  toon: makeToonMat(toonColor),
  ink: makeToonMat(inkColor),
  shell: null
}
proxies.push(record)

② 模式切换：五件事一起改：

js
function applyMode() {
  const m = params.mode
  proxies.forEach((p) => {
    p.mesh.material = m === '写实' ? p.real : m === '卡通' ? p.toon : p.ink
    if (p.shell) p.shell.visible = (m === '卡通')
  })

  const inkMode = m === '水墨'
  scene.background.set(inkMode ? PAPER : DARK)
  scene.fog.color.set(inkMode ? PAPER : DARK)
  globalU.uRamp.value = inkMode ? rampInk : rampToon
  inkPass.enabled = inkMode
  renderer.toneMapping = m === '写实' ? THREE.ACESFilmicToneMapping : THREE.NoToneMapping
}

renderer.toneMapping 改动会影响 OutputPass 内部的宏定义，Three.js 会自动重建；但标准材质需要 needsUpdate 才会重新编译，所以切换后遍历一次 realMaterials 置脏是必要的保险。

③ InkPass：去色 + 边缘 + 分层 + 纸纹，一次全屏做完：

glsl
float l0 = luma(texture2D(tDiffuse, uv).rgb);
float lx = luma(texture2D(tDiffuse, uv + vec2(texel.x * 1.6, 0.0)).rgb)
         - luma(texture2D(tDiffuse, uv - vec2(texel.x * 1.6, 0.0)).rgb);
float ly = luma(texture2D(tDiffuse, uv + vec2(0.0, texel.y * 1.6)).rgb)
         - luma(texture2D(tDiffuse, uv - vec2(0.0, texel.y * 1.6)).rgb);
float grad = length(vec2(lx, ly)) * 2.0;
float line = smoothstep(uEdge, uEdge + 0.12, grad);

把边缘、分层、纸纹合并到同一个 Pass，是控制成本的关键：如果拆成三个 Pass，就多两次全屏采样，移动端会直接掉帧。

④ 把纸纹和笔触叠在最后：

glsl
vec3 paper = texture2D(uPaper, vUv).rgb;
float paperMix = mix(1.0, paper.r, uPaperAmp);
float brush = (noise(vUv * 170.0) - 0.5) * 0.055;

vec3 col = vec3(tone) * paperMix + brush;
col = mix(col, vec3(0.045, 0.05, 0.062), line * 0.92 * uInk);

顺序是"先上纸、再加墨线"，墨线最后压在最上层，保证线条不会被纸纹的明度起伏冲淡。brush 是高频噪声，幅度只有 0.055，用来模拟纸张上的颗粒，不能太大。

⑤ 成本看板：Pass 数、draw call、帧时间：

js
const passes = composer.passes.filter((p) => p.enabled).length
frameMs = frameMs * 0.88 + Math.min(now - prevNow, 80) * 0.12
stat.textContent = `模式：${params.mode} · Pass：${passes} · Draw calls：${calls} · ${frameMs.toFixed(1)} ms`

帧时间用指数滑动平均，避免数字每帧乱跳；renderer.info.reset() 每帧开头调用一次，autoReset = false，这样跨多个 Pass 的绘制次数才能被正确累加。

常见问题解答 ​

Q1：风格化之后模型边缘一直闪烁、噪点也在跳，是什么原因？

按来源分三类排查：① 屏幕空间描边：边缘检测用的是单采样缓冲，线宽只有一像素时，相机轻微移动就会让线在相邻像素间跳动。修法是加粗搜索半径（≥2 像素）、加阈值余量、远处淡出，并配合 SMAA。② 逐帧随机噪声：如果噪声用 Math.random() 每帧重新生成，整幅画会高频闪烁。必须用连续函数（如 noise(uv + time * speed)），并限制时间项的速率。③ boiling line 抖动过大：把 uBoil 从 1.5 降到 0.3~0.6，抖动像素控制在 1~3 个。④ 深度精度不足也会让轮廓抖动，收紧 near/far 通常立刻见效。

Q2：为什么我的水墨风看起来像"黑白卡通"，没有墨的晕染感？

因为只做了去色和阈值，没做"渗化"。三个补充手段：① 在边缘检测后对线做一次极小的方向性模糊（沿法线方向的 3 像素模糊），模拟墨在纸上扩散；② 在暗部边缘用噪声做"毛边"，让浓墨与淡墨的交界不规则；③ 叠一层低频纸纹（不是高频颗粒），让大面积留白有起伏。注意不要把 Bloom 加进来——Bloom 会让暗部发光，正好与水墨的"墨是减法"相反，画面会立刻变成霓虹风。

Q3：三种模式切换时卡一下，能避免吗？

卡顿来自 shader 重编译。优化顺序：① 三份材质在初始化时就全部创建好（makeToonMat 提前调用），切换只换引用；② 避免在切换时修改 onBeforeCompile 或重新赋值 material.onBeforeCompile，那会强制重新编译；③ renderer.toneMapping 的变化会让 OutputPass 重建宏定义，但只有一次，可接受；④ 如果标准材质在切换后才第一次被渲染，先让它渲染一帧"预热"（可以先放到屏幕外或极小的视口里画一次）；⑤ 用 WebGLRenderer.compileAsync(scene, camera) 在加载阶段预编译整条管线。

Q4：水墨模式里，线宽和纸张颗粒应该按什么单位调？

全部按"屏幕像素"调，而不是世界单位或 UV 单位。线宽、噪声搜索半径、boiling 抖动都以 uResolution 为基准换算：texel = 1.0 / uResolution，再乘像素数。这样在高分屏（devicePixelRatio = 2）和不同窗口尺寸下，观感保持一致。纸张颗粒则要反过来——它应该跟随 UV 而不是像素，否则窗口越大颗粒越密，纸纹会变成噪点。判断标准很简单：与物体结构相关的量用屏幕空间，与材质质感相关的量用 UV 空间。

术语解释 ​

  • NPR（Non-Photorealistic Rendering）：非真实感渲染，目标不是还原光线，而是模拟绘画、漫画、版画等视觉语言。
  • boiling line：手绘动画中线条逐帧轻微抖动的现象，数字管线里用连续噪声复刻。
  • 墨色分层：把亮度量化成有限的几档（浓墨 / 淡墨 / 留白），是水墨风格的基本结构。
  • 阈值噪声：用噪声扰动分类阈值，让硬边产生毛边，而不是在画面上叠噪声。
  • 飞白：笔触快速划过纸面时留下的断续空白，常用高频噪声加亮度抬升模拟。
  • 预渲染 prepass：为后处理服务的额外场景渲染，产出法线/深度等辅助信息。

动手小练习 ​

  1. 打开 ink-wash-lab.html，把"墨线阈值"从 0.09 调到 0.25，观察哪些轮廓线先消失；再关掉雾（把 far 调到 200），看远景的线是否回来，并解释雾为什么会"吃掉"深度差。
  2. 把"线条抖动 boil"从 0 调到 1.6，分别截取连续三帧对比，判断哪个数值开始让人觉得"闪"。记录你认为的上限，并说明它与屏幕刷新率的关系。
  3. 在 applyMode 里增加第四种模式"黑白线稿"：去掉所有色阶、只保留 InkPass 的边缘线，并复用 uEdge 作为唯一参数。思考：这条管线与 28.1 的后处理描边有什么共同点？
