28.1 基础入门：描边（Outline）的四种做法 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑫⑬ 再学习本篇。

核心概念讲解 ​

接桥：12.1 的"发光外壳"其实已经是描边 ​

在 ⑫ 着色器 里，我们做过一个全息投影效果：片元里用 1.0 - dot(N, V) 算出视线与法线夹角，夹角越大越亮，于是物体边缘浮起一圈发光轮廓。当时我们把它当成"科技感光晕"，它其实就是描边的一种——菲涅尔描边。

描边（Outline）在非真实感渲染（NPR）里不是装饰，而是"读图说明书"。写实渲染靠光影、遮挡、景深让物体从背景里分离；一旦把光照压平成色块，物体与背景、物体与物体之间就只剩颜色差异，边界会糊在一起。描边就是在这些边界上补一条线，告诉观众"这里是外轮廓，这里是一个独立的物件"。

本篇把四种最常用的描边做法摆在同一张桌子上：反向外壳、后处理边缘检测、菲涅尔视角描边、纹理描边。它们各有各的"物理来源"，也各有各的代价，先看清取舍，再谈风格。

描边描的是什么"边" ​

动手之前先分清两种边，这决定了你该选哪种技术：

边的类型含义例子
外轮廓 silhouette物体与背景在屏幕上的分界球体最外圈、角色剪影
内部线 interior line同一物体内部因深度或法线突变产生的折线布料褶皱、鼻梁与脸颊的交界、衣领

外轮廓是所有描边方案都能做的；内部线只有"能读到几何信息"的方案（后处理、纹理）才做得到。很多项目一开始只用反向外壳，做到角色特写时才发现脸上没有结构线，只好补一套纹理描边或换后处理，这就是没提前区分两类边导致的返工。

做法一：反向外壳 BackSide Shell ​

最古老也最稳的做法：把同一个模型再画一遍，只画背面，并向法线方向外扩一点。正面模型正常渲染，背面模型被推到轮廓外侧，于是屏幕边缘出现一圈"外壳"的颜色。

glsl
// vertex shader of the shell
uniform float uWidth;
uniform vec2 uResolution;

void main() {
  vec3 nView = normalize(normalMatrix * normal);
  vec4 clip = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
  clip.xy += nView.xy * uWidth * 2.0 / uResolution * clip.w;
  gl_Position = clip;
}

这套写法有三个要点：

  1. 只画背面：material.side = THREE.BackSide。外壳被外扩后，正面视角看到的其实是被"推"到物体外面的背面三角形，它围成一圈。
  2. 在裁剪空间外扩，而不是在物体空间：直接写 position += normal * width 会得到一个"世界单位厚度"，透视投影下近处粗、远处细。演示里用的是屏幕空间公式，clip.w 负责把像素宽度还原到透视刻度上，于是无论远近，线宽都稳定在同样的像素数。
  3. 法线质量决定描边质量：如果模型是硬边（法线被拆开、面与面之间不共享顶点），外扩方向会分叉，转角处出现断口或尖刺。想线条干净，几何要么是平滑法线，要么用 mergeVertices 补一遍。

反向外壳的优点是非常直接：一次额外绘制，不需要任何后处理，不挑渲染管线，移动端也能用。它的短板同样明确：

  • 只能描外轮廓，看不到内部线；
  • 凹陷结构（例如腋下、指缝）可能被外壳糊住；
  • 线宽是"整体统一"的，无法局部加粗；
  • 每一个要描边的物体都多一次 draw call，物体多时成本线性上涨。

做法二：后处理边缘检测 Depth / Normal Sobel ​

如果项目已经有后处理链，把描边放进 Pass 里是最"顺"的路线。核心是额外渲染一张只包含法线和深度的图，然后对这张图做 Sobel 算子：

  • 深度不连续 → 前后景分界，对应外轮廓；
  • 法线不连续 → 表面朝向突变，对应内部结构线；
  • 两者取较大值，得到完整的线稿。

深度缓冲里存的不是线性距离，而是经过投影压缩的值。做边缘检测前要先换算：

glsl
float linearDepth(float d) {
  float n = 0.1;
  float f = 100.0;
  return n * f / (f - d * (f - n));
}

之后用中心像素与上下左右四个邻居做二阶差分：

glsl
float depthEdge = (abs(zl - zr) + abs(zu - zd)) / max(z0, 0.0001);
depthEdge = smoothstep(uDepthSens, uDepthSens * 3.5, depthEdge);

vec3 n0 = normalize(texture2D(tNormal, vUv).xyz * 2.0 - 1.0);
vec3 nl = normalize(texture2D(tNormal, vUv - vec2(texel.x, 0.0)).xyz * 2.0 - 1.0);
float nDiff = 1.0 - dot(n0, nl);

这种做法和 ⑬ 后处理 里讲过的 Pass 链完全兼容：RenderPass → EdgePass → OutputPass，边缘的浓淡、颜色、粗细都能在 shader 里当参数暴露给美术。代价是多一次全场景预渲染 + 一至两次全屏绘制，并且在跟随后处理分辨率时容易出现"细线闪烁"：一像素宽的线在缩放时会时有时无，需要更粗的搜索半径或加一点模糊来稳定。

做法三：菲涅尔 / 视角描边 Fresnel Rim ​

这是 ⑫ 着色器 那一篇里已经出现的公式：

glsl
float fres = pow(1.0 - clamp(dot(N, V), 0.0, 1.0), 3.0);
col += rimColor * fres * strength;

N 是表面法线，V 是指向相机的单位向量。正对镜头的面 dot(N, V) ≈ 1，边缘的掠射面 dot(N, V) ≈ 0，于是只有轮廓附近被加亮。它没有额外 pass、没有额外 draw call，一行代码就能让物体从背景里跳出来。

但要注意它的本质：菲涅尔描边是"用亮度差模拟轮廓"，不是真的画了一条线。因此：

  • 线宽会随视角变化，镜头正对时最粗、侧看时变细甚至消失；
  • 只能做外轮廓，做不了内部线；
  • 在深色背景上效果最好，在浅色背景上亮边会被吞掉；
  • 描边颜色必须与主体色有明度差，否则只是"更亮的边缘"，起不到分隔作用。

它最适合"补一层气氛"而不是作为主描边方案。演示里把它单独列出来，是为了让你看清它和反向外壳的差别：外壳是几何的，菲涅尔是着色的。

做法四：纹理描边 Normal-map + UV 外扩 ​

当项目的美术资源里已经带了法线贴图，可以换一个思路：在 UV 空间里找边。做法是在片元着色器里围绕当前 UV 采样四次法线贴图，比较中心法线与邻居法线的差异，差异大的地方画线：

glsl
vec3 nA = texture2D(uNormalMap, uv + vec2(uTexel.x, 0.0)).xyz * 2.0 - 1.0;
vec3 nB = texture2D(uNormalMap, uv - vec2(uTexel.x, 0.0)).xyz * 2.0 - 1.0;
vec3 nC = texture2D(uNormalMap, uv + vec2(0.0, uTexel.y)).xyz * 2.0 - 1.0;
vec3 nD = texture2D(uNormalMap, uv - vec2(0.0, uTexel.y)).xyz * 2.0 - 1.0;
float diff = max(max(distance(nA, nB), distance(nC, nD)), distance(n0, nA));
float line = smoothstep(uTexEdge, uTexEdge + 0.07, diff);

它的价值在于能画出内部结构线：衣领、褶皱、鼻梁、甲片接缝，只要法线贴图在这些位置有突变的"台阶"，采样就会把它们识别成线。它不增加 draw call，也不增加 pass，成本只是每像素多四次纹理采样。

局限也很清楚：

  • 这条线是"贴"在表面的，描不出真正的物体外轮廓，所以通常要和反向外壳搭配使用；
  • 依赖 UV：UV 接缝、镜像 UV 都会产生假线；
  • 依赖法线贴图的精度与压缩方式，贴图被压得太狠，线会断续；
  • 屏幕上的线宽会随距离缩小，远处容易闪烁，需要按 mip 级别或距离做淡出。

四种做法对比 ​

做法质量特点成本受分辨率影响支持内部线条适用场景
反向外壳轮廓干净、线宽可控，凹陷处易出错每物体 +1 draw call否（按像素设定即可稳定）否角色、道具、低多边形场景
后处理边缘内外线都有，可做全屏统一风格预渲染 + 1~2 个全屏 Pass是（细线在缩放时闪烁）是已有后处理链、画面统一的动画风
菲涅尔描边只在轮廓发亮，随视角变化零额外绘制否否补气氛、深色背景的发光轮廓
纹理描边内部细节线丰富，外轮廓弱每像素 +4 次采样是（远处变细）是有法线贴图资产、布料/机械结构

一条实用结论：外轮廓靠反向外壳，内部线靠纹理或后处理。前者便宜稳定，后者信息更全。项目里常见的组合是"外壳 + 法线内线"，或者"后处理统一出线 + 局部菲涅尔补光"。

组合建议：一条线往往不够用 ​

真实项目里很少从头到尾只用一种描边。更常见的分层策略是：

  • 主角与前景：反向外壳负责硬轮廓，保证角色在任何背景上都"立得住"；再叠一层纹理描边补衣领、褶皱、机械接缝这些内部结构。两套线用同一个颜色和相近的粗细，视觉上才是"一支笔"。
  • 中景道具：如果数量多、形状杂，逐物体挂外壳的 draw call 会迅速膨胀，这时改用后处理边缘一次出完所有线，成本与物体数量脱钩。
  • 远景与背景：干脆不描边。让雾、色阶和留白把它们推远，比给每座山都勾一条黑边更符合"绘画"的观看逻辑。

判断标准不是"哪种技术更先进"，而是这条边在画面里承担什么信息：需要明确分隔就上硬线，只是营造气氛就用菲涅尔，需要结构细节才动纹理。把三种需求混在同一物体上，往往会得到"线条打架"的结果。

线宽与设备像素比 ​

最后一个容易忽略的细节：屏幕上的"1 像素"在不同设备上不是同一件事。devicePixelRatio = 2 的手机，1 个 CSS 像素对应 2 个缓冲像素；如果外壳的 uWidth 只按 CSS 像素传，线会细一半。正确做法是把设计稿上的线宽乘以 Math.min(devicePixelRatio, 2)，并把 uResolution 传成渲染缓冲的真实尺寸，两边单位才对齐。后处理描边同理：uThickness 也要做同样的换算，否则同一套参数在桌面和手机上看起来是两种风格。

术语解释 ​

  • silhouette 剪影/外轮廓：物体在屏幕投影的最外边界。
  • backface 背面：法线背向相机的三角形，BackSide 只渲染它们。
  • Sobel 算子：用相邻像素差分估算梯度的卷积核，边缘检测的基础工具。
  • prepass 预渲染：为后处理额外渲染一张辅助图（法线、深度、ID），不直接上屏。
  • rim 边缘光：从侧后方打来的光在物体轮廓上形成的高亮，菲涅尔描边借用了它的视觉语言。
  • draw call：CPU 向 GPU 提交一次绘制命令，数量直接影响 CPU 侧开销。

三个常见坑 ​

  1. 外壳挡住主体：把外壳当普通子物体加进去，深度测试通过后反而糊住正面。外壳必须 side = BackSide，且不要开 depthWrite 之外的透明混合。
  2. 后处理描边在雾里失效：雾把远处物体压成背景色，深度差变小，轮廓线消失。要么在预渲染时关闭雾，要么对远处物体改用外壳描边。
  3. 线宽用世界单位：position += normal * 0.02 在透视下远近不一致，近处像粗马克笔，远处像发丝。用屏幕空间外扩公式，或按相机距离补偿。

代码示例 ​

对应演示 outline-lab.html：同一组模型（环面结、球、立方体），右上角切换四种描边方式，滑杆调线宽，信息卡实时显示 draw call 与额外 pass 数。

① 外壳：在裁剪空间沿法线外扩：

js
const shellMaterial = new THREE.ShaderMaterial({
  uniforms: {
    uWidth: { value: 4 },                       // 像素宽度
    uResolution: { value: new THREE.Vector2(innerWidth, innerHeight) },
    uColor: { value: new THREE.Color(0x070a12) }
  },
  vertexShader: /* glsl */`
    uniform float uWidth;
    uniform vec2 uResolution;
    void main() {
      vec3 nView = normalize(normalMatrix * normal);
      vec4 clip = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
      clip.xy += nView.xy * uWidth * 2.0 / uResolution * clip.w;
      gl_Position = clip;
    }
  `,
  fragmentShader: /* glsl */`
    uniform vec3 uColor;
    void main() { gl_FragColor = vec4(uColor, 1.0); }
  `,
  side: THREE.BackSide
})

把它挂成模型的子物体，父子共享同一份几何，位置天然对齐：

js
const shell = new THREE.Mesh(geometry, shellMaterial)
shell.visible = false
mesh.add(shell)

② 后处理：先画法线 + 深度，再做边缘检测：

js
const normalRT = new THREE.WebGLRenderTarget(w, h, { depthBuffer: true })
normalRT.depthTexture = new THREE.DepthTexture(w, h)
normalRT.texture.colorSpace = THREE.NoColorSpace

const edgePass = new ShaderPass(EdgeShader)
edgePass.uniforms.tNormal.value = normalRT.texture
edgePass.uniforms.tDepth.value = normalRT.depthTexture

每帧在合成之前补一次预渲染，注意临时替换材质再还原：

js
if (edgePass.enabled) {
  scene.overrideMaterial = normalMaterial      // MeshNormalMaterial
  renderer.setRenderTarget(normalRT)
  renderer.clear()
  renderer.render(scene, camera)
  scene.overrideMaterial = null
  renderer.setRenderTarget(null)
}
composer.render()

③ 菲涅尔：无须额外绘制的描边：

js
float fres = pow(1.0 - clamp(dot(n, v), 0.0, 1.0), 3.0);
col += uRimColor * fres * uRim;

在演示里，模式切到"菲涅尔描边"时只是把 uRim 从 0 调到 0.85，其他一切不变——这就是它的全部成本。

④ 纹理描边：在 UV 空间找法线台阶：

常见问题解答 ​

Q1：反向外壳的线条在远处变细、近处变粗，怎么改成等宽？

因为外扩量写在了物体空间。改正方法是把法线转到视图空间，再把偏移量换算到裁剪坐标：clip.xy += nView.xy * widthPx * 2.0 / resolution * clip.w。这里的 2.0 来自 NDC 的跨度（-1 到 1），clip.w 负责抵消透视除法造成的近大远小。改完后无论相机距离如何，线宽都稳定在设定的像素数。别忘了在 resize 时同步更新 uResolution，并把 widthPx 乘以 devicePixelRatio，否则高分屏上会细一半。

Q2：后处理描边一开启，物体表面全是噪点和小短线？

先查三个来源：① 深度精度：把 near 调得过小（比如 0.01）会让远处深度精度骤降，差分结果全是噪声，先把 near/far 收紧；② 法线缓冲的编码：MeshNormalMaterial 输出的是 0.5 + 0.5 * n，采样后必须 * 2.0 - 1.0 再归一化，直接拿编码值做点积会得到错误结果；③ 半径与阈值不匹配：搜索半径只有一像素时，柔和曲面的法线差几乎为零，噪声反而被放大；把半径提到 2~3 像素、阈值提到 0.15 以上，同时给线条加一点淡出。另外，后处理描边是在单采样的辅助缓冲上做的，主画面开 MSAA 也救不了它，必要时配 SMAA 或 FXAA。

Q3：外壳和阴影一起用时，为什么地上多出一圈黑边/阴影变脏？

外壳是真实几何，默认会参与阴影投射。修复方式是给外壳 castShadow = false、receiveShadow = false，并尽量把它放在阴影计算的通道之外；如果使用自定义 ShaderMaterial，还要确认没有开启 depthWrite 造成透明排序问题。另一个常见原因是外壳被加了 renderOrder 却仍走不透明队列，导致它和主体在同一深度上闪烁，把外壳稍微朝内推一点点或单独分层渲染即可。

Q4：菲涅尔描边和反向外壳应该选哪个？

看你要"线"还是"光"。反向外壳是真正的几何线，宽度稳定、颜色可控、能压住背景；菲涅尔是亮度渐变，随视角呼吸，更像边缘光，适合发光体、深色背景、需要氛围的镜头。两者并不互斥：外壳负责清晰轮廓，菲涅尔负责轮廓附近的冷暖过渡，叠加使用时只要把菲涅尔的 pow 指数调大、强度调低，就不会和硬线抢戏。预算紧张时优先外壳，因为它至少不会随镜头转动而消失。

动手小练习 ​

  1. 打开 outline-lab.html，把"反向外壳"的线宽从 2 调到 10，观察球体与立方体转角处的差异。为什么立方体的边角更容易出现断口？提示：想一想硬边法线的方向。
  2. 切到"后处理边缘"，把"深度灵敏度"从 0.04 调到 0.15，记录地面与远景中假线的变化；再关掉深度检测、只用普通检测，比较两条路线的取舍。
  3. 用纹理描边模式，把 uTexEdge 从 0.1 调到 0.8，找出"线太多"与"线断成虚线"的两个临界值，并解释它们分别对应法线贴图的什么特征。
