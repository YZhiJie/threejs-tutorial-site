28.2 进阶应用：卡通着色与光照分级 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑫⑬ 再学习本篇。

核心概念讲解 ​

接桥：⑧ 的软阴影在卡通风格里反而"脏" ​

在 ⑧ 灯光 · 阴影 里，我们花了不少篇幅调 shadow.radius、shadow.blurSamples 和 PCF 类型，目标只有一个：让阴影边缘像真实世界那样柔和过渡。那套经验在写实渲染里完全正确，但在卡通渲染里会立刻失效——柔和的阴影边缘会变成一圈灰蒙蒙的脏边，把刚刚分好的色阶又搅浑。

原因不难理解：卡通风格的前提是"世界由有限几种明度组成"，而软阴影在亮部与暗部之间制造了一条连续的灰带，这条灰带既不属于亮色阶，也不属于暗色阶，视觉上就是"脏"。所以做 NPR 时，阴影的处理方向经常是反过来的：要硬边、要少渐变、要明确落在某一档里。这一篇就从这条反直觉的经验出发，讲清卡通着色的核心——光照分级（light banding）。

从 Lambert 到色阶：把连续函数切成台阶 ​

Lambert 光照的核心是一句 ndl = max(dot(N, L), 0)，结果在 0 到 1 之间连续变化。写实渲染珍惜这种连续性，卡通渲染则要主动破坏它：把 ndl 映射到有限的几档明度上。

有两种实现路径，效果接近，但可控性不同：

路径做法优点缺点
step 函数floor(ndl * n) / n 或嵌套 step无需贴图，档数一个 uniform 控制档位边界写死，难以染色
ramp 贴图把 ndl 当 UV 去采样一张 1D 渐变图边界、颜色、软硬都能由美术调多一次纹理采样，需管理贴图

演示用的是第二种：一张 256×1 的 CanvasTexture，横轴就是光照强度，纵轴固定 0.5。采样时：

glsl
vec3 ramp = texture2D(uRamp, vec2(ndl, 0.5)).rgb;
vec3 col = uBase * ramp;

因为 ramp 是 RGB 三通道，它不只是"明度表"，还能顺手染亮部与暗部：暗部给一点蓝、亮部给一点暖黄，色阶之间就有了色彩倾向，而不是简单地把颜色变亮变暗。这是 ramp 贴图比 step 函数更有价值的地方——它把"分级"和"调色"合并成了一张图。

色阶数量：不是越多越好 ​

色阶数量直接决定风格的"硬度"。档数太少，画面像海报；档数太多，又会退回写实，失去卡通的味道。经验区间大致如下：

色阶数观感渲染成本典型用途
2 档极硬，像双色版画/剪影最低标题画面、剪影风、强图形感
3 档主流卡通：亮 / 中间 / 暗低角色、道具、大多数动画风项目
4~5 档柔和，接近"厚涂"低有体积感、需要细腻过渡的角色特写
连续渐变基本回到 Lambert最低只想要描边、不想改光照的项目

3 档之所以成为主流，是因为它刚好对应人眼读体积所需的最少信息：受光面、背光面、以及两者之间的一条过渡。再少就只剩"亮/暗"两块，转折关系会丢；再多则每档之间的差异变小，分级的意义被稀释。

成本方面，色阶数量本身几乎不影响性能——无论 3 档还是 5 档，都是一次纹理采样。真正花钱的是为了分级而增加的辅助手段：法线平滑、描边外壳、额外的后处理。所以"要不要上 5 档"从来不是性能问题，而是风格问题。

高光块：把镜面反射也切成硬边 ​

卡通渲染的高光不能是 Standard 材质那种柔和高光，而应该是一块边界清晰的形状。做法与漫反射分级同构：先算 Blinn-Phong 的高光项，再用 step 切出硬边：

glsl
vec3 h = normalize(l + v);
float spec = pow(max(dot(n, h), 0.0), 26.0);
float block = step(uSpecThreshold, spec) * uSpecStrength;
col += vec3(1.0, 0.96, 0.9) * block;

三个参数各管一件事：pow 的指数决定高光块的大小（越大越小越锐），uSpecThreshold 决定它出现的门槛，uSpecStrength 决定亮度。注意高光块要比漫反射色阶更亮更暖，否则会和中间调混在一起，失去"反光"的暗示。对角色来说，高光块通常只放在头发、眼睛、皮革和金属配件上，皮肤和布料尽量不给硬高光，否则会显得像塑料。

阴影侧着色：冷色偏移，避免"灰死" ​

写实渲染里阴影只是"更暗的同一个颜色"，卡通渲染里如果也这么做，暗部会迅速塌成一块死灰。真实世界的阴影并不是单纯变暗：直射光被挡住后，环境光（天空的蓝、地面的反射）成为主导，于是阴影天然偏冷。

实现上只要在阴影侧叠一点冷色：

glsl
col += uShadowTint * (1.0 - ramp.r) * 0.20;

ramp.r 越小表示越靠暗部，权重越大；uShadowTint 给一个偏蓝紫的颜色，暗部就有了"空气感"。数值不要太大，0.1~0.25 之间通常足够；超过这个范围，暗部会变成明显的紫色，风格会从"卡通"滑向"赛博"。

这条经验的另一面是不要用纯灰来做暗部。纯灰在彩色环境里看起来总是"脏"，因为它同时缺少色相和明度层次。即便项目是黑白漫画风，也建议暗部带一点点蓝或褐，让画面有温度。

MeshToonMaterial + gradientMap：官方现成方案 ​

如果不想自己写 shader，Three.js 提供了 MeshToonMaterial。它的关键参数是 gradientMap——一张横向的明度阶跃图：

js
const data = new Uint8Array([70, 150, 255])
const gradientMap = new THREE.DataTexture(data, 3, 1, THREE.RedFormat)
gradientMap.minFilter = THREE.NearestFilter
gradientMap.magFilter = THREE.NearestFilter
gradientMap.generateMipmaps = false
gradientMap.needsUpdate = true

const mat = new THREE.MeshToonMaterial({
  color: 0x46c2b8,
  gradientMap
})

三个细节必须注意：NearestFilter 保证档与档之间是硬切换，用线性过滤会得到一张"伪平滑"的渐变；RedFormat 是因为内置 toon 光照只读红色通道；NoColorSpace（或不设）表示这是数据而不是颜色，别按 sRGB 解码。MeshToonMaterial 不支持金属度/粗糙度那套 PBR 参数，所以它更适合"角色 + 手绘贴图"的组合，不适合替代产品级材质。

onBeforeCompile 改造 Standard 材质 ​

项目里常常已经有一整套 MeshStandardMaterial（带动画、贴图、阴影、环境贴图），不想全部换成 toon。这时可以用 onBeforeCompile 在编译期给现有 shader 打补丁：

js
const mat = new THREE.MeshStandardMaterial({ color: 0x46c2b8, roughness: 0.85 })
mat.onBeforeCompile = (shader) => {
  shader.uniforms.uRamp = { value: rampTex }
  shader.uniforms.uToonLight = { value: new THREE.Vector3(0.5, 0.8, 0.5) }
  shader.fragmentShader = shader.fragmentShader
    .replace('#include <common>', `
      #include <common>
      uniform sampler2D uRamp;
      uniform vec3 uToonLight;
    `)
    .replace('#include <opaque_fragment>', `
      float toonNL = clamp(dot(normalize(vNormal), normalize(uToonLight)), 0.0, 1.0);
      vec3 toonBand = texture2D(uRamp, vec2(toonNL, 0.5)).rgb;
      outgoingLight *= toonBand;
      #include <opaque_fragment>
    `)
}
mat.customProgramCacheKey = () => 'toon-standard'

这段补丁在最终输出前把光照结果再乘一次色阶，视觉上接近"给写实材质套了一层卡通滤镜"。它不是最纯正的做法（真正的 toon 应该在光照计算阶段就分级），但胜在改造成本低、和现有资产兼容。两个坑：onBeforeCompile 只在编译时执行，之后改参数必须走 uniform；customProgramCacheKey 必须返回唯一值，否则不同补丁的材质会共用同一份缓存程序。

法线平滑与轮廓线的配合 ​

卡通着色把光照压成了几块平面，观众对"形状"的感知会更强，这时法线质量会被放大：

  • 硬边模型 + 平滑法线会让转角的色阶过渡变得柔和，更像手绘；但如果同时叠加反向外壳描边，外壳会沿平滑法线外扩，转角处反而更圆润，风格更统一。
  • 硬边 + 硬法线适合机械、方块类角色，外壳在转角会出现断口，反而像"手绘描线没有接上"，有些风格会刻意保留。
  • 低模（面数很少）配合平滑法线是卡通渲染的黄金组合：轮廓干净、色阶块面大、性能好，还自带"手作感"。这也是为什么很多卡通项目反而不追求高模。

一句话总结：写实靠法线细节，卡通靠法线整体走向。做 NPR 时，先决定"这个模型要不要软法线"，再决定描边方案，顺序不要反。

色阶与描边要像"同一支笔" ​

色阶决定块面的层次，描边决定边界的硬度，两者必须看起来出自同一套笔法，否则画面会"各画各的"。一条可操作的对应关系：

  • 2 档 + 3~5 px 粗硬线：海报、版画、强图形感，线本身承担结构信息；
  • 3 档 + 2~3 px 硬线：主流卡通，最稳的组合，角色与场景都能用；
  • 5 档 + 1~2 px 细线或深棕线：偏厚涂、偏插画，线要退到色块后面，不能抢体积；
  • 连续渐变 + 菲涅尔边缘光：接近写实，只需要一层气氛，不需要真正的黑线。

线条颜色也值得单独决定。纯黑 #000000 在所有色块上都会显得"贴上去的"，而带一点主体色相的深色（例如深蓝灰、深棕）会像"同一张纸上压下去的墨"，更自然。原则是：线比最暗的色阶再暗一档，但保留一点色相。

高光块与镜头距离 ​

卡通高光是一块硬边，这意味着它对"距离"非常敏感：模型离镜头远时，高光块会缩成一个亮点，甚至在像素级别闪烁；离镜头近时又会大得像一块贴纸。工程上常见两种处理：把高光强度按距离或屏幕占比淡出，或者在远景 LOD 上直接关掉高光块。别用缩小 pow 指数的方式"软化"它——那会把硬边重新变成渐变，破坏分级结构。宁可让它消失，也不要让它变成一坨模糊的亮斑。

风格统一：角色、场景、特效用同一套色阶 ​

卡通风格最容易翻车的地方不是单个物体，而是同一个画面里混用了不同规则：角色 3 档、场景 5 档、特效连续渐变，再各自配不同的描边宽度。观众说不出哪里不对，但会觉得"廉价"。

工程上的做法是把风格参数收敛成一个共享配置：

js
const NPR_CONFIG = {
  rampSteps: 3,
  rampTexture: sharedRamp,
  shadowTint: 0x35569e,
  outlineWidth: 3,       // 像素
  outlineColor: 0x080b12,
  specThreshold: 0.42
}

所有材质从同一份配置读参数，UI 面板只调这份配置并广播给所有材质。这样"角色改了色阶，场景没跟上"这类问题从结构上就不存在。更进一步，可以把 ramp 贴图当成"美术交付物"：由美术出一张 256×1 的 PNG，程序只负责加载和绑定，风格调整就不再需要改代码。

术语解释 ​

  • 光照分级（light banding）：把连续的 dot(N, L) 映射到有限档明度，是卡通着色的核心操作。
  • ramp / gradient map：横轴为光照强度、纵轴固定的 1D 贴图，用来定义每一档的颜色与边界。
  • 明暗交界线（terminator）：受光面与背光面的分界，卡通风格里通常压成一条明确的色阶边。
  • 硬边 / 软边：相邻色阶之间是突跳还是渐变；档位越少、过渡区越窄，观感越硬。
  • toon shading：一类把光照结果量化为色块的非真实感着色模型，MeshToonMaterial 是它的官方实现。
  • 高光块：用阈值切出的硬边镜面高光，形状清晰、不含渐变。

① 程序化 ramp：用 Canvas 画出阶跃：

js
function makeRamp(stops) {
  const canvas = document.createElement('canvas')
  canvas.width = 256
  canvas.height = 1
  const ctx = canvas.getContext('2d')
  const grad = ctx.createLinearGradient(0, 0, 256, 0)
  stops.forEach(([pos, color]) => grad.addColorStop(pos, color))
  ctx.fillStyle = grad
  ctx.fillRect(0, 0, 256, 1)

  const tex = new THREE.CanvasTexture(canvas)
  tex.wrapS = THREE.ClampToEdgeWrapping
  tex.minFilter = THREE.NearestFilter
  tex.magFilter = THREE.NearestFilter
  tex.colorSpace = THREE.NoColorSpace
  return tex
}

const ramp3 = makeRamp([
  [0.00, '#343a4d'], [0.32, '#343a4d'],
  [0.33, '#8d8e9a'], [0.66, '#8d8e9a'],
  [0.67, '#f4e7cf'], [1.00, '#f4e7cf']
])

同一位置放两个色标（例如 0.32 与 0.33）就得到一条硬边。想要软一点，把间隔拉大；想要更多档，继续复制这一对色标。

② 片元里采样 ramp，并叠加高光块与冷色暗部：

glsl
float ndl = clamp(dot(n, l), 0.0, 1.0);
vec3 ramp = texture2D(uRamp, vec2(ndl, 0.5)).rgb;
vec3 col = uBase * ramp;
col += uShadowTint * (1.0 - ramp.r) * 0.20;

vec3 h = normalize(l + v);
float spec = pow(max(dot(n, h), 0.0), 26.0);
float block = step(uSpecThreshold, spec) * uSpecStrength;
col += vec3(1.0, 0.96, 0.9) * block;

③ 全局描边：所有部件共享一份外壳材质：

js
function addOutline(mesh) {
  const shell = new THREE.Mesh(mesh.geometry, shellMaterial)
  mesh.add(shell)
  shellMeshes.push(shell)
}

function applyOutline() {
  shellMeshes.forEach((s) => { s.visible = params.outline })
}

角色由头、身体、眼睛、帽子、手臂七个部件拼成，每个部件都挂一个外壳；用同一个开关控制全部，视觉上才不会出现"身体有线、手臂没线"的割裂。

④ 切换色阶只改 uniform，不重建材质：

gui.add(params, 'ramp', ['平滑', '3 阶', '5 阶', '自定义 ramp 贴图'])

    globalU.uRamp.value = ramps[params.ramp]
  })

演示里所有材质共享同一个 uRamp uniform 对象，所以一次赋值就全场景生效。这也是把风格参数集中管理的最小实现。

常见问题解答 ​

Q1：卡通渲染的暗部总是发灰发脏，是色阶不够多吗？

通常不是色阶数量的问题，而是暗部缺少色彩倾向、并且混入了柔和的中间层次。按顺序排查：① 阴影是否用了大半径软阴影，软边制造出一条连续灰带，卡通风格里应改成硬边或减小模糊；② 有没有开 SSAO/AO 贴图，在高频噪点的遮蔽图上做色阶等于给暗部撒灰；③ 暗部是不是单纯乘了一个小于 1 的数，没有加冷色偏移；④ ramp 贴图的暗部是不是纯灰。最有效的修法是给暗部叠加 0.1~0.25 强度的冷色（uShadowTint），并让 ramp 的过渡段尽量窄。

Q2：`MeshToonMaterial` 的 gradientMap 设了却没效果，画面还是平滑的？

四个常见原因：① 贴图不是 RedFormat，内置 toon 光照只读红色通道，RGBA 图的红通道值如果一致就等于只有一档；② 过滤方式用了默认的线性过滤，档与档之间被插值成渐变，必须 NearestFilter；③ generateMipmaps 没关，缩小时 mip 会把台阶平均掉；④ 贴图创建后忘了 needsUpdate = true，数据没上传。另外别把 gradientMap 当成颜色贴图设 colorSpace = SRGBColorSpace，它是数据。

Q3：用 onBeforeCompile 改造 Standard 材质，参数改了不生效怎么办？

onBeforeCompile 只在程序编译时执行一次，它的作用是把 uniform 声明和代码片段塞进去，不是每帧回调。运行时要改效果，必须把参数做成 uniform 并保存引用：在 onBeforeCompile 里把 shader.uniforms.uRamp 存到一个外层变量，之后改 uniform.value。另外要给材质设置 customProgramCacheKey，返回一个能区分不同补丁的字符串，否则多个材质会共用同一份编译缓存，出现"改了一个材质，别的也跟着变"或"改了没反应"的诡异现象。最后，修改 onBeforeCompile 之后要 material.needsUpdate = true 才会重新编译。

Q4：色阶越多越好吗？5 档是不是比 3 档高级？

不是。色阶数量是风格参数，不是质量参数。3 档对应"受光 / 背光 / 过渡"的最小可读结构，信息量刚好；5 档更接近厚涂，适合需要体积感的角色特写；2 档则更图形化。档数增加不会增加渲染成本（都是一次纹理采样），但会削弱"卡通"的特征，让画面向写实靠拢。判断标准应该是这套档数是否符合项目的整体美术语言，而不是数字越大越精细。

动手小练习 ​

  1. 打开 toon-ramp-lab.html，把"3 阶"与"5 阶"各截一张图，遮住颜色只看明度，数一数球体上出现了几块不同的明度，并解释为什么 5 档的边界更不明显。
  2. 固定 3 阶，把"阴影冷色"从深蓝调到暖橙，观察暗部从"冷灰"变成"脏棕"的过程，记录你认为可接受的两个端点值。
  3. 把"高光块强度"从 0 调到 1，再把 uSpecThreshold 的思路改成"按距离淡出"，想一想：为什么卡通高光必须是一块而不是一条渐变？把你的结论写成三行文字。
