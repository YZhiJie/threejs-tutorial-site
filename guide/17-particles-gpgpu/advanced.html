17.2 进阶应用：FBO 与 GPGPU 粒子 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑫⑮ 与 17.1 再学习本篇。

核心概念讲解 ​

接桥：当"只喂时间"不够用时 ​

17.1 的星云之所以轻松，是因为每颗粒子的位置都能写成 f(初始位置, uTime) 的封闭公式——无状态、可重放。但只要效果带"记忆"（粒子被鼠标推开后留在那里、互相碰撞、按上一帧的速度继续飞），公式法就失效了：下一帧的位置取决于上一帧的位置。这种带状态的模拟，传统做法是 JS for 循环逐粒子更新——而这正是性能悬崖的入口。

为什么 CPU 更新万级粒子会爆 ​

假设 5 万颗粒子，每帧在 JS 里做最省的更新：

js
// 每帧：5 万次数学运算 + 150KB 数据重新上传 GPU
for (let i = 0; i < 50000; i++) {
  vel[i*3] += forceX; pos[i*3] += vel[i*3] * dt
  // …还有 y、z 两个分量
}
geometry.attributes.position.needsUpdate = true   // 整个缓冲重新走总线上传

两个致命点：

  1. JS 单线程串行：5 万次循环在 16.6ms 帧预算里很奢侈，物理一复杂（距离判断是 O(n²)）直接爆炸；
  2. 每帧全量上传：needsUpdate 会把整个 Float32Array 从内存搬到显存，CPU→GPU 总线带宽成为第二个瓶颈。

GPU 恰恰相反：它有几千个并行核心，5 万个"互相独立的粒子更新"正是它的天职。GPGPU（General-Purpose GPU computing）的思想就是：把粒子状态留在显存里，让 GPU 自己算下一帧。

FBO：把计算结果画进纹理 ​

GPU 的唯一"编程入口"是渲染。做通用计算的窍门是不往屏幕上画，往纹理上画——这就是 FBO（Framebuffer Object，帧缓冲对象）离屏渲染：

  • 一张 RGBA float 纹理 = 一个巨大的 vec4 数组：R/G/B 存粒子 xyz，A 存寿命或随机种子；
  • 把片元着色器当"计算器"：渲染一个铺满纹理的四边形，每个片元（=每个纹素=每颗粒子）读出旧值、算出新值、写回去；
  • 数据全程不离开显存，CPU 只在最初填一次初始值。

ping-pong 双缓冲：自己不能读自己 ​

片元着色器有个硬约束：不能读写同一张纹理（未定义行为）。解法是准备两张纹理来回倒手：

第 1 帧：读 位置纹理A ──计算──▶ 写入 位置纹理B
第 2 帧：读 位置纹理B ──计算──▶ 写入 位置纹理A
第 3 帧：读 A → 写 B …交替进行（ping-pong）

每帧交换"谁是输入、谁是输出"，这就是 ping-pong 双缓冲。自己手写要管理两套 WebGLRenderTarget、每帧 swap、绑全屏四边形——样板代码不少，所以直接用官方封装。

GPUComputationRenderer：官方封装 ​

three/addons/misc/GPUComputationRenderer.js 把 FBO + ping-pong + 全屏四边形全部包好，你只剩三件事：

js
import { GPUComputationRenderer } from 'three/addons/misc/GPUComputationRenderer.js'

// ① 建计算器：纹理尺寸 WIDTH×WIDTH，粒子数 = WIDTH²
const gpu = new GPUComputationRenderer(WIDTH, WIDTH, renderer)

// ② 填初始状态：createTexture() 给一张空纹理，逐纹素写入初始位置/速度
const dtPos = gpu.createTexture()
const dtVel = gpu.createTexture()
// …往 dtPos.image.data 里撒初始坐标

// ③ 注册"变量"：每个变量 = 一张状态纹理 + 一段更新它的片元着色器
const posVar = gpu.addVariable('texturePosition', posFragShader, dtPos)
const velVar = gpu.addVariable('textureVelocity', velFragShader, dtVel)

// 声明依赖：谁要被注入为 sampler2D uniform，就读谁
gpu.setVariableDependencies(posVar, [posVar, velVar])  // 位置更新需要读旧位置+旧速度
gpu.setVariableDependencies(velVar, [posVar, velVar])  // 速度更新同理

const err = gpu.init()          // 编译；不支持 float 纹理时返回错误字符串
if (err !== null) console.error(err)

每帧两行：

js
gpu.compute()  // 内部连续渲染 pos/vel 两个 pass，ping-pong 自动交换
// 把"最新位置纹理"交给绘制粒子的材质
pointsMat.uniforms.texturePosition.value =
  gpu.getCurrentRenderTarget(posVar).texture

绘制阶段，粒子几何体不再存真实坐标，只存一个 reference（vec2，该粒子在纹理里的 uv）；顶点着色器用 texture2D(texturePosition, reference).xyz 取回位置——取位置这一步也是在 GPU 里完成的，JS 从头到尾没碰过粒子数据。

代码示例 ​

GPUComputationRenderer 实现 4096 颗粒子受鼠标排斥/吸引（排斥为正、吸引为负，滑杆可调），逐段注释：

js
import { GPUComputationRenderer } from 'three/addons/misc/GPUComputationRenderer.js'

const WIDTH = 64                        // 64×64 = 4096 颗粒子
const gpu = new GPUComputationRenderer(WIDTH, WIDTH, renderer)

// ---------- 1. 初始状态：球壳内随机位置，零速度 ----------
const dtPos = gpu.createTexture()
const dtVel = gpu.createTexture()
const posArr = dtPos.image.data         // Float32Array，len = WIDTH²×4
const velArr = dtVel.image.data
for (let i = 0; i < posArr.length; i += 4) {
  const r = Math.cbrt(Math.random()) * 5          // 均匀充满球体
  const t = Math.random() * Math.PI * 2
  const p = Math.acos(2 * Math.random() - 1)
  posArr[i]     = r * Math.sin(p) * Math.cos(t)   // x
  posArr[i + 1] = r * Math.sin(p) * Math.sin(t)   // y
  posArr[i + 2] = r * Math.cos(p)                 // z
  posArr[i + 3] = Math.random()                   // w: 随机种子备用
  // velArr 保持 0：初速度为零
}

// ---------- 2. 速度更新着色器：弹簧回中 + 鼠标斥力 + 阻尼 ----------
const velFrag = /* glsl */ `
  uniform vec3 uMousePos;     // mouse position in world space
  uniform float uRepel;       // positive = repel, negative = attract
  uniform float uDelta;       // frame delta time

  void main() {
    vec2 uv = gl_FragCoord.xy / resolution.xy;   // this particle's texel
    vec4 pos = texture2D(texturePosition, uv);   // read own state
    vec4 vel = texture2D(textureVelocity, uv);

    vec3 force = -pos.xyz * 0.8;                 // spring back to origin
    vec3 toMouse = pos.xyz - uMousePos;
    float d2 = dot(toMouse, toMouse);
    force += normalize(toMouse + 0.0001) * uRepel / (d2 + 0.5);  // mouse push

    vel.xyz += force * uDelta;
    vel.xyz *= 0.96;                             // damping: no infinite speedup
    gl_FragColor = vel;                          // write back to texture
  }
`

// ---------- 3. 位置更新着色器：半隐式欧拉积分 ----------
const posFrag = /* glsl */ `
  uniform float uDelta;

  void main() {
    vec2 uv = gl_FragCoord.xy / resolution.xy;
    vec4 pos = texture2D(texturePosition, uv);
    vec4 vel = texture2D(textureVelocity, uv);
    pos.xyz += vel.xyz * uDelta;                 // p' = p + v*dt
    gl_FragColor = pos;
  }
`

// ---------- 4. 注册变量与依赖，编译 ----------
const posVar = gpu.addVariable('texturePosition', posFrag, dtPos)
const velVar = gpu.addVariable('textureVelocity', velFrag, dtVel)
gpu.setVariableDependencies(posVar, [posVar, velVar])
gpu.setVariableDependencies(velVar, [posVar, velVar])
velVar.material.uniforms.uMousePos = { value: new THREE.Vector3() }
velVar.material.uniforms.uRepel    = { value: 18.0 }
velVar.material.uniforms.uDelta    = { value: 0 }
posVar.material.uniforms.uDelta    = { value: 0 }
gpu.init()

// ---------- 5. 绘制：顶点着色器按 reference 取回位置 ----------
const geo = new THREE.BufferGeometry()
const refs = new Float32Array(WIDTH * WIDTH * 2)
for (let i = 0; i < WIDTH * WIDTH; i++) {
  refs[i * 2]     = (i % WIDTH) / WIDTH + 0.5 / WIDTH   // texel center u
  refs[i * 2 + 1] = Math.floor(i / WIDTH) / WIDTH + 0.5 / WIDTH
}
geo.setAttribute('position', new THREE.BufferAttribute(new Float32Array(WIDTH * WIDTH * 3), 3)) // placeholder
geo.setAttribute('reference', new THREE.BufferAttribute(refs, 2))

const pointsVert = /* glsl */ `
  uniform sampler2D texturePosition;
  attribute vec2 reference;

  void main() {
    vec3 p = texture2D(texturePosition, reference).xyz;   // fetch state on GPU
    vec4 mv = modelViewMatrix * vec4(p, 1.0);
    gl_PointSize = 2.4 * (300.0 / -mv.z);
    gl_Position = projectionMatrix * mv;
  }
`
// 片元照常用 gl_PointCoord 采样柔点贴图，略（同 17.1）

// ---------- 6. 渲染循环：先 compute，再喂纹理，再画 ----------
renderer.setAnimationLoop(() => {
  clock.update()
  const dt = Math.min(clock.getDelta(), 0.033)  // clamp: avoid explosion after tab switch
  velVar.material.uniforms.uDelta.value = dt
  posVar.material.uniforms.uDelta.value = dt
  // uMousePos 由 pointermove 事件写入（NDC 反投影到原点附近平面）
  gpu.compute()
  pointsMat.uniforms.texturePosition.value =
    gpu.getCurrentRenderTarget(posVar).texture
  renderer.render(scene, camera)
})

整条链路的关键认知：JS 每帧只做"喂 uniform + 两次渲染调用"，4096 个粒子的受力、积分、存取全部发生在显存内部。把 WIDTH 调到 128（1.6 万）甚至 256（6.5 万），帧率基本不动——这就是"把 for 循环搬进显卡"。

常见问题解答 ​

Q1：gpu.init() 返回错误字符串 / 粒子全部不动？

init() 返回非 null 字符串只有两类原因：① 设备不支持顶点着色器采样纹理（maxVertexTextures === 0，古董级）；② setVariableDependencies 里依赖的变量名拼错。但 GPGPU 还有一道 init 管不到的门槛：渲染到 float 纹理需要 EXT_color_buffer_float 扩展（WebGL2）。稳妥做法是初始化前自己探一次：renderer.extensions.has('EXT_color_buffer_float')。桌面 Chrome/Edge/Safari 15+ 基本都支持；老设备可降级为 half float（gpu.setDataType(THREE.HalfFloatType)），精度和范围会打折但通常够用。另外粒子"编译通过却纹丝不动"时，先查依赖列表有没有漏写变量自己。

Q2：移动端 GPGPU 兼容性如何？

分两头看：① 功能——近两三年的主流手机（WebGL2 普及）都能跑，但务必真机验证 init() 返回值；② 性能——手机 GPU 并行度低、纹理带宽小，WIDTH 建议从 64 起步实测，别直接上 256。另外手机内存吃紧，float 纹理每 64×64 占 256KB（4 张变量纹理×2 份 ping-pong 就是 2MB），量级心里有数即可。

Q3：粒子位置出现"抖动"或逐渐漂移，是精度问题吗？

float 纹理是 32 位浮点，精度约 7 位十进制有效数字。坐标绝对值越大，小数部分越粗糙——粒子跑到离原点几百单位远的地方，位置量化误差就会肉眼可见。对策：① 模拟空间尽量以原点为中心、限制范围（示例用弹簧力把球约束在原点附近）；② 场景本身很大的话，把纹理里存"相对某锚点的偏移"而不是世界坐标。对精度敏感的场合（轨道模拟）再考虑 double 精度——WebGL 不支持，只能 CPU 算，又回到老路了。

Q4：为什么变量之间要 setVariableDependencies？

addVariable 只注册了"这张纹理由这段 shader 更新"，着色器里用到的 texturePosition / textureVelocity 这些 sampler 并不会自动出现——setVariableDependencies(var, [deps]) 告诉渲染器"把哪些变量的纹理作为 uniform 注入这段 shader"。漏声明依赖的典型症状：着色器编译不报错，但采样到的全是 0，粒子纹丝不动。规则：依赖列表写全（包括变量自己——要读旧值就得声明自己）。

动手小练习 ​

  1. 把速度着色器里的弹簧力 -pos.xyz * 0.8 改成环绕力 vec3(-pos.z, 0.0, pos.x)，观察粒子从"球"变成"漩涡"。
  2. 给位置纹理的 w 分量存入出生时刻，在速度着色器里让大龄粒子逐渐失速，做"粒子衰老"。
  3. 把 uDelta 的 clamp 上限从 0.033 改成 0.1，切后台再切回来观察粒子爆炸——理解为什么必须 clamp 帧间隔。
