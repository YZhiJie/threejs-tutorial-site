17.3 实战案例：万级粒子数据洪流 ​

前置提示：本篇属于精通方向扩展内容，建议先完成 17.1 / 17.2 与 13.1 后处理基础 再学习本篇。

核心概念讲解 ​

企业数据大屏里常见这样的镜头：上万条光点汇成洪流，绕着一个看不见的轴奔涌，鼠标划过处水流被劈开，快的地方发白发亮、慢的地方沉成深蓝。这就是本篇要交付的成品——万级粒子数据洪流。技术上它是前两篇的组合拳，再加一点点后期调味。

方案选型：公式流场 vs GPGPU ​

17.2 说过：带状态、要记忆的模拟才需要 GPGPU。数据洪流恰恰相反——它要的是永不停歇、无需记忆的流动，每颗粒子的位置都能写成 f(种子, uTime) 的封闭公式。所以我们回到 17.1 的"只喂时间"路线，把流场公式写进顶点着色器：

方案适用本案
时间驱动公式流场永续循环、无交互残留✅ 主流水
GPGPU 状态模拟鼠标推开后粒子留在原地只需瞬时扰动，用不上

经验：能用公式算出来的，就不要上状态纹理——少一层 FBO，少一类兼容性问题。

洪流的骨架：螺旋管道流场 ​

把洪流想成一根无限长的螺旋管道，每颗粒子只管回答一个问题："我在 t 时刻应该在哪"：

glsl
// 每颗粒子带一个 0~1 的出生相位 aOffset，加上时间后取小数 = 在管道里的循环进度
float t = fract(aOffset + uTime * uSpeed);
// t 沿管道前进：x 从 -L/2 走到 +L/2
float x = (t - 0.5) * uLength;
// 绕 x 轴螺旋：种子决定初始角和半径
float angle = aSeed.x * 6.2831 + t * uTwist;
float radius = uRadius * (0.3 + 0.7 * aSeed.y);
vec3 p = vec3(x, cos(angle) * radius, sin(angle) * radius);

fract 让粒子走到管道尽头自动回到起点——无限循环，零状态。在此基础上叠一个正弦摆动让水流不死板，再加鼠标斥力做交互扰动，洪流的形态就完成了。

速度着色：有限差分估速度 ​

"快的地方亮"需要知道每颗粒子的瞬时速度。公式流场里速度没有显式存着，但可以在顶点着色器里算两次位置：p(t) 和 p(t + Δ)，差值长度就是速度的近似：

glsl
vec3 p1 = flowPos(t);
vec3 p2 = flowPos(t + 0.01);
vSpeed = length(p2 - p1) / 0.01;   // finite-difference speed

vSpeed 经 varying 递给片元，mix(uColorSlow, uColorFast, smoothstep(...)) 完成按速度混色。每顶点多算一次公式的开销对 GPU 来说忽略不计。

泛光：一步点亮大屏质感 ​

粒子本身用小亮点，开一层 UnrealBloom 泛光，亮部向四周晕开——大屏的"辉光感"就是这么来的。接入方式就是 13.1 的三件套：

js
const composer = new EffectComposer(renderer)
composer.addPass(new RenderPass(scene, camera))
const bloom = new UnrealBloomPass(new THREE.Vector2(innerWidth, innerHeight), 0.9, 0.5, 0.25)
composer.addPass(bloom)
composer.addPass(new OutputPass())

渲染循环里用开关决定走 composer.render() 还是 renderer.render(...)——泛光可以关，方便低端机降级。

代码示例 ​

与演示对应的核心代码，逐段注释（几何生成、JS 侧 GUI 从略处省略，完整代码见演示源码）：

js
// ---------- 1. 几何：只存"出生证明"，不存真实坐标 ----------
// position 占位（必须有），真正的信息在 aOffset（相位）与 aSeed（随机种子）
function buildFlow(count) {
  const geo = new THREE.BufferGeometry()
  const offsets = new Float32Array(count)
  const seeds = new Float32Array(count * 4)
  for (let i = 0; i < count; i++) {
    offsets[i] = Math.random()                 // 沿管道的出生相位
    seeds[i * 4]     = Math.random()           // 螺旋初始角
    seeds[i * 4 + 1] = Math.random()           // 半径比例
    seeds[i * 4 + 2] = Math.random()           // 摆动相位
    seeds[i * 4 + 3] = Math.random()           // 大小倍率
  }
  geo.setAttribute('position', new THREE.BufferAttribute(new Float32Array(count * 3), 3))
  geo.setAttribute('aOffset', new THREE.BufferAttribute(offsets, 1))
  geo.setAttribute('aSeed', new THREE.BufferAttribute(seeds, 4))
  geo.boundingSphere = new THREE.Sphere(new THREE.Vector3(), 40) // 手动包围球：顶点在 shader 里动
  return geo
}

// ---------- 2. 顶点着色器：流场公式 + 鼠标扰动 + 速度差分 ----------
const vertexShader = /* glsl */ `
  uniform float uTime;
  uniform float uSpeed;
  uniform float uLength;
  uniform float uRadius;
  uniform float uTwist;
  uniform vec3 uMouse;        // mouse world position on the flow plane
  uniform float uRepel;       // interaction strength
  uniform float uSize;
  attribute float aOffset;
  attribute vec4 aSeed;
  varying float vSpeed;
  varying float vMix;

  // the flow field: one formula answers "where am I at progress t"
  vec3 flowPos(float t, vec4 seed) {
    float x = (t - 0.5) * uLength;
    float angle = seed.x * 6.2831 + t * uTwist;
    float r = uRadius * (0.3 + 0.7 * seed.y);
    vec3 p = vec3(x, cos(angle) * r, sin(angle) * r);
    p.y += sin(uTime * 1.7 + seed.z * 6.2831 + t * 9.0) * 0.35;  // idle wobble
    return p;
  }

  void main() {
    float t = fract(aOffset + uTime * uSpeed);
    vec3 p = flowPos(t, aSeed);

    // mouse disturbance: push away, falls off with distance
    vec3 toP = p - uMouse;
    float d2 = dot(toP, toP);
    p += normalize(toP + 0.001) * uRepel / (d2 + 2.0);

    // finite-difference speed for coloring
    vec3 pNext = flowPos(fract(t + 0.01), aSeed);
    vSpeed = length(pNext - p) * 100.0;
    vMix = t;                                 // also pass progress for head/tail fade

    vec4 mv = modelViewMatrix * vec4(p, 1.0);
    gl_PointSize = uSize * (0.5 + aSeed.w) * (300.0 / -mv.z);
    gl_Position = projectionMatrix * mv;
  }
`

// ---------- 3. 片元着色器：柔点 × 速度混色 ----------
const fragmentShader = /* glsl */ `
  uniform sampler2D uTexture;
  uniform vec3 uColorSlow;
  uniform vec3 uColorFast;
  uniform float uSpeedMax;
  varying float vSpeed;
  varying float vMix;

  void main() {
    vec4 tex = texture2D(uTexture, gl_PointCoord);
    float k = smoothstep(0.0, uSpeedMax, vSpeed);
    vec3 color = mix(uColorSlow, uColorFast, k);
    // fade at both ends of the pipe: no pop when particles wrap
    float fade = smoothstep(0.0, 0.06, vMix) * (1.0 - smoothstep(0.94, 1.0, vMix));
    gl_FragColor = vec4(color * tex.rgb, tex.a * fade);
  }
`

// ---------- 4. 材质：加法混合 + 不写深度（同 17.1 配方） ----------
const material = new THREE.ShaderMaterial({
  uniforms: {
    uTime:      { value: 0 },
    uSpeed:     { value: 0.06 },
    uLength:    { value: 36.0 },
    uRadius:    { value: 3.2 },
    uTwist:     { value: 9.0 },
    uSize:      { value: 2.2 },
    uRepel:     { value: 3.0 },
    uSpeedMax:  { value: 6.0 },
    uMouse:     { value: new THREE.Vector3(999, 999, 999) }, // park far away by default
    uColorSlow: { value: new THREE.Color(0x1d4ed8) },
    uColorFast: { value: new THREE.Color(0x7ff3ff) },
    uTexture:   { value: makeSoftDotTexture() }              // 同 17.1 的 Canvas 柔点
  },
  vertexShader, fragmentShader,
  transparent: true, blending: THREE.AdditiveBlending, depthWrite: false
})
const flow = new THREE.Points(buildFlow(20000), material)
scene.add(flow)

// ---------- 5. 泛光后处理链（可开关，13.1 三件套） ----------
const composer = new EffectComposer(renderer)
composer.addPass(new RenderPass(scene, camera))
const bloom = new UnrealBloomPass(new THREE.Vector2(innerWidth, innerHeight), 0.9, 0.5, 0.25)
composer.addPass(bloom)
composer.addPass(new OutputPass())

// ---------- 6. 鼠标：NDC 反投影到 z≈0 平面，作为扰动中心 ----------
const raycaster = new THREE.Raycaster()
const flowPlane = new THREE.Plane(new THREE.Vector3(0, 0, 1), 0)
const tmpVec = new THREE.Vector3()
addEventListener('pointermove', e => {
  const ndc = new THREE.Vector2(e.clientX / innerWidth * 2 - 1, -(e.clientY / innerHeight) * 2 + 1)
  raycaster.setFromCamera(ndc, camera)
  const hit = raycaster.ray.intersectPlane(flowPlane, tmpVec)
  if (hit) material.uniforms.uMouse.value.copy(hit)
})

// ---------- 7. 渲染循环：喂时间，按开关选渲染路径 ----------
renderer.setAnimationLoop(() => {
  clock.update()
  material.uniforms.uTime.value += clock.getDelta()
  if (params.bloom) composer.render()
  else renderer.render(scene, camera)
})

三个实战细节值得记住：① 包围球要手动给——顶点在 shader 里搬家，引擎按原始 position 算的包围盒是错的，不手动指定会被视锥剔除整批误杀；② 管道两端要淡出——fract 回绕的瞬间粒子会"瞬移"回起点，用进度做 alpha 渐隐就毫无痕迹；③ 鼠标默认停到 (999,999,999)，没划过鼠标时扰动为零，比布尔开关省事。

常见问题解答 ​

Q1：粒子一动就被视锥剔除，转到某个角度整批消失？

顶点着色器里改了位置，但视锥剔除用的是 JS 侧原始 position 算出的包围体——两者对不上就会误杀。解法二选一：手动给一个足够大的 geometry.boundingSphere（本例做法），或简单粗暴 flow.frustumCulled = false。GPGPU 方案同理——绘制用的占位 position 全是 0，包围球形同虚设，必须手动处理。

Q2：开泛光后整个画面发白/发灰？

加法混合的粒子叠加处亮度本来就高，UnrealBloom 再把高亮晕开，容易过曝。三个旋钮：threshold 调高（只让最亮的芯起辉）、strength 调低、renderer.toneMapping 保持 NoToneMapping 或换 ACES。另外泛光强度要随粒子数量联动调——5 万颗叠出来的亮度和 5 千颗完全不同。

Q3：数量拉到 5 万开始掉帧，瓶颈在哪？

本案没有 CPU 循环，瓶颈只剩 GPU 两端：① 片元填充率——加法混合的大粒子重叠越多，每像素混合次数越多，这是大屏粒子最常见的瓶颈，优先把 uSize 调小试试；② 顶点计算——每顶点算两遍流场公式，5 万也才 10 万次，对 GPU 是零头。所以掉帧先砍点的大小和屏幕占比，再考虑砍数量。

Q4：想让鼠标扰动"留下痕迹"（划过后水流持续紊乱）怎么办？

公式流场做不到——它无状态，扰动随鼠标离开立刻复原。这正是 17.2 GPGPU 的领地：把扰动力写进速度纹理，阻尼系数调低（比如 0.995），紊乱就能持续好几秒。两套方案可以在同一项目里按效果需求选用，甚至叠加：公式负责主流水，GPGPU 负责局部交互粒子。

动手小练习 ​

  1. 把流场的 cos/sin 螺旋换成直线 + 正弦蛇形（y = sin(t * 12.0) * r），对比两种洪流气质。
  2. 给 vSpeed 的混色加第三档：速度超过 uSpeedMax 的 1.5 倍时混入品红，做"超速告警"效果。
  3. 关掉泛光，把 uSize 从 2.2 一路调到 8，同时观察帧率变化，亲身体会片元填充率瓶颈。
