17.1 基础入门：Points 与粒子贴图 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑫⑮ 再学习本篇。

核心概念讲解 ​

接桥：把 shader 从网格表面搬到"点"上 ​

12.1 基础入门：GLSL 与第一个自定义着色器 里，我们写的 ShaderMaterial 都贴在网格上——顶点着色器搬运三角形顶点，片元着色器给每个像素上色。粒子系统用的是完全相同的知识，只是渲染对象从"三角形"换成了"点"：

网格（12.x 所学）粒子（本篇）
图元三角形，顶点插值出像素点，一个顶点直接变成一块方形区域
顶点着色器算 gl_Position算 gl_Position + gl_PointSize
片元着色器vUv 来自顶点插值用内置的 gl_PointCoord 当 uv
几何数据position/normal/uv通常只有 position（甚至 position 都不画三角形）

所以本篇没有新语言——uniforms、varying、smoothstep、fract 全部沿用，只是多两个点的专属内置变量。学完 12.x 的你其实已经会写粒子 shader 了，差的只是"点"这个图元的规则。

THREE.Points 与 PointsMaterial ​

Three.js 里粒子是一个专门的物体类型 THREE.Points，配对的内置材质是 PointsMaterial：

js
const points = new THREE.Points(
  geometry,                          // BufferGeometry，一个顶点 = 一颗粒子
  new THREE.PointsMaterial({
    size: 0.05,                      // 点的边长（世界单位）
    sizeAttenuation: true,           // 远处变小（透视衰减）
    vertexColors: true,              // 使用 geometry 里的 color attribute
    transparent: true,
    map: softDotTexture              // 不给贴图就是实心方块
  })
)
scene.add(points)

三个最容易踩的属性：

  • size：点图元在屏幕上是一块正方形，size 就是边长。最终好不好看取决于贴图，不靠 size 本身；
  • sizeAttenuation：开启后点随距离缩小，有空间感；关闭则所有点屏幕上一样大（适合做 HUD 标记）；
  • vertexColors：给每颗粒子上不同颜色，数据放在 geometry 的 color attribute 里。

BufferGeometry 存粒子数据 ​

粒子没有"形状"，几何体的职责只剩存数据。最小集合是 position（每粒子一个 vec3），按需再加 color、aScale、aSeed 等自定义 attribute：

js
const count = 5000
const positions = new Float32Array(count * 3)
const colors = new Float32Array(count * 3)

for (let i = 0; i < count; i++) {
  // 在盘状星云范围内撒点：半径平方根分布，中心密、边缘稀
  const r = Math.sqrt(Math.random()) * 6
  const a = Math.random() * Math.PI * 2
  positions[i * 3 + 0] = Math.cos(a) * r
  positions[i * 3 + 1] = (Math.random() - 0.5) * 0.6   // 压扁成盘
  positions[i * 3 + 2] = Math.sin(a) * r
  // 颜色按半径从暖白渐变到青蓝
  // …写入 colors
}

const geometry = new THREE.BufferGeometry()
geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3))
geometry.setAttribute('color', new THREE.BufferAttribute(colors, 3))

关键认知：这一大坨数据只上传 GPU 一次（setAttribute 时），之后渲染循环里 JS 完全不碰它——动画全交给着色器算。这正是 17.2 要展开的思想的预演。

自定义 Points shader：gl_PointSize 与 gl_PointCoord ​

写粒子的 ShaderMaterial 与 12.x 几乎一样，只多两个内置变量：

glsl
// 顶点着色器
uniform float uSize;        // base point size in world units
attribute float aScale;     // per-particle size multiplier

void main() {
  vec4 mvPosition = modelViewMatrix * vec4(position, 1.0);
  // gl_PointSize: on-screen square edge length, in PIXELS
  // divide by -mvPosition.z so distant points shrink (perspective)
  gl_PointSize = uSize * aScale * (300.0 / -mvPosition.z);
  gl_Position = projectionMatrix * mvPosition;
}
glsl
// 片元着色器
uniform sampler2D uTexture;

void main() {
  // gl_PointCoord: uv of the current fragment INSIDE the point square
  // (0,0) top-left .. (1,1) bottom-right, free of charge
  vec4 tex = texture2D(uTexture, gl_PointCoord);
  gl_FragColor = vec4(tex.rgb, tex.a);
}
  • gl_PointSize（顶点阶段，只写）：这块方形区域的屏幕像素边长。想要"近大远小"，手动除以 -mvPosition.z（视图空间深度），这就是 sizeAttenuation 的 shader 版；
  • gl_PointCoord（片元阶段，只读）：当前片元在这块方形内的局部坐标，直接拿来采样贴图——不用自己声明 uv。

Canvas 程序化粒子贴图 ​

粒子贴图 99% 是"中心亮、边缘透明的柔和圆点"。这种图没必要找素材，用 Canvas 画一个径向渐变最干净（思路与 7.1 的程序化纹理一脉相承）：

js
function makeSoftDotTexture(size = 64) {
  const cv = document.createElement('canvas')
  cv.width = cv.height = size
  const ctx = cv.getContext('2d')
  // 径向渐变：中心纯白不透明 → 边缘全透明
  const g = ctx.createRadialGradient(
    size / 2, size / 2, 0,
    size / 2, size / 2, size / 2
  )
  g.addColorStop(0.0, 'rgba(255,255,255,1)')
  g.addColorStop(0.4, 'rgba(255,255,255,0.6)')
  g.addColorStop(1.0, 'rgba(255,255,255,0)')
  ctx.fillStyle = g
  ctx.fillRect(0, 0, size, size)
  return new THREE.CanvasTexture(cv)
}

配上 blending: THREE.AdditiveBlending（加法混合，重叠处变亮）与 depthWrite: false（半透明不挡后面的粒子），几千颗柔点叠在一起就是发光的星云。

代码示例 ​

5000 颗程序化贴图粒子组成的旋转星云，自定义 shader 控制大小与颜色，逐段注释：

js
import * as THREE from 'three'

// ---------- 1. 数据：一次性生成并上传 ----------
const COUNT = 5000
const positions = new Float32Array(COUNT * 3)
const colors = new Float32Array(COUNT * 3)
const scales = new Float32Array(COUNT)
const colorInner = new THREE.Color(0xfff3d6)   // 核心暖白
const colorOuter = new THREE.Color(0x3b82f6)   // 边缘青蓝

for (let i = 0; i < COUNT; i++) {
  const r = Math.sqrt(Math.random()) * 6       // 平方根让面密度均匀
  const a = Math.random() * Math.PI * 2
  positions[i * 3]     = Math.cos(a) * r
  positions[i * 3 + 1] = (Math.random() - 0.5) * 0.6 * (1 - r / 6)  // 边缘更薄
  positions[i * 3 + 2] = Math.sin(a) * r
  const c = colorInner.clone().lerp(colorOuter, r / 6)  // 按半径混色
  colors[i * 3] = c.r; colors[i * 3 + 1] = c.g; colors[i * 3 + 2] = c.b
  scales[i] = 0.5 + Math.random()              // 每粒子随机大小倍率
}

const geometry = new THREE.BufferGeometry()
geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3))
geometry.setAttribute('color', new THREE.BufferAttribute(colors, 3))
geometry.setAttribute('aScale', new THREE.BufferAttribute(scales, 1))

// ---------- 2. 顶点着色器：呼吸动画 + 透视点大小 ----------
const vertexShader = /* glsl */ `
  uniform float uTime;
  uniform float uSize;
  attribute float aScale;
  varying vec3 vColor;

  void main() {
    vColor = color;                       // vertexColors: built-in attribute
    vec3 p = position;
    p.y += sin(uTime * 0.8 + position.x * 2.0) * 0.06;  // gentle breathing
    vec4 mvPosition = modelViewMatrix * vec4(p, 1.0);
    gl_PointSize = uSize * aScale * (300.0 / -mvPosition.z);
    gl_Position = projectionMatrix * mvPosition;
  }
`

// ---------- 3. 片元着色器：gl_PointCoord 采样柔点 ----------
const fragmentShader = /* glsl */ `
  uniform sampler2D uTexture;
  varying vec3 vColor;

  void main() {
    vec4 tex = texture2D(uTexture, gl_PointCoord);
    gl_FragColor = vec4(vColor * tex.rgb, tex.a);
  }
`

// ---------- 4. 材质与粒子对象 ----------
const material = new THREE.ShaderMaterial({
  uniforms: {
    uTime:    { value: 0 },
    uSize:    { value: 3.0 },
    uTexture: { value: makeSoftDotTexture() }
  },
  vertexShader, fragmentShader,
  vertexColors: true,                    // 开启内置 color attribute
  transparent: true,
  blending: THREE.AdditiveBlending,      // 光点叠加更亮
  depthWrite: false                      // 半透明粒子互不遮挡
})

const points = new THREE.Points(geometry, material)
scene.add(points)

// ---------- 5. 渲染循环：只喂时间，JS 不碰任何顶点 ----------
renderer.setAnimationLoop(() => {
  clock.update()
  material.uniforms.uTime.value += clock.getDelta()
  points.rotation.y += 0.0008            // 整体缓慢旋转
  renderer.render(scene, camera)
})

注意三件事：① 顶点颜色用内置的 color attribute，材质要开 vertexColors: true；② 动画只改 uTime 和整团旋转，5000 个顶点的位移全在 GPU 上完成；③ 加法混合 + 不写深度是发光粒子的标配组合（与 12.3 全息同一配方）。

常见问题解答 ​

Q1：粒子渲染出来是一块块方块，不是圆点？

点图元的本质是正方形区域，不做任何处理当然是方的。排查三步：① 材质有没有给 map（PointsMaterial）或 shader 里有没有用 texture2D(uTexture, gl_PointCoord) 采样——没采样贴图就是纯色方块；② 开了 transparent: true 没有，或者改用 alphaTest: 0.5 直接裁掉透明像素；③ 贴图本身是不是带透明通道（程序化 Canvas 渐变天然带 alpha）。三者缺一，方块立现。

Q2：粒子大小不随距离变化，远近一样大？

用 PointsMaterial 检查 sizeAttenuation 是否为 true；用自定义 shader 则检查 gl_PointSize 有没有除以 -mvPosition.z（视图空间深度，近处 z 小、点大）。另外注意除法前的系数（示例中的 300.0）要和相机距离量级匹配——系数太小所有点都缩成像素点，太大则近处糊满屏。

Q3：粒子数量上限是多少？加到多少会卡？

WebGL 单个 attribute 缓冲上限很大（百万级顶点通常没问题），瓶颈不在"能不能存"而在每帧谁去算它们：位置不动、动画靠 shader 的粒子，10 万级也能 60fps；一旦回到 JS 里 for 循环逐颗更新（每帧改数组 + needsUpdate 重传），几万颗就掉帧——这正是 17.2 用 GPGPU 解决的问题。经验值：纯展示粒子 1~5 万很舒服，10 万以上请先确认动画全在 GPU 侧。

Q4：粒子透明交叠处出现脏块/闪烁？

与 12.3 全息同一套药方：发光粒子用 blending: THREE.AdditiveBlending（加法混合对渲染顺序不敏感）+ depthWrite: false（半透明不写入深度，避免互相错误遮挡）。如果需要的是"烟雾"这类遮光型粒子才用 NormalBlending，那就得按到相机的距离排序（points.sortObjects 不管用，要逐粒子排），成本很高，能避则避。

动手小练习 ​

  1. 把贴图换成"空心环"（径向渐变改成中间透明、0.6 处最亮），观察星云质感的变化，体会"贴图即形状"。
  2. 删掉 gl_PointSize 里的 (300.0 / -mvPosition.z)，对比开关透视衰减的观感差异。
  3. 给每颗粒子加一个 aSeed attribute，片元里用 vColor * (0.8 + 0.2 * sin(uTime * 3.0 + aSeed * 20.0)) 做随机闪烁的星空。
