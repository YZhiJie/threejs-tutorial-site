1.1 基础入门：Three.js 是什么与第一个场景 ​

核心概念讲解 ​

什么是 Three.js ​

Three.js 是 Web 生态最流行的 3D 图形库。它不是一套游戏引擎，而是对 WebGL 的高层封装——把"绑定 WebGL 上下文 → 编写着色器 → 管理 GPU Buffer"这些繁琐底层工作藏到背后，让你只需要操作几个高级对象就能画出 3D 画面。

术语解释：WebGL 是浏览器提供的"JavaScript 调用 GPU 进行 3D 渲染"的底层标准，语法接近 OpenGL ES。直接写 WebGL 需要手写着色器代码（GLSL）并管理所有 GPU 资源，学习曲线极陡。

渲染管线的四个核心角色 ​

任何一个 Three.js 程序都能拆成四件事：

  1. 场景 Scene —— 3D 世界里所有物体的"容器"和"坐标系原点"
  2. 相机 Camera —— 观察者的位置和观察方式，决定"从哪里看"
  3. 渲染器 Renderer —— 把前两者的组合结果画到 <canvas> 上
  4. 物体 Mesh —— 场景里摆的东西，由"形状 Geometry + 外观 Material"拼起来

代码示例 ​

下面这段"Hello Cube"是所有 Three.js 教程的起步，逐行注释帮你看懂每一步：

html
<!DOCTYPE html>
<html>
<head>
  <!-- 声明 ES Module，让浏览器按 importmap 解析 import 路径 -->
  <script type="importmap">
  {
    "imports": {
      "three": "https://cdn.jsdelivr.net/npm/three@0.186.0/build/three.module.js",
      "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.186.0/examples/jsm/"
    }
  }
  </script>
</head>
<body>
  <!-- canvas 会被 renderer.domElement 追加到这个容器里 -->
  <div id="app"></div>

  <script type="module">
    // ---------- ① 导入 ----------
    import * as THREE from 'three'
    // OrbitControls 在 addons 里，不在核心包（核心坚持"只渲染，不交互"的边界）
    import { OrbitControls } from 'three/addons/controls/OrbitControls.js'

    // ---------- ② 场景 Scene ----------
    // Scene 是场景树的根节点：所有可见物体必须挂在这棵树上才会被渲染
    const scene = new THREE.Scene()
    scene.background = new THREE.Color(0x0b0e14)  // 背景色（十六进制）

    // ---------- ③ 相机 Camera ----------
    // PerspectiveCamera(fov 视场角, aspect 宽高比, near 近裁面, far 远裁面)
    // near/far 之间才会渲染，超出的被裁掉；near 不能设 0（会有深度精度问题）
    const camera = new THREE.PerspectiveCamera(
      50,
      window.innerWidth / window.innerHeight,
      0.1, 100
    )
    camera.position.set(3, 2, 4)  // 相机挪开，否则和立方体中心重合会"扎"进去

    // ---------- ④ 渲染器 Renderer ----------
    // antialias 抗锯齿；像素比 clamp 到 2，防止 3/4x 高分屏 GPU 过载
    const renderer = new THREE.WebGLRenderer({ antialias: true })
    renderer.setSize(window.innerWidth, window.innerHeight)
    renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))
    document.getElementById('app').appendChild(renderer.domElement)

    // ---------- ⑤ OrbitControls 鼠标交互 ----------
    // 左键绕原点旋转 / 右键平移 / 滚轮缩放；enableDamping 加惯性
    const controls = new OrbitControls(camera, renderer.domElement)
    controls.enableDamping = true

    // ---------- ⑥ Mesh = 几何体(形状) + 材质(外观) ----------
    // MeshNormalMaterial 按顶点法线方向自动配色，不需要灯光就能看到形状
    const cube = new THREE.Mesh(
      new THREE.BoxGeometry(1.4, 1.4, 1.4),
      new THREE.MeshNormalMaterial()
    )
    scene.add(cube)  // 忘记这步 = 屏幕一片黑

    // ---------- ⑦ 渲染循环 ----------
    renderer.setAnimationLoop(() => {
      cube.rotation.x += 0.01       // rotation 是欧拉角，单位弧度
      cube.rotation.y += 0.012
      controls.update()             // 开了 damping 就必须每帧 update
      renderer.render(scene, camera)
    })

    // ---------- ⑧ 窗口自适应 ----------
    window.addEventListener('resize', () => {
      camera.aspect = window.innerWidth / window.innerHeight
      camera.updateProjectionMatrix()  // 改投影参数后必须调用！
      renderer.setSize(window.innerWidth, window.innerHeight)
    })
  </script>
</body>
</html>

常见问题解答 ​

Q1：页面一片黑，什么都没画出来？

90% 是下面三条之一：

  1. 忘了 scene.add(obj) —— Mesh 创建出来不会自动显示。
  2. 相机在物体内部 —— 立方体中心默认 (0,0,0)，相机 z=0 就"扎"进去了。
  3. 用了需要灯光的材质却没放灯 —— Standard/Lambert 材质依赖灯光；改用 MeshNormalMaterial / MeshBasicMaterial 或加一盏 HemisphereLight。
Q2：为什么 setPixelRatio 要限制到 2？

Retina 是 2x，部分 Android 旗舰是 3x~4x。按 4x 渲染意味着每帧处理 16 倍 CSS 像素的三角面，绝大多数视觉效果在 2x 已足够锐利。

Q3：setAnimationLoop 和 requestAnimationFrame 有什么区别？

功能接近，但 setAnimationLoop 额外处理了页面隐藏自动暂停与 WebGL 上下文丢失自动恢复。r152+ 起官方推荐。

Q4：updateProjectionMatrix 为什么必须手动调？

Three.js 假设你改投影参数（fov/aspect/near/far/zoom）的频率远低于渲染频率，所以更新投影矩阵是手动触发。忘了调会出现画面拉伸、黑屏等诡异现象。

动手小练习 ​

  1. 把立方体换成球体 new THREE.SphereGeometry(0.8, 32, 24)，旋转速度减半。
  2. 加一个地面 new THREE.PlaneGeometry(4, 4)，用 rotation.x = -Math.PI/2 躺平。
  3. 切换到 MeshStandardMaterial 并加一盏 HemisphereLight，感受两类材质差异。
