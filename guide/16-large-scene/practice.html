16.3 实战案例：万级实例城市 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑪ 再学习本篇。

核心概念讲解 ​

这篇把前两篇的读数法与药方串成完整实战：从 3000 个独立 Mesh 的"卡顿城市" 出发，分三步优化到 万级实例 + 合并静态几何 + 视锥剔除，全程用 renderer.info 说话。

优化路线图 ​

步骤手段针对瓶颈预期收益
第 0 步原始版本：3000 独立 Mesh——基准：卡
第 1 步InstancedMesh 实例化全部楼块draw callcalls 从 ~3000 降到个位数
第 2 步合并静态几何（地面/道路合并成 1 个 Mesh）残余 draw call辅助物体只留 1~2 次提交
第 3 步视锥剔除 + 街区分块GPU 无效渲染视野外城区整帧不画

数据对比（中端设备实测量级，供校准预期）：

指标第 0 步第 3 步
draw calls~3000+个位数~两位数
帧率20fps 上下，转动视角明显顿挫稳定 60fps
三角形总数不变（几何量没变）视野内减少（剔除生效）

关键认知：三步里收益最大的是第 1 步。大场景优化永远是"先砍 draw call，再谈别的"。

代码示例 ​

完整演示较长，这里按优化步骤逐段拆解，每段都有注释：

第 0 步：卡顿的原始版本——3000 个楼块就是 3000 个 Mesh：

js
// ❌ 反面教材：一楼一 Mesh，draw call = 楼数
function buildIndividualCity(count) {
  const side = Math.ceil(Math.sqrt(count))
  for (let i = 0; i < count; i++) {
    const h = 1 + Math.random() * 8            // 楼高随机
    const m = new THREE.Mesh(boxGeometry, material)
    m.position.set(
      (i % side - side / 2) * 3, h / 2,
      (Math.floor(i / side) - side / 2) * 3)
    m.scale.set(1.5, h, 1.5)                   // 用缩放拉伸成楼
    group.add(m)
  }
}

第 1 步：实例化——同一份几何体、一次提交，楼高与颜色写进每实例数据：

js
// ✅ InstancedMesh：一万栋楼也只占 1 次 draw call
function buildInstancedCity(count) {
  const mesh = new THREE.InstancedMesh(boxGeometry, material, count)
  const dummy = new THREE.Object3D()
  const color = new THREE.Color()
  const side = Math.ceil(Math.sqrt(count))
  for (let i = 0; i < count; i++) {
    const h = 1 + Math.random() * 8
    dummy.position.set(
      (i % side - side / 2) * 3, h / 2,
      (Math.floor(i / side) - side / 2) * 3)
    dummy.scale.set(1.5, h, 1.5)
    dummy.updateMatrix()
    mesh.setMatrixAt(i, dummy.matrix)          // 每实例变换
    mesh.setColorAt(i, color.setHSL(0.6, 0.2, 0.3 + Math.random() * 0.4))
  }
  group.add(mesh)
}

第 2 步：合并静态几何——地面、道路等永远不动的物体，用 BufferGeometryUtils.mergeGeometries 合成一个 Mesh，只占 1 次 draw call：

js
import { mergeGeometries } from 'three/addons/utils/BufferGeometryUtils.js'

// 多块地面/道路 → 一个几何体 → 一个 Mesh → 1 次 draw call
const groundGeoms = []
for (let i = 0; i < 16; i++) {
  const g = new THREE.BoxGeometry(20, 0.2, 20)
  g.translate((i % 4 - 1.5) * 22, -0.1, (Math.floor(i / 4) - 1.5) * 22)
  groundGeoms.push(g)
}
const ground = new THREE.Mesh(
  mergeGeometries(groundGeoms),
  new THREE.MeshStandardMaterial({ color: 0x1e293b })
)
scene.add(ground)

第 3 步：视锥剔除的"助攻"——超大 InstancedMesh 只有 1 个包围球，剔除粒度太粗；按街区分成多个 InstancedMesh，视野外的街区整块跳过：

js
// 每 20×20 楼一个街区，各自一个 InstancedMesh
// 相机转向时，身后街区被视锥剔除，calls 与 triangles 同步下降
const BLOCK = 20
for (let bx = 0; bx < side / BLOCK; bx++)
  for (let bz = 0; bz < side / BLOCK; bz++)
    buildInstancedBlock(bx * BLOCK, bz * BLOCK, BLOCK * BLOCK)

对比开关：lil-gui 一键切换两种模式，HUD 实时读数：

js
const params = { mode: '实例化 ×10000', count: 10000 }
gui.add(params, 'mode', ['独立 Mesh ×3000', '实例化 ×10000'])
  .name('渲染模式')
  .onChange(v => v.startsWith('独立') ? buildIndividualCity(3000)
                                     : buildInstancedCity(10000))
// HUD 每 0.5s 刷新 renderer.info：calls / triangles / FPS

常见问题解答 ​

Q1：为什么实例化后一万栋楼比独立模式三千栋还流畅？

瓶颈不同。独立模式的卡顿来自 CPU 提交开销：3000 次 draw call 的状态准备把 16.6ms 预算吃光了。实例化后 draw call 降到个位数，CPU 解放；一万栋楼的三角形总量（12 三角形/楼 ≈ 12 万）对 GPU 来说非常轻松，所以帧率反而更高。

Q2：每栋楼都要单独变色，InstancedMesh 顶得住吗？

顶得住。setColorAt 写入的 instanceColor 是每实例顶点属性，GPU 在着色器里直接取，不改变 draw call 数。初始化时一次性写完全部颜色即可；只有需要动态变色（如夜间亮灯）时才再设 instanceColor.needsUpdate = true。

Q3：合并静态几何时有什么限制？

三条：① 合并的几何体必须属性结构一致（都有 position/normal/uv，顶点属性个数对齐），否则 mergeGeometries 会返回 null；② 合并后共用一份材质，不同材质要分组分别合并；③ 合并是不可逆的，之后想单独移动某一块就做不到了——只合"永远不动"的东西。

Q4：街区怎么分才合适？

按"视野内常见跨度"分：第一人称/近地面视角，街区边长取视野宽度（比如 20~40 个楼距）较合适；高空俯瞰视角下大部分街区都在视野里，分块收益小，反而可以合成更大的块减少 draw call。分块大小本身就是一道 LOD 题。

动手小练习 ​

  1. 把楼块几何体换成 BoxGeometry(1,1,1, 4,4,4)（分段加细分），观察 triangles 读数变化，体会"draw call 解决了，几何总量又会成为新瓶颈"。
  2. 给城市加"夜间模式"：随机挑 20% 实例把 instanceColor 改成暖黄色，只设一次 needsUpdate，看 FPS 是否受影响。
  3. 把街区大小从 20 调到 5，转动视角观察 calls 读数波动，找到本机剔除收益最大的分块粒度。
