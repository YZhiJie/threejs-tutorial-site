32.1 基础入门：TSL 节点与函数式着色器 ​

前置提示：本篇属于战略前瞻内容，不纳入阶段考核；建议先完成基础模块 ⑫ 与 ⑰ 再阅读。

核心概念讲解 ​

接桥：12.2 的 GLSL 字符串拼接，在 TSL 里变成函数调用 ​

在 ⑫ 着色器 · Uniforms 与 Varying 里，我们写过这样的片段：把一段段 GLSL 源码写进模板字符串，再把 uTime、uMouse 之类的 uniform 对象手工挂到 ShaderMaterial 上。那种写法很直接，也很"底层"：你清楚地知道每一个变量在顶点着色器和片元着色器里叫什么，但一旦要改结构，就得同时改两段字符串、手写 varying、手动对齐类型。

TSL 换了一个思路：你不再拼接字符串，而是调用 JavaScript 函数来"搭"一棵节点图。positionLocal、uv()、time、sin()、mix() 都是函数调用，返回值是节点对象。节点对象之间用方法链组合，最后由材质自动翻译成着色器。看起来像在写数学表达式，实际上你写的是渲染管线的一部分。

举个最小的对照。旧的 GLSL 写法是：

glsl
uniform float uTime;
varying vec2 vUv;

void main() {
  float stripes = step(0.5, fract(vUv.y * 12.0 + uTime));
  gl_FragColor = vec4(mix(vec3(0.05, 0.4, 0.9), vec3(0.8, 0.4, 0.95), stripes), 1.0);
}

而 TSL 写法是：

js
const uTime = uniform(0)
const stripes = step(0.5, fract(uv().y.mul(12).add(uTime)))

material.colorNode = mix(color(0x0ea5e9), color(0x9b5cf6), stripes)

两者表达的数学完全一样，但 TSL 版本没有 varying、没有字符串、没有重复声明。uv() 直接返回一个节点，.y 取分量，.mul()、.add() 是节点运算。改变量的类型由节点系统推断，最终统一编译成 WGSL 或 GLSL。这就是"函数式着色器"的第一层含义：着色器是一段可以被组合、复用、传递的表达式。

TSL 是什么：用 JS 构建节点图，再编译到目标后端 ​

TSL 是 Three Shading Language 的缩写。它不是一个独立的新语言，而是一套 JavaScript API 加一层节点编译器。你写的每一个函数（sin、mix、texture、normalize）都会创建一个节点，节点记录"我要做什么运算"以及"输入是谁"。材质在第一次渲染时，把这些节点整理成有向无环图（DAG），再根据当前后端生成对应的着色器源码：

  • 后端是 WebGPU：生成 WGSL。
  • 后端是 WebGL2：生成 GLSL ES 3.0。

同一棵节点图可以在两个后端上工作，这就是"统一后端"的来源。它不保证两个后端的每个细节都逐像素相同（例如精度、纹理格式、混合实现可能不同），但保证你不需要维护两套着色器源码。

从 three/tsl 导入的是节点构造函数，从 three/webgpu 导入的是渲染器与节点材质。两者配合使用，核心代码大致如下：

js
import * as THREE from 'three/webgpu'
import { Fn, uniform, positionLocal, uv, time, mix, sin, color } from 'three/tsl'

注意 time 是 TSL 内置的时间节点。它并不是一个普通的 JS 数字，而是由渲染器每帧更新的节点。也可以像本篇演示那样自己声明 uniform(0)，在主循环里累加，这样控制更直观，也方便暂停。

常用导出速查：从位置到颜色 ​

TSL 的导出很多，初学阶段先认识下面这一组就够用：

导出类型作用类比 GLSL
Fn函数工厂把一段 JS 回调封装成可复用的节点函数自定义函数
uniformuniform 节点声明一个从 JS 传入的值uniform float
positionLocal属性节点模型局部空间坐标position
uv属性节点第一套 UVuv
time时间节点自动递增的秒数手写 uTime
mix数学节点线性插值mix()
sin / cos数学节点三角函数sin() / cos()
color颜色节点按色彩空间解释的颜色常量vec3 常量
instancedArray存储节点创建 GPU 存储缓冲无直接对应（WebGPU 才有）

Fn 值得单独说。它让你把一段节点表达式命名、复用、甚至可以带参数：

js
const valueNoise = Fn(([p]) => {
  const i = floor(p).toVar()
  const f = fract(p).toVar()
  const u = f.mul(f).mul(f.mul(-2).add(3))
  const a = hash2(i)
  const b = hash2(i.add(vec2(1, 0)))
  const c = hash2(i.add(vec2(0, 1)))
  const d = hash2(i.add(vec2(1, 1)))
  return mix(mix(a, b, u.x), mix(c, d, u.x), u.y)
})

Fn 的回调不是普通 JS 函数，它只在构建节点图时执行一次；里面的 i、f、u 都是节点，不是真实数值。.toVar() 的作用是把一个表达式固定成局部变量，避免同一段计算在生成的着色器里被重复展开。这个习惯在复杂节点图里非常重要，后面还会反复出现。

NodeMaterial：节点图的"宿主" ​

节点本身不会自动生效，它必须挂到材质上。TSL 配套的材质统称 NodeMaterial，最常用的两个是：

  • MeshBasicNodeMaterial：不受光照影响，适合纯色、渐变、后期式效果。
  • MeshStandardNodeMaterial：PBR 标准材质，支持灯光、粗糙度、金属度，同时允许你用节点覆盖颜色、自发光、法线等通道。

常见的挂载点有 colorNode、emissiveNode、opacityNode、normalNode、positionNode、scaleNode。它们不是"额外参数"，而是材质内部管线的一个个插槽。你给 colorNode 一个节点，材质就把"基础色"这一步替换成你的节点图；你给 positionNode 一个节点，顶点位置就会被你的表达式改写。

本篇演示里的球体用的是 MeshStandardNodeMaterial：

js
const material = new THREE.MeshStandardNodeMaterial({ roughness: 0.38, metalness: 0.12 })
material.colorNode = stripedColor
material.emissiveNode = color(0x22d3ee).mul(fresnel.mul(uRim))

colorNode 负责条纹与双色渐变，emissiveNode 负责菲涅尔边缘光。灯光仍然由标准材质自己计算，节点只接管你关心的通道。这种"局部接管"是 NodeMaterial 相比整段手写 ShaderMaterial 最实用的地方：你可以只改一个通道，不必重写整套光照。

节点复用与统一后端 ​

节点是普通对象，可以保存、传参、多次引用。下面这段把"菲涅尔"抽成一个函数，球体和别的物体都能复用：

js
const fresnel = Fn(([power = 3]) => {
  return pow(float(1).sub(abs(dot(normalView, positionViewDirection))), power)
})

material.emissiveNode = color(0x22d3ee).mul(fresnel(3).mul(uRim))

因为节点图与后端无关，同一份材质代码在支持 WebGPU 的浏览器里走 WGSL，在不支持的浏览器里走 GLSL。你不需要写 if (webgpu) ... else ...。这也是为什么本模块把它列为"战略前瞻"：它代表 Three.js 未来的着色器组织方式，但现阶段仍有兼容性与生态成熟度的问题，了解即可，按需采用。

维度GLSL 字符串TSL 节点图

一句话总结：GLSL 字符串像"手写汇编"，TSL 像"用函数组合表达式"。前者掌控感强，后者更适合复杂、可复用的效果，也更适合未来的 WebGPU 管线。

需要强调的是，"函数式"并不意味着写法一定要很抽象。你完全可以在 TSL 里写出和 GLSL 一一对应的直白表达式，也可以把常用片段封装成 Fn 复用。它改变的是组织方式，而不是数学本身。对已经熟悉 GLSL 的读者来说，最有效的学习路径不是从零背 API，而是把旧着色器逐行翻译成节点表达式：先翻译 uniform 与属性，再翻译运算，最后把 gl_FragColor 换成 colorNode。翻译两三遍之后，节点 API 的命名习惯就建立起来了。

还有一点容易误解：TSL 并不是"运行时解释器"。它不会在每一帧重新解释节点图，而是在材质首次编译时把图固化成着色器。运行时改变的只有 uniform 值，节点结构保持不变。因此，节点图应该按"编译期结构"来设计，把变化的部分留给 uniform，把不变的部分固化成节点。这个心法决定了后面 compute 与交互场的写法。

常见坑：节点没挂上、颜色不对、uniform 不更新 ​

坑一：节点必须挂到材质。 只写 const c = color(0xff0000) 不会改变任何东西，必须 material.colorNode = c。同样，positionNode 不挂到材质上，顶点位置不会移动。

坑二：颜色空间用 color()。 直接写 vec3(1.0, 0.5, 0.1) 得到的是线性空间的数值；而你从设计稿拿到的十六进制颜色是 sRGB。TSL 的 color(0xff8800) 会按当前色彩管理配置做转换。模块 ㉔ 讲过，渲染器的 outputColorSpace、纹理的 colorSpace、颜色常量的解释方式必须一致，否则画面会偏灰或偏亮。节点材质里优先用 color()，不要手工拆十六进制。

坑三：uniform 更新要改 .value。 uniform(0) 返回的是节点，真正的值在 node.value 上。每帧写 uTime.value += dt，而不是重新赋值 uTime = 0。后者只是让 JS 变量指向了一个新节点，材质引用的旧节点不会变。

坑四：不要在执行期修改节点图结构。 节点的组合关系在材质编译时确定。运行时想改变"用 A 还是 B 分支"，应该用 uniform 驱动的 select、mix，或者在切换材质/节点后显式触发重编译。频繁重建节点图会带来着色器重编译卡顿。

坑五：WebGL2 后端不是"零成本"。 TSL 在 WebGL2 下会编译成 GLSL，但某些 WebGPU 专属能力（storage buffer、compute）无法等价模拟。写跨后端代码时，先确认你用的节点在 WebGL2 有实现。

代码示例 ​

下面是一个最小但完整的 TSL 球体。它保留了演示的核心结构：条纹、滚动噪声、菲涅尔边缘光。

js
import * as THREE from 'three/webgpu'
import { Fn, uniform, positionLocal, uv, normalView, positionViewDirection,
  vec2, vec3, float, color, mix, sin, fract, floor, dot, pow, smoothstep, step, abs, clamp } from 'three/tsl'

const renderer = new THREE.WebGPURenderer({ antialias: true })
await renderer.init()

const uTime = uniform(0)
const uStripeCount = uniform(12)
const uNoiseAmp = uniform(0.42)
const uRim = uniform(1.35)

const hash2 = Fn(([p]) => fract(sin(dot(p, vec2(127.1, 311.7)).mul(43758.5453))))

const valueNoise = Fn(([p]) => {
  const i = floor(p).toVar()
  const f = fract(p).toVar()
  const u = f.mul(f).mul(f.mul(-2).add(3)).toVar()
  const a = hash2(i)
  const b = hash2(i.add(vec2(1, 0)))
  const c = hash2(i.add(vec2(0, 1)))
  const d = hash2(i.add(vec2(1, 1)))
  return mix(mix(a, b, u.x), mix(c, d, u.x), u.y)
})

const stripes = step(0.5, fract(positionLocal.y.mul(uStripeCount)))
const scroll = vec2(uTime.mul(0.13), uTime.mul(0.08))
const n = valueNoise(uv().mul(3.6).add(scroll))
const blend = smoothstep(0.15, 0.85, clamp(uv().y.add(n.sub(0.5).mul(uNoiseAmp)), 0, 1))

const base = mix(color(0x0ea5e9), color(0x7c3aed), blend)
const fresnel = pow(float(1).sub(abs(dot(normalView, positionViewDirection))), 3)

const material = new THREE.MeshStandardNodeMaterial({ roughness: 0.38, metalness: 0.12 })
material.colorNode = mix(base, color(0xffffff), stripes.mul(0.18))
material.emissiveNode = color(0x22d3ee).mul(fresnel.mul(uRim))

要点有三个：

  1. hash2 与 valueNoise 是普通的节点函数，可以在任何材质里复用。
  2. positionLocal.y 用来做条纹，uv().y 用来做上下渐变，两者空间不同，效果也不同。
  3. 菲涅尔用 normalView 与 positionViewDirection 点乘，越接近边缘值越小，取反后取幂。

演示还加了一个"等价 GLSL 版"作为对照。GLSL 版本用自定义 ShaderMaterial，把同样的噪声、条纹、菲涅尔公式抄成 GLSL 字符串；两者在 WebGL2 后端下由同一套渲染器绘制，切换时图案应当对齐。这个对照的意义不是证明"TSL 更漂亮"，而是证明同一套数学可以有两种组织方式，并且结果一致。

运行效果展示 ​

演示启动后，画面中央是一颗带条纹与双色渐变的球体。条纹沿模型局部 Y 轴周期性分布，噪声让色带边缘产生轻微起伏，菲涅尔在球体轮廓处形成一圈青色边缘光。球体缓慢自转，因此能看到噪声在表面"流动"，而不是贴死在 UV 上。

左上角会显示当前后端。演示固定使用 WebGL2 后端，这是刻意为之：只有让 TSL 与 GLSL 落在同一个后端，对照才有意义。如果你在支持 WebGPU 的浏览器中打开，标签会提示"WebGPU 可用，本演示固定 WebGL2 后端对照"；如果浏览器完全不支持 WebGPU，标签会提示未检测到 WebGPU，但画面仍然正常，因为 TSL 已经被编译成 GLSL。

右侧面板可以切换"TSL 节点"与"GLSL 字符串"，并实时调整滚动速度、条纹数量、噪声强度、边缘光强。切换实现时，球体不换位置、不换相机，只换材质。你会看到两种实现的条纹数量、渐变方向、边缘光位置基本一致，差异主要来自光照模型：TSL 版本走的是标准 PBR 光照，GLSL 版本用固定方向光近似。这个差异是预期内的，正文前面已经解释过。

需要注意，演示里两条路径都使用 color(0x...) 或 THREE.Color，没有手工写线性 RGB。这是为了保证色彩管理与模块 ㉔ 的结论一致：颜色常量、纹理、输出空间三者要统一。

常见问题解答 ​

为什么我按教程写了 `colorNode`，球还是原来的颜色？

先检查三件事：材质是不是 NodeMaterial（普通 MeshStandardMaterial 不认 colorNode）；渲染器是不是 WebGPURenderer（WebGLRenderer 不认节点材质）；节点是否真的赋给了材质。还有一个容易忽略的点：如果 colorNode 被后续的 material.color 覆盖，或者材质在赋值前就已经编译过，需要设置 material.needsUpdate = true 触发重编译。演示里切换材质是直接替换 mesh.material，所以不存在这个问题。

TSL 一定要用 WebGPU 吗？没有 WebGPU 的浏览器怎么办？

不一定要。WebGPURenderer 会在不支持 WebGPU 的环境里自动回退到 WebGL2 后端，节点材质仍然可用，TSL 会被编译成 GLSL。区别在于 WebGPU 专属能力不可用：compute shader、storage buffer 的任意读写、部分纹理格式。本篇的演示只用了节点材质，所以没有 WebGPU 也能跑。下一节的 compute 演示就需要额外处理降级。

为什么同样的颜色，TSL 里看起来比 GLSL 里亮？

最常见原因是色彩空间不同。color(0x...) 会把 sRGB 常量转换到线性工作空间，而你在 GLSL 里直接写 vec3(0.1, 0.5, 0.9) 得到的是线性值，两者并不等价。其次是光照模型不同：标准材质有能量守恒的 PBR 光照，手写 max(dot(N, L), 0) 只是一个近似。对照时应该关注图案结构是否一致，而不是逐像素亮度相同。

节点函数里的 `.toVar()` 是必须的吗？

不是必须，但强烈建议在复杂表达式里使用。不加 .toVar() 时，同一个子表达式可能在生成的着色器里被展开多次，导致重复计算，甚至让编译器难以优化。.toVar() 会把结果固定成局部变量，语义更清晰，也便于调试。简单的一次性表达式可以不加，例如 const stripes = step(...)。

我能在运行时根据条件切换两套节点吗？

可以，但不要在执行期重建节点图。推荐把两套效果都写成节点，用 uniform 驱动的 select 或 mix 在着色器里分支；如果必须换材质，就在切换后设置 needsUpdate，并接受一次重编译开销。频繁重编译会造成明显卡顿，尤其是在移动端。

动手小练习 ​

  1. 把条纹方向改掉：当前条纹沿 positionLocal.y，试着改成沿球体法线的某个分量，或者用 uv().x 做竖向条纹。观察条纹在球体两极附近的疏密变化，并解释原因。
  2. 给噪声加第二层：在 valueNoise 的基础上叠加一层频率更高、振幅更小的噪声，形成"细节噪声"。提示：用两个不同缩放的 uv()，再用 mix 或直接相加，注意总振幅不要超过 1。
  3. 做一次 A/B 对照：把 colorNode 换成纯 color(0xffffff)，只保留 emissiveNode 的菲涅尔边缘光。分别在 TSL 和 GLSL 两个版本里观察边缘光的宽度与衰减，尝试调整幂次，让两者在视觉上接近。
