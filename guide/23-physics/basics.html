23.1 基础入门：物理引擎与第一个下落小球 ​

前置提示：本篇属于精通方向扩展内容，建议先完成基础模块 ⑨⑩ 再学习本篇。

核心概念讲解 ​

接桥：给 9.1 的弹跳小球来一次"真实碰撞" ​

在 ⑨ 动画与过渡 里，小球怎么动全是我们"导演"安排好的轨迹——lerp 插值、缓动函数、easeOutBounce 假装落地反弹。它有一个天花板：轨迹是写死的。球永远不会因为撞到别的东西而改变方向，也没法被用户"推一把"。

物理引擎换了一种思路：我们不再编排轨迹，只描述初始状态 + 物理规律（质量、重力、弹性、摩擦），之后每一帧球在哪里，由引擎按牛顿力学算出来。动画是剧本，物理是自然法则——剧本要逐字排练，法则只要颁布就永远生效。

这一篇就给 9.1 的弹跳小球装上真实物理：松手下落、撞地反弹、滚动直至停下。

物理世界 vs 渲染世界 ​

引入物理引擎后，程序里同时存在两个平行的"世界"：

渲染世界物理世界
库Three.jscannon-es / rapier
组成Scene → Mesh（几何体 + 材质）World → Body（形状 + 质量）
关心长什么样、怎么打光受什么力、怎么碰撞
可见性被相机拍到永远不可见，只产出坐标

两个世界靠"每帧同步"连接：物理引擎算完一步，把 Body 的位置和姿态抄给对应的 Mesh：

js
world.step(1 / 60, dt, 3)                 // ① 物理世界推进一步
mesh.position.copy(body.position)         // ② 渲染世界跟着抄作业
mesh.quaternion.copy(body.quaternion)

从此 Mesh 变成没有思想的"提线木偶"，Body 才是幕后提线的人。想看见隐形的物理世界，可以用 cannon-es-debugger 给每个 Body 画线框。

选型：cannon-es 还是 rapier ​

cannon-esrapier（@dimforge/rapier3d-compat）
语言/形态纯 JavaScript，ESM 直接 importRust 编译的 WASM + JS 胶水层
体积~300 KB~1.5 MB+（含 WASM）
API 风格简明直白，和 Three.js 一个味道更工程化，概念分层多
性能中小场景（几百刚体）足够大规模刚体、复杂约束明显更快
生态文档示例多，教程友好游戏向，官方配套 react-three/rapier

本模块统一用 cannon-es：学习阶段可读的 API 比极限性能重要；真到了上万刚体再迁移 rapier，物理概念完全通用。CDN 一行接入，importmap 加一条即可：

html
<script type="importmap">
{
  "imports": {
    "three": "https://cdn.jsdelivr.net/npm/three@0.186.0/build/three.module.js",

核心概念速查表 ​

概念cannon-es 对应一句话理解
物理世界World装所有刚体的容器，每帧 step() 推进一步
刚体Body有质量、速度、位置的"物理对象"
形状Shape（Sphere/Box/Plane…）刚体的碰撞轮廓，与渲染几何体无关
物理材质Material + ContactMaterial定义两个物体接触时的摩擦与弹性
重力world.gravity全局加速度，默认指向 -Y，9.82 m/s²
时间步world.step(1/60, dt, 3)固定步长 + 追赶机制，保证不同帧率结果一致

术语解释：

  • 恢复系数 restitution：0 = 完全不弹（湿毛巾落地），1 = 完全弹性（理想弹球），大于 1 会越弹越高（不符合现实，但引擎不拦你）。
  • 摩擦系数 friction：0 = 冰面，数值越大越"涩"，滚动停止得越快。

代码示例 ​

对应演示 physics-basic.html：一块地面 + 一个下落反弹的小球，逐段拆解。

① 建物理世界，定重力：

js
import * as CANNON from 'cannon-es'

const world = new CANNON.World()
world.gravity.set(0, -9.82, 0)   // 地球表面重力加速度
world.allowSleep = true          // 静止的刚体自动休眠，省 CPU

② 地面：无限大平面，静态刚体：

js
const groundBody = new CANNON.Body({
  type: CANNON.Body.STATIC,      // 静态刚体：不受力、永不移动
  shape: new CANNON.Plane()      // 无限大平面
})
// cannon-es 的 Plane 默认朝 +Z 立着，绕 X 轴转 -90° 才能放平成地面
groundBody.quaternion.setFromEuler(-Math.PI / 2, 0, 0)
world.addBody(groundBody)

③ 小球：有质量的动态刚体：

js
const ballBody = new CANNON.Body({
  mass: 1,                       // 有质量 = 动态刚体，受重力下落
  shape: new CANNON.Sphere(0.5), // 碰撞形状：半径 0.5 的球
  position: new CANNON.Vec3(0, 6, 0),
  material: ballPhysMat          // 挂物理材质（下一步定义）
})
world.addBody(ballBody)

④ 物理材质对：弹性与摩擦定义在"接触"上：

js
const ballPhysMat = new CANNON.Material('ball')
const groundPhysMat = new CANNON.Material('ground')

world.addContactMaterial(new CANNON.ContactMaterial(ballPhysMat, groundPhysMat, {
  restitution: 0.7,              // 弹性：撞地后保留约 70% 的垂直速度
  friction: 0.3                  // 摩擦：滚动时逐渐减速
}))

注意物理材质和 Three.js 的 MeshStandardMaterial 毫无关系——一个管碰撞手感，一个管视觉外观。

⑤ 渲染循环：先 step，再同步：

js
renderer.setAnimationLoop(() => {
  timer.update()
  const dt = Math.min(timer.getDelta(), 0.05) // 截断大跳变：切后台回来 dt 可能好几秒
  world.step(1 / 60, dt, 3)                   // 固定步长 1/60，最多追 3 步

  // 物理世界 → 渲染世界：抄坐标与姿态
  ballMesh.position.copy(ballBody.position)
  ballMesh.quaternion.copy(ballBody.quaternion)

  controls.update()
  renderer.render(scene, camera)
})

地面那个 Mesh 不用抄——它对应的 Body 是静态的，位置永远不变，初始化时摆好即可。

常见问题解答 ​

Q1：小球直接穿过地面掉下去了，怎么回事？

九成是步长太大导致的"隧道效应"：这一帧球还在地面上方，下一帧按 dt 积分完已经到地面之下，碰撞检测根本来不及触发。对策按优先级排：① 用固定步长 world.step(1/60, dt, 3)，并对 dt 做上限截断（切后台回来 dt 可能大到好几秒）；② 刚体休眠设置别乱动，allowSleep 开着的球静止后休眠是特性不是 bug，唤醒它给 body.wakeUp() 即可；③ 子弹级的高速物体，换支持 CCD（连续碰撞检测）的 rapier。日常场景做到 ① 就够了。

Q2：画面一顿一顿的，物理和渲染像是不同步？

先检查 world.step() 的位置——它必须在渲染循环里、renderer.render 之前调用，且每个渲染帧只调一次。固定步长下，若渲染帧率高于物理步频（如 120Hz 屏幕配 1/60 物理），物体在两个物理步之间画面不动，会感觉"顿"。cannon-es 的第三个参数 maxSubSteps 自带时间累积，并且给每个 Body 算好了 interpolatedPosition / interpolatedQuaternion——渲染同步时抄这两个插值而不是 position，画面立刻丝滑。

Q3：cannon-es 和 Three.js 的坐标系能直接互抄吗？

能。两家都是右手坐标系、Y 轴朝上，CANNON.Vec3 与 THREE.Vector3 分量顺序一致，mesh.position.copy(body.position) 直接成立（Three.js 的 copy 只读 x/y/z），四元数同理。真正要留神的不是坐标系，而是形状的默认朝向：cannon-es 的 Plane 默认朝 +Z，要 setFromEuler(-Math.PI/2, 0, 0) 放平；Cylinder 在部分版本里轴向与 Three.js 不一致。物理侧与渲染侧各自摆对朝向，再互抄位置，就不会出现"看着在地上、物理在半空"的灵异现象。

动手小练习 ​

  1. 把 ContactMaterial 的 restitution 调到 1.2，观察小球"越弹越高"——想想这违反了什么物理定律，引擎为什么不拦着你。
  2. 一次投放 30 个球，对比 world.allowSleep 开关下 world.step() 的耗时（用 performance.now() 粗测），体会休眠机制的价值。
  3. 投放时给小球一个水平初速度 ballBody.velocity.set(4, 0, 0)，再把摩擦调到 0，对比"冰面"和"草地"上滚动停止的时间差。
