11.3 实战案例：性能优化实验与上线检查清单 ​

核心概念讲解 ​

最后一篇不讲新 API，而是建立性能工程的直觉与方法论。同样视觉效果，差的实现可能 15fps，好的实现能稳 60fps，差距几乎都来自三件事：draw call、三角形数量、像素填充。

三大瓶颈与对应手段 ​

瓶颈现象/指标优化手段
CPU/draw call物体多、info.render.calls 很高InstancedMesh、合并几何体、按需剔除
顶点处理triangles 巨大降几何体细分、LOD 远景切低模
像素填充高 DPR/大后处理下掉帧降 pixelRatio、缩小阴影/渲染分辨率

三种"大量物体"方案对比 ​

  1. 独立 Mesh：最灵活（可单独控制），但 draw call = 物体数，几百个就吃力
  2. InstancedMesh：draw call≈1，保留逐实例矩阵/颜色，大量重复物体首选
  3. 合并几何体：draw call≈1 且无逐实例开销，但烘焙后无法单独移动，适合静态远景

术语解释：

  • 视锥剔除（Frustum Culling）：相机看不到的物体直接不提交 GPU，Three.js 默认对每个物体开启（frustumCulled=true）。
  • LOD（Level of Detail）：同一物体准备高/中/低几套模型，按相机距离自动切换，远处用省的。

用 renderer.info 做决策，而不是猜 ​

js
renderer.info.render.calls      // draw call 数
renderer.info.render.triangles  // 三角形数
renderer.info.memory.geometries // 几何体内存占用

先量化、再优化、再量化——避免"凭感觉优化"。

代码示例 ​

下面演示在同一批 2000 个立方体数据上，切换独立/实例化/合并三种模式，并叠加视锥剔除与 LOD 开关（可运行完整版见 DemoFrame）：

js
import * as THREE from 'three'
import { mergeGeometries } from 'three/addons/utils/BufferGeometryUtils.js'

// 三种模式共用同一批 transforms，保证性能对比公平
function buildIndividual(field, data, geometry, material) {
  // ❌ draw call = data.length（2000）
  for (const t of data) {
    const mesh = new THREE.Mesh(geometry, material)  // 共享几何体/材质省内存
    mesh.position.set(t.x, t.s / 2, t.z)
    mesh.scale.setScalar(t.s)
    mesh.rotation.y = t.ry
    field.add(mesh)
  }
}

function buildInstanced(field, data) {
  // ✅ draw call ≈ 1，且保留逐实例变换与颜色
  const geo = new THREE.BoxGeometry(1, 1, 1)
  const mat = new THREE.MeshStandardMaterial({ roughness: 0.6 })
  const inst = new THREE.InstancedMesh(geo, mat, data.length)
  const dummy = new THREE.Object3D()
  const c = new THREE.Color()
  data.forEach((t, i) => {
    dummy.position.set(t.x, t.s / 2, t.z)
    dummy.rotation.set(0, t.ry, 0)
    dummy.scale.setScalar(t.s)
    dummy.updateMatrix()
    inst.setMatrixAt(i, dummy.matrix)
    inst.setColorAt(i, c.setHSL(t.hue, 0.6, 0.55))
  })
  inst.instanceMatrix.needsUpdate = true
  inst.instanceColor.needsUpdate = true
  field.add(inst)
}

async function buildMerged(field, data) {
  // ✅ 静态烘焙：draw call≈1，无逐实例开销，但之后不能单独动
  const src = new THREE.BoxGeometry(1, 1, 1)
  const chunks = data.map(t => {
    const g = src.clone()
    g.scale(t.s, t.s, t.s); g.rotateY(t.ry); g.translate(t.x, t.s / 2, t.z)
    return g
  })
  const merged = mergeGeometries(chunks, false)
  field.add(new THREE.Mesh(merged, new THREE.MeshStandardMaterial({ roughness: 0.6 })))
}

// LOD：近高模、远低模
function makeLOD() {
  const lod = new THREE.LOD()
  lod.addLevel(new THREE.Mesh(new THREE.CylinderGeometry(0.8, 1, 4, 24), mat()), 0)
  lod.addLevel(new THREE.Mesh(new THREE.CylinderGeometry(0.8, 1, 4, 10), mat()), 18)
  lod.addLevel(new THREE.Mesh(new THREE.CylinderGeometry(0.8, 1, 4, 5),  mat()), 38)
  return lod
}
function mat() { return new THREE.MeshStandardMaterial({ color: 0xf59e0b, flatShading: true }) }

// 切换模式时记得释放旧 GPU 资源，否则反复切换会显存泄漏
function disposeObject(root) {
  root.traverse(o => {
    if (o.isMesh) {
      o.geometry?.dispose()
      const m = o.material
      Array.isArray(m) ? m.forEach(x => x.dispose()) : m?.dispose()
    }
  })
}

常见问题解答 ​

Q1：InstancedMesh 之后还想让其中几个实例动，怎么办？

可以。每帧重新 setMatrixAt(变化的索引, matrix) 并置 instanceMatrix.needsUpdate=true 即可。只更新变动的实例；若几乎所有实例每帧都变，GPU 顶点着色器方案会更省。拾取时 intersection.instanceId 能告诉你点的是第几个实例。

Q2：合并几何体和 InstancedMesh 到底选哪个？

物体永远静止（建筑远景、碎石、装饰）→ 合并几何体，省掉逐实例的运行时开销；物体需要整体批量但可能变化/着色/拾取 → InstancedMesh，它保留每实例矩阵与颜色，灵活得多。

Q3：为什么我 dispose 了，显存好像还是没释放？

常见原因：几何体/材质被多个 Mesh 共享，只 dispose 了引用没真正释放；或纹理还挂在材质上没 dispose。确保 dispose 纹理本身，且在移除最后一个引用之后；可用 renderer.info.memory 前后对比确认。

综合结业练习 ​

把 11.2 的科幻基地用本篇方法改造：

  1. 把 26 栋楼扩到 2000 栋（保持 InstancedMesh），对比 FPS 与 calls。
  2. 给远处建筑加 LOD 或降低远处实例的几何体细分。
  3. 加一个"画质"按钮：高/中/低三档联动 pixelRatio、阴影 mapSize、雾密度。
  4. 用 disposeObject 实现"离开基地页面时完整释放资源"，并用 renderer.info 验证几何体内存归零。
