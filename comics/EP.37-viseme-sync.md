## 知识点拆解

### 1. 骨骼给姿势，morph 给表情，两者都不负责"像不像人"

37.1 用 17 根骨骼和一套胶囊零件拼出低多边形人形：`Bone` 组成层级，`SkinnedMesh` 用 `skinIndex` 与 `skinWeight` 把每个顶点绑到最多四根骨头上，逆绑定矩阵负责"绑定姿势回到原点"。这一步解决的是**姿势**：抬手、转身、点头。第二层才是**表情与口型**，它不靠骨骼，而靠 `morphAttributes.position`：把同一份顶点数据存成若干"目标形状"，用 `morphTargetInfluences` 里的 0~1 权重做线性插值。三件事分工明确，混在一起就会得到"整张脸跟着头一起抖"的假人。

### 2. 口型不是一个状态，而是一条时间轴上的概率分布

人说话时嘴不是"张开 / 闭合"两态，而是在若干 viseme 之间连续过渡。做法是把音素映射到 viseme：`n` 是双唇闭合的 M，`i` 是咧开的 E，`a` 是扁而大的 A，`o` 是圆唇的 O。每个音节拆成"声母 + 韵母"两段，每段给一个起始时间与一个权重，就得到一条 `[时间, viseme, 权重]` 的轨道。播放时用 `replyTime` 去查当前落在哪一段，再对权重做指数平滑（系数 `1 - exp(-dt * k)`），嘴就不会一格一格地跳。协同发音是加分项：两个相邻 viseme 短暂共存，比硬切更像真人。

### 3. 表演要分层叠加，而不是互相抢占

一个可信的数字人同时有三层动作：待机层（呼吸、眨眼、轻微摆头）、手势层（说到重点抬一下手）、口型层（viseme 权重）。三层分别写不同的目标值，最后统一叠加到骨骼与 morph 上，任何一层都不能把另一层清零。若用 `AnimationMixer` 播导入动画，可用 `crossFadeTo` 在 idle / talk 之间过渡；若全是程序化姿态，就用"目标姿态 + 指数平滑"，并给每层不同的平滑速度：口型要快（k 约 18~20），手势要慢（k 约 4~6）。快慢同频，人就会显得机械。

### 4. 对话系统真正难的是状态与失败

37.3 的状态机只有五个状态：idle → listening → thinking → speaking → idle。三个约束把它钉死：字幕、口型、声音必须读同一个 `replyTime`；打断时必须立刻停口型、清空待播队列；TTS 失败必须走兜底——直接显示整段文本，并用一个默认的微开节奏撑住时长，而不是让嘴永远张着。状态徽章、转场轨迹、口型权重柱这些可视化不是装饰，它们是调试工具：出问题时你能一眼看出是"状态没切"还是"时间没同步"。

## 常见误区

- **误区一：用帧数推时间。** 按"每 3 帧换一个 viseme"写死，帧率一变口型就整体漂移；必须用秒或统一的 `replyTime`。
- **误区二：字幕与口型各起一个计时器。** 两个计时器起点差几十毫秒，观众就会觉得"声音在前面飞"；字幕逐字显示应该由同一个进度驱动。
- **误区三：权重不做平滑，直接硬切。** 每 0.1 秒跳一次的嘴像在嚼东西；至少加一层指数平滑，并让相邻 viseme 短暂共存。
- **误区四：TTS 失败就静默。** 没有兜底时，数字人会停在 speaking 状态、嘴一直微张；正确做法是降级为文本 + 默认节奏，并明确回到 idle。

## 自测

<details>
<summary><b>Q1：骨骼和 morph target 各自负责什么？为什么不能只用一种？</b></summary>

骨骼负责**姿势**：通过 `skinIndex` / `skinWeight` 把顶点绑到骨骼链上，改骨骼旋转就能抬手、点头、转身，还能复用同一套动作到不同体型。morph target 负责**局部形状**：把嘴、眉、眼睑的目标形状存成额外的顶点位置，用 `morphTargetInfluences` 做插值，适合口型和表情这类"同一块区域的小幅变形"。只用骨骼做口型要建几十根面部骨，成本高且难调；只用 morph 做全身姿态，等于给每个姿势都存一份顶点数据，内存直接爆掉。两者叠加才是常规方案。
</details>

<details>
<summary><b>Q2：为什么 viseme 权重需要指数平滑，公式里的 k 怎么选？</b></summary>

音素的时间刻度只有几十到一百毫秒，直接把权重赋成 0 或 1，渲染出来就是逐格跳变。指数平滑用 `w += (target - w) * (1 - exp(-dt * k))`，让权重以固定时间常数追向目标，且与帧率无关。`k` 越大追得越快：口型建议 18~20，眨眼可以更快，手势与头部建议 4~6。k 太小会"糊嘴"，太大则等于没平滑。平滑只作用于显示权重，时间轴本身仍严格按 `replyTime` 采样，否则会累积延迟。
</details>

<details>
<summary><b>Q3：字幕、口型、声音怎样保证不错位？TTS 失败又该怎么兜底？</b></summary>

三者都必须由同一个 `replyTime` 派生：声音是主时钟（或 mock 的等效时钟），口型用 `replyTime` 查 viseme 轨道，字幕用同一个 `replyTime` 算进度逐字显示。任何一方都不允许自己 `setInterval` 或按帧累加。打断时立刻把 `replyTime` 归零并清空队列。TTS 失败时进入兜底分支：直接展示完整文本，用一个固定节奏（例如 3.2 秒的默认微开序列）驱动口型，结束后回到 idle，并在界面上给出可见提示，而不是让角色永远停在说话状态。
</details>
