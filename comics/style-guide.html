漫画剧场风格规范 · 霓虹墨 Neon Ink（Three.js 版）v1.0 ​

本规范是 comics/ 全部漫画的唯一视觉与叙事标准，与 frontend-advanced-guide 漫画剧场共用同一套霓虹墨视觉体系与三角色设定。新增或修改任何一话，都必须对照本文档执行。 校验入口：node comics/check-comics.mjs（manifest 一致性 + SVG 良构性 + 文本溢出启发式 + MD 完整性）。

1. 画布与分格 ​

项规定
画布viewBox="0 0 1200 840"，深墨底渐变（左上 #0b1220 → 右下 #101a33）
分格2×2 四格，面板尺寸 572×361，圆角 14
面板坐标左上 (20,84)、右上 (608,84)、左下 (20,462)、右下 (608,462)
页眉EP 徽章（#7C3AED 圆角矩形 92×36）+ 标题（渐变字 26px）+ 右侧系列名；页眉下 1160×2 渐变分隔线（y=62）
页脚右下角 11px 水印 NEON INK · threejs-tutorial · EP.NN（色 #475569）
装饰每格 1~2 条斜切光楔（多边形，霓虹色 opacity ≤0.05），禁止高不透明度大色块

2. 色板（60/30/10） ​

用途色值
底色（60%）#0b1220 #101a33 #0e1730（面板）
结构线/弱文本（30%）#1e2a44 #223055 #64748b #94a3b8 #e2e8f0
霓虹强调（10%）青 #22d3ee / 紫 #7C3AED #a78bfa / 品红 #f472b6 / 橙 #f97316 / 绿 #34d399 / 黄 #fbbf24
面板编号色1=青、2=紫、3=品红、4=橙

Three.js 语义色约定（全系列保持一致）：坐标轴 X=红/#f87171、Y=绿/#34d399、Z=蓝/#60a5fa；相机视锥=青、光线=黄、阴影/深度图=紫。

对比度规则：气泡为浅底（#f8fafc）配深字（#0b1220）；深底上正文用 #e2e8f0；强调词单独 <tspan> 换霓虹色。所有文字对比度 ≥ 4.5:1。

3. 字号阶梯与字体 ​

元素字号字色
话标题26 bold渐变（青→紫）
面板标题17 bold#e2e8f0
气泡正文15~16#0b1220（浅底）
代码12~13 mono#7dd3fc / #fbbf24 / #34d399 / #f472b6
注脚/水印11~12#64748b
  • font-family="'PingFang SC','Hiragino Sans GB','Microsoft YaHei',sans-serif"；代码用 'SF Mono','JetBrains Mono',Consolas,monospace。
  • 每个 <text>/<tspan> 必须显式写 font-size（校验脚本依赖）。
  • 气泡单行 ≤ 17 个汉字（约 272px），代码单行 ≤ 40 字符；预计行宽 = 汉字数×字号 + ASCII 数×0.58×字号，校验器按此做溢出启发式。

4. 组件规范 ​

  • 气泡：圆角 10 浅底矩形 + 小三角尾巴指向说话人；尾巴必须连到头像。
  • 头像（半身 44px 级）：头圆 r≈17 + 发型 + 眼睛两点 + 微笑弧 + 身体圆角矩形。见 samples/character-sheet.svg，EP.19 参考实现可直接复制迷你头像片段。
  • 代码芯片：深底 #0a0f1c、描边霓虹色（opacity 0.35）、圆角 8、内边距 ≥12；代码中的 </> 必须写 &lt;/&gt;。
  • 底部结论条：(24,278) 起 524×52 圆角矩形 #111a30 + 左侧 4px 霓虹竖条，两行 13.5px。
  • 坑点标签：橙 #f97316 小圆角条 + "⚠ 坑点" 前缀，只出现在第 4 格。
  • 转义：文本中 < → &lt;、> → &gt;、& → &amp;；禁止在属性值里出现 >。

5. 三角色设定（沿用 v2 定妆稿） ​

角色在本系列的人设视觉锚点
像素酱提问担当：参数党、爱追问"为什么必须这样调"青色高马尾 + 紫色卫衣 + 胸前 {} 徽章
标签君行动派：要做 3D 产品展厅，上手最快、踩坑最多橙色刺猬头 + 蓝外套 + HTML5 盾徽
码叔教授：讲渲染管线、矩阵与性能预算，负责总结白发白须 + 圆框眼镜 + 浅灰大褂 + 指教鞭

叙事分工：像素酱/标签君负责"黑屏了/糊了/卡了"的困境与追问，码叔负责"揭示管线、给出参数与最佳实践"。每话至少两角色出场。

6. 叙事结构（四幕） ​

  1. 第一格 · 困境：真实开发场景抛出问题（黑屏/锯齿/拖不动/帧率掉）；
  2. 第二格 · 揭秘：原理拆解，配 1 段迷你代码芯片或管线示意图；
  3. 第三格 · 实证：对比演示（正确 vs 错误、参数前后对比、流程顺序图示）；
  4. 第四格 · 结案：最佳实践 + ⚠ 坑点标签（2~3 条）+ 一句码叔总结。

每格左上角有编号色块（1~4）+ 4~8 字面板标题；整话无对白超过 3 行/气泡。

7. 命名与文件 ​

  • 一话 = EP.NN-slug.svg + EP.NN-slug.md，NN 两位数，slug 全小写连字符；
  • 一话严格对应 guide/ 下一个模块（01-intro … 11-capstone 的 basics / advanced / practice 三篇）；
  • 新增话必须同步：manifest.json、README.md 导航表；
  • 讲解 MD 结构固定：# EP.NN 标题 → > 对应正文（链接 ../guide/NN-xxx/{basics,advanced,practice}.md 与 ../public/demos/... 演示）→ 剧情回顾 → 知识点拆解（四格各一节） → 坑点清单（FAQ） → 自测 3 题（含答案）；
  • 每话必须链接至少 1 个 public/demos/ 下的对应演示，形成"漫画 → 讲解 → 可运行演示"闭环。
