| 格 | 场景 |
| --- | --- |
| ① 困境 | 像素酱为了让差距"更明显"，把柱子从半空起算；标签君盯着画面问：这根柱子到底代表多少？ |
| ② 揭秘 | 码叔画出一张映射表：位置放维度、高度放数值、颜色放类别或大小；图表先有语法，才有装饰。 |

## 知识点拆解

### ① 高度不是数值，除非从 0 起算

柱状图的长度只有在**统一起点、统一比例尺**下才与数值成正比。把基线抬到半空，视觉差距会被放大，但读者读出的倍数关系也随之失真。3D 柱状更要注意：透视会让远处柱子变短，没有 0 基线和网格时，读者会把"近"误当成"高"。

正确做法是三件事一起做：所有柱子从同一个 y=0 平面长出、共用同一个高度归一化比例、至少提供一条可换算的参考（刻度、网格或数值标签）。如果数据差距太小，改用差值、增长率或对数刻度并明确标注，而不是偷偷截断基线。

### ② 三种形态是三种句子

| 形态 | 主要编码 | 最擅长 | 最容易翻车 |
| --- | --- | --- | --- |
| 3D 柱状 | 高度 = 数值 | 比大小、排名、同比 | 非 0 基线、遮挡、透视缩短 |
| 3D 散点 | 三个位置轴各放一个维度 | 相关、聚类、离群点 | 三轴含义不清、点云重叠 |
| 曲面高度图 | 高度 = 网格数值 | 整体趋势、波峰波谷 | 单点读数难、背面被遮挡 |

柱状在比较离散个体，散点在寻找变量关系，曲面在描述连续场。选错形态，后面调再久也只是把一句话说错得更漂亮。

### ③ 颜色是第四个通道，不是滤镜

颜色有三种基本用法：**分类色**表达无序类别，最多六到八种；**连续色**表达有序数值，明度或色相单向递进；**发散色**表达围绕中点的偏离，两端用对立色相。用彩虹渐变表达连续数值、用分类色表达有序数据，都是让颜色"看起来有信息，实际读不出信息"。

还要记住两条：颜色不能是唯一编码，必须配标签、形状或位置；色板的十六进制默认按 sRGB 解释，进入 Three.js 后会解码到线性工作空间，和色彩管理那一篇的链路保持一致。

### ④ 3D 的门槛：第三个维度真的有用吗

3D 适合三类场景：数据本身有三个空间维度、需要空间关系、展示与沉浸优先于精确读数。如果问题只是"谁最高、谁最低"，2D 柱状永远更快更准。3D 饼图是反模式的代表：倾斜让角度被透视压缩，遮挡让扇区消失，读者几乎无法比较占比。

判断标准不是"好不好看"，而是"第三个维度是不是问题的一部分"。不是，就别加；是，就保证 0 基线、可读标签和正面视角都在。

## 坑点清单（FAQ）

- **Q：柱子差距很小，看不出来？** 先切正面视角、打开 0 基线；仍看不清就改用差值、增长率或对数刻度，别截断基线。
- **Q：分类色能用几种？** 六到八种是经验上限；超过就合并长尾类别、分组或分面，并始终配标签。
- **Q：曲面为什么不能报精确值？** 它擅长趋势，不擅长单点读数；精确值交给 hover、标签或 HTML 指标卡。
- **Q：3D 饼图能不能只当装饰？** 可以，但真实占比必须另放一张 2D 图或图例里，主图表别让它承担读数。
- **Q：颜色和 ㉔ 有什么关系？** 色板值默认按 sRGB 解释，渲染时解码到线性空间；颜色贴图要解码，数据贴图不要解码。

## 自测（Quiz）

1. 为什么 3D 柱状图的柱子必须从 0 起算？如果数据差距太小，应该怎么办？
2. 柱状、散点、曲面各自最擅长回答什么问题？各举一个不该用它的场景。
3. 分类色、连续色、发散色分别编码什么？各说一条使用纪律。

<details>
<summary>答案</summary>

1. 柱子的长度只有在同一起点、同一比例尺下才与数值成正比；抬高基线会放大视觉差距，让读者读出错误的倍数关系。差距太小时，应改用差值/增长率、对数刻度并明确标注，或直接在指标卡里给出精确值，而不是截断基线。
2. 柱状擅长比大小与排名，不适合表达相关关系；散点擅长看相关、聚类与离群点，不适合精确报出单个类别的排名；曲面擅长看整体趋势与波峰波谷，不适合单点精确读数。3D 饼图则不适合任何占比比较。
3. 分类色编码无序的离散类别，纪律是控制在六到八种并配标签；连续色编码有序数值，纪律是明度或色相单向递进，避免彩虹色；发散色编码围绕中点的偏离，纪律是中点用中性色、两端用对立色相并标明方向。
</details>
